# Codex 훅 미호출 원인과 실제 실행 복구

기준 커밋은 `6109278`이다. 이전 [우선순위 2 검증](2026-10-02-priority-two-native-codex.md)의 실패 기록은 보존한다. 이번 검증은 설치된 `codex-cli 0.160.0`, Windows, 실제 모델 `gpt-6.1-sol`로 수행한다. 초기 준비·요구 확정은 합성 fixture이며 사람의 승인 실측이 아니다.

## 원인 분리

첫 진단은 도구를 쓰지 않고 OK만 반환하는 실제 Codex 세션이다. 격리 저장소의 기록 훅만 설치하고 호출 여부를 확인했다. 제품 관찰 이벤트나 결과를 직접 만들지 않았다.

| 조건 | 실제 호출 |
|---|---|
| `/`로 변환한 프로젝트 신뢰 키, 사용자 설정 제외 | 0건 |
| 같은 조건에서 `--no-daemon` 추가 | 0건 |
| 같은 조건에서 프로젝트 config.toml 추가 | 0건 |
| 사용자 설정 로딩 허용 | SessionStart·UserPromptSubmit·Stop·SessionEnd |
| 사용자 설정 제외 유지, 신뢰 키만 Windows 네이티브 경로로 변경 | SessionStart·UserPromptSubmit·Stop·SessionEnd |

사용자가 전달한 Claude의 원인 분석을 실제 Codex 세션에서도 확인했다. `projects`의 신뢰 키는 `C:\...`인 호스트 네이티브 경로를 그대로 전달해야 했다. 검증 도구가 이를 `C:/...`로 변환하여 프로젝트 신뢰와 일치하지 않았다. 사용자 설정을 포함하면 호출된 관찰만으로 `--ignore-user-config` 자체를 원인으로 단정할 수 없으며, 최종 도구는 이 옵션을 유지하고 경로 키를 수정한다. 훅 실행 명령 안의 파일 경로와 프로젝트 신뢰 키는 서로 다른 용도다.

앞선 검증은 모든 재시도에서 잘못된 신뢰 키를 유지했다. 설정 조회에서 훅을 발견한 것은 실행 세션이 프로젝트를 신뢰하고 훅을 호출했다는 증거가 아니었다. 짧은 훅 호출 진단을 먼저 수행하지 않아 같은 장애 조건을 반복한 것이 검증 절차의 문제였다.

훅 호출 뒤에는 `--ephemeral` 실행에서 하위 에이전트가 부모 실행 기록을 찾지 못하는 오류(`no rollout found for thread id`)가 확인됐다. 실제 계획 검증은 이 옵션을 제거하고 호스트 실행 기록을 유지한다. 짧은 훅 진단은 하위 담당을 만들지 않으므로 해당 옵션을 사용할 수 있다.

공식 [훅 문서](https://learn.chatgpt.com/docs/hooks)는 프로젝트 신뢰와 개별 훅 신뢰를 구분한다. 일회성 훅 신뢰 옵션은 외부에서 검토한 생성 훅만 있는 진단에 한정하며, 일반 설치의 훅 검토를 생략하는 안내가 아니다.

## 제품 보완

훅이 활성화되자 Codex의 파일 읽기 셸 명령이 Claude의 Read/Grep/Glob을 전제로 한 게이트에 막혔다. `code-agent read <파일> [시작 줄] [줄 수]`를 추가하고 Codex 역할·스킬과 거부 안내에 연결했다.

- 저장소 안의 일반 텍스트 파일을 줄 번호와 함께 반환한다. 기본 200줄, 최대 400줄, 파일 크기 1 MB 이하이다.
- 실제 경로를 확인해 연결 디렉터리·상대·절대 경로를 통한 저장소 밖 접근을 거부한다. 기존 Read의 플러그인 키 보호도 적용한다.
- 셸 연결·임의 쓰기·상태 변경·직접 관찰 이벤트 호출에 대한 제한은 유지한다.
- 역할별 모델·추론 기본값과 문서 소유권·실제 시작/완료 관찰·근거·출력 계약은 유지한다.

검증 프롬프트도 담당마다 배정된 outputs만 반환하도록 수정했다. 분석 이후 담당에게도 요구 정의 문서를 작성하라고 지시하던 혼선을 제거했다. 분석 기본 제한은 300초, 영향도 포함은 600초이며 `--timeout-seconds`로 30~900초를 명시할 수 있다. 제한 확대는 성공 판정을 완화하지 않는다.

실제 Codex 분석·통합 영향도 결과는 모두 수락됐지만 `next`에서 문서 제목 `확인 필요`가 미결 표시로 거부됐다. 기존 explorer의 일반 출력 지침이 이 제목을 요구한 것이 완료 문서 계약과 충돌했다. 지침을 `질문·가정 후보`로 바꾸고, 완료 문서의 기술적 미확인 범위는 `조사 한계`로 사실대로 적도록 명시했다. 실제 업무 질문은 needs-input/questions로 남기는 기존 계약을 유지한다. 문서 게이트는 완화하지 않았다.

검증 도구는 기존 결과를 별도 입력 파일로 보존하고 피드백을 새 작업 입력에 연결해 해당 impact만 다시 배정한다. 이것은 JSON 형식 오류의 1회 교정과 다른, 내용 피드백에 따른 새 실행이다. 분석 결과는 재사용하며 새 담당의 실제 시작·완료 훅을 다시 요구한다. 이전 문서의 미확인 사실을 확정하거나 지우라는 지시는 하지 않는다.

## 재현

```sh
npm run build
node scripts/diagnose-codex-hooks.cjs --standalone --native-trust-path
node scripts/evaluate-planning-hosts.cjs codex <새-기록이름> --vetted-hooks --model gpt-6.1-sol --through-impact
```

위 제목 충돌로 내용 게이트에서 멈춘 통합 영향도 검사는 `--resume-impact <이전-기록이름>`과 새 기록 이름으로 한 번 보완한다. 기존 결과·문서에 대한 피드백 파일만 준비하고, 새 결과와 번호 문서는 실제 담당의 완료 훅이 기록한다. 최종 도구는 ready-for-gate 확인 뒤 `next`로 내용 게이트도 검사하며 다음 역할을 배정하지 않는다.

진단은 실제 모델을 호출한다. 로그와 격리 저장소는 `dist/`에 보존하며 Codex의 부모·하위 실행 기록은 호스트에도 남는다. 도구가 전역 설정을 직접 편집하지는 않지만 호스트 자체의 실행·신뢰 기록 저장은 가능하다. 이전 실패와 수정 후 결과를 덮어쓰지 않는다.

## 결과

Claude는 분석·조사·영향도 정리의 실제 담당 3명이 완료됐고 내용 게이트도 통과했다(175,155 ms). 이 실행에서는 분석이 요구를 더 세분화해 일반 분할 조사 경로가 선택됐다. Claude의 통합 impact 실제 완료를 검증한 실행으로 세지 않는다.

Codex 첫 수정 실행은 분석·통합 영향도 담당 2명의 시작·완료 훅이 모두 호출되고 결과가 수락됐다(494,579 ms). 내용 게이트의 제목 충돌 실패를 별도 기록으로 보존했다. 이후 새 impact 담당이 기존 결과와 피드백을 읽어 보완했고, 실제 완료 훅·결과 수락·내용 게이트가 모두 통과했다(326,852 ms). 분석은 한 번, impact는 최초와 보완의 두 번 실행됐다. 최종 단계는 design이며 설계 담당을 추가 배정하지 않았다. 훅의 model 필드에서 main·ca_analyst·ca_explorer의 gpt-6.1-sol을 확인했다. 추론 강도의 실제 적용까지 별도 계측한 것은 아니다.

| 검사 | 결과 |
|---|---|
| 첫 파일 읽기·Codex 집중 검사 | 20개 중 19개 통과·1개 실패. 새 테스트의 요구 확정 fixture 누락을 수정 |
| 수정 후 집중 검사 | 20개 통과·실패 0·생략 0 |
| 전체 회귀 | 720개 중 716개 통과·실패 0·생략 4, 949,122.3912 ms |
| 설치 지침 후속 검사 | 2개 통과. 탐색 지침까지 수정한 최종 검사에서도 동일 2개 통과 |

전체 회귀 실행을 시작한 뒤 설치 지침 문구와 실제 검증 도구를 추가 보완했다. 최종 설치 검사를 별도로 기록하며 겹치는 수치를 더하지 않는다. 빌드·검증 도구 구문 검사·diff 검사, 문서 링크 203개와 원자료·소스 해시 43개도 확인했다. [기계 판독 결과](evidence/codex-hook-recovery-2026-10-02.json)는 짧은 진단 6건, 실제 역할 실행 5건, 자동 검사 5건의 범위·원본 해시와 최종 소스 해시를 포함한다.

실제 확인 범위는 두 호스트의 분석·영향도 완료와 내용 게이트다. 전체 개발·실제 사람 승인·Codex UI 사용성·최적 비용 검증으로 확대 해석하지 않는다. 임시 집계 보조 파일은 제거하고 원본 로그·격리 저장소·실패 당시 문서는 로컬 dist에 보존한다.
