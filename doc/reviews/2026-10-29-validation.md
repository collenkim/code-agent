# 현재 검증 상태

검증 환경은 Windows 11, Node 24.19.0, PowerShell 5.1.26100이다. [집계 자료](evidence/2026-10-29-validation.json)는 실행별 결과이며 서로 다른 시험 수를 합산하지 않는다. 재현 기준선은 [재현 기준선 자료](evidence/2026-10-29-repro-baseline.json)에 있다.

## 자동 시험

실행 타임라인·검증 실행별 로그·재현 시나리오가 닿는 시험 파일 27개를 `node --test --test-concurrency=4`로 실행했다. 664건 중 662건이 통과했고 2건이 실패했으며 소요 시간은 1024.1초다. 실패 2건과 원인은 다음과 같다.

- 버전 미리보기의 파일 불변 시험: CLI 명령 기록이 `log/timeline.jsonl`을 바꿨다. 설치·버전·진단·측정 명령은 기록하지 않게 고쳤다.
- 새 실행별 로그 시험: 단계마다 마지막 실행만 남는 증거를 대조했다. 로그 파일과 타임라인을 대조하도록 고쳤다.

고친 뒤 그 두 파일과 새 시험 두 파일(`timeline`·`reproScenarios`)을 다시 실행했고 73건이 모두 통과했다(175초). 나머지 23개 파일은 이 수정(`cliMain.ts`의 기록 제외 목록) 전 빌드로 실행한 결과다.

이번 변경 뒤 전체 시험은 실행하지 않았다. 마지막 전체 시험은 이 변경 전 코드(`cd8a5f8`)에서 실행했으며 결과는 1807건 중 1803 통과·4 생략·0 실패다. 생략 4건은 플랫폼 조건이다.

## 재현 기준선 (개선 전)

`scripts/repro-baseline.cjs --repeat 3`으로 같은 fixture(`sha256:4be6f82c570ee977`)의 세 시나리오를 실행했다. 세 번 모두 같은 사실을 관찰했다. 시나리오마다 새 임시 저장소를 쓰며, 완료 정지는 CLI 진입점에 hook 입력을 넣는 격리된 가짜 Claude 호스트에서 재현한다.

| 시나리오 | 관찰한 사실 | 소요 중앙값 |
|---|---|---:|
| `amendment` | 확정한 요구 2개를 같은 ID의 추가 요구 1개가 대체한다. 제출 뒤 미확정이 되고 경고가 나오며, 다시 확정할 수 있다. 무효화 원인 1건이 남는다 | 17ms |
| `staleIds` | 지시서의 요구 ID는 REQ-1·REQ-2인데, 다시 준비한 분석 배정은 REQ-1만 가진다 | 18ms |
| `completionStall` | 담당이 완료된 뒤에도 Stop 이 턴을 잇지 않아 사람 입력이 있어야 다음 행동을 실행한다. 호스트 재개 대기 1건이 남는다(사유: 담당 완료 뒤 다음 행동 대기, 턴 종료·사람 입력 표시, 계획 작업·배정 ID 포함). 재개한 advance 는 게이트를 통과한다 | 2710ms |

개선 후에는 같은 스크립트로 `--out <후.json>`을 만들고 `--compare doc/reviews/evidence/2026-10-29-repro-baseline.json <후.json>`으로 사실·소요·분류 시간·대기 사유를 비교한다. 격리 호스트의 대기 시간은 자식 프로세스 사이 간격이다. 따라서 실제 세션의 대기 시간은 재현하지 않으며, 비교 대상은 Stop 차단 여부·사람 입력 필요 여부·구간 분류다. `reproScenarios.test.ts`는 지금 동작을 고정한다.

## 상태 형식 세대

상태 형식 세대는 16을 유지한다. 검증 실행 기록(`verify.json` `runs[]`)에는 선택 필드 `endedAt`·`durationMs`만 더했다. `logFile`은 표시에만 쓰는 경로이고, 이전 릴리스는 모르는 필드를 무시한다. `log/timeline.jsonl`은 새 측정 파일이라 이전 릴리스가 읽지 않는다. 승인·증거·작업 기록의 판정 형식은 바뀌지 않았다. 버전 표지가 없는 작업도 현재 번들로 재개할 수 있다.

## 템플릿 예산

`node scripts/template-sizes.cjs --suggest`는 LF로 정규화한 글자 수에 파일별 1.03, 흐름 합계 1.02를 곱하고 100자 단위로 올린다. 현재 흐름 예산은 Claude 49200자, Codex 45900자다. 공통 계획 절차는 `ca-plan/contract.md`에 두며 예산은 4100자다. 검증 기록·비밀 값·언어 규칙을 포함한 CODEX.block 예산은 2200자다. 파일별 상한은 `src/test/templateBudget.test.ts`가 관리한다. 이번 변경은 템플릿을 바꾸지 않았다.

## 배포와 검증 한계

- 패키지 dry-run은 217개 파일이며 `dist/agent/timeline.js`를 포함하고 `dist/test`는 포함하지 않는다. 재현 시나리오와 기준선 스크립트는 이 소스 저장소에서만 실행된다.
- 실제 Claude·Codex 호스트에서의 타임라인 기록은 확인하지 않았다. 확인 범위는 격리된 가짜 호스트와 hook 입력이다. 미확인 대상은 메인 대화 기록의 완료 알림 표지와 Codex UserPromptSubmit 시각이다.
- 구현·테스트 담당(`ca-implementer`·`ca-tester`)에는 SubagentStart·Stop hook 이 등록돼 있지 않다. 그래서 담당 실행 구간 없이 인계(`agent.assigned`)와 다음 명령으로만 보인다.
- Codex 의 완료 알림은 관측하지 않는다.
- 요구 개정 번호(revision/cycle)는 아직 도입하지 않아 타임라인 줄에 그 필드가 없다.
- 실제 모델·유료 평가는 호출하지 않았다. 자동 회귀를 실제 사람 승인·전체 모델 완주·사용자 사용성의 증거로 해석하지 않는다. 실제 호스트 동작 설명에 붙은 버전은 관찰 조건이며 지원 최소 버전을 뜻하지 않는다.
