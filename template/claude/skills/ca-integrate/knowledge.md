# 지식 제안 형식 — `doc/work/<ID>/knowledge.proposal.md`

반영(deliver)에서 사람이 항목마다 고르고 코드가 공통 KNOWLEDGE 에 적용한다. **구현·검증된 지금 동작만** 쓴다 — 계획만 한 동작이나 실패·생략한 검증에 기댄 동작은 쓰지 않는다.

종류마다 `## <종류>` 절(`data-dictionary` · `api-catalog` · `business-rules` · `features` · `flows`), 항목마다 ``### `키` 이름`` 블록이다. 본문은 `- 이름: 값` 줄이고 이번 작업의 R 번호를 단다(없으면 반영이 거른다).

```markdown
## features
### `FEAT-ORDER-CANCEL` 주문 취소
- 목적: 배송 전 주문을 고객이 취소한다
- 진입점: POST /api/orders/{id}/cancel
- 입력·출력: 취소 사유 → 취소된 주문
- 정책: `BR-ORDER-03`
- 흐름: `FLOW-ORDER`
- 예외: 배송 시작 뒤면 ORDER_NOT_CANCELLABLE
- 코드: src/order/OrderService.java
- 테스트: src/test/order/OrderCancelTest.java
- 별칭: 주문 철회
- 근거: R1, R2
```

- **기능(features)** — 사용자·호출자가 보는 기능 단위만 쓴다. 함수마다 쓰지 않는다. `코드`·`테스트`는 지금 트리에 있는 경로여야 반영된다. 정책·흐름은 본문을 옮기지 않고 키로 가리킨다. 이미 있는 기능 문서가 있으면 `- 상세:` 에 그 경로를 적고 같은 내용을 다시 쓰지 않는다.
- **흐름(flows)** — 주요 업무 시나리오 하나가 항목 하나다. `- 시나리오:` 한 줄과 `- 단계:` 아래 번호 목록(단계마다 기능 키), `- 정책:` BR 키.
- **업무 정책(business-rules)** — 조건 → 결과 한 줄과 `- 구분: 필수|권장` · `- 상태: 확정|관찰` · `- 출처:` · `- 범위:`(경로·도메인, 모든 작업이면 `전체`) · `- 예외:` · `- 검증:`(TC·테스트 경로). `확정`의 출처는 이번 작업의 R 번호나 사용자 결정(Q 번호)뿐이다. 코드에서 본 동작은 `관찰`과 `path:line` 출처로 쓴다 — 승인된 정책이 아니다.
- **삭제** — 본문에 `- 삭제: <사유>` 한 줄. **이름 변경·이동** — 새 키로 쓰고 `- 대체: \`옛 키\``. 옛 항목 자리에 새 항목이 들어간다.
- 02 문서 영향에서 갱신을 선언한 키를 제안하지 않거나 사람이 거부하면 그 항목은 반영 뒤 `보류`로 보인다. 지금 문서와 다른 정책은 고치지 말고 02 의 `충돌`로 남긴다.
