# [bootstrap 04] 선언 — code-agent.json + 컨벤션 문서

> **선행**: [03] 공통 모듈 · **다음**: seed (첫 도메인)
> **산출물**: `doc/templates/code-agent.json`, `doc/guide/*.md`

## 0. 사용법

**bootstrap의 본체다.** 지금까지의 결정을 이후 모든 실행이 읽을 수 있는 파일로 옮긴다.
코드는 부산물이고, 여기서 나오는 두 파일이 진짜 산출물이다.

## 1. 입력 게이트

- [ ] 결정 문서가 확정돼 있다
- [ ] `out/` 에 스캐폴딩 결과와 공통 모듈이 있다 (경로를 여기서 읽어 낸다)

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| `domainBase`·`domainRoots`는 **실제로 만들어진 디렉토리 경로**를 쓴다. 추측하지 않는다 | 무효 |
| `stages`의 계층 이름과 `outputDirs`는 결정 5번과 일치해야 한다 | 무효 |
| `referenceDomain`은 **비워 둔다** — 아직 도메인이 없다. seed가 만든 것을 나중에 넣는다 | 무효 |
| 컨벤션 문서는 결정 문서를 **규칙 문장으로** 옮긴 것이어야 한다. 일반론을 채우지 않는다 | 무효 |
| 결정에 없는 규칙을 컨벤션 문서에 넣지 않는다 | 무효 |

## 3. 작업

### 3.1 `doc/templates/code-agent.json`

| 키 | 어디서 |
|---|---|
| `language`·`sourceExtensions` | 결정 1 |
| `domainBase`·`domainRoots` | 결정 4 + `out/`의 실제 경로 |
| `conventions` | 3.2에서 만들 문서의 경로 |
| `build`·`test` | 결정 3의 빌드 도구 |
| `stages[]` | 결정 5의 계층 — 계층당 하나, `outputDirs`는 그 계층 디렉토리 |
| `referenceDomain` | 비워 둠 (seed 이후 채움) |

각 단계의 `template` 파일명도 함께 정한다 — 그 문서는 seed 전에 사람이 채우거나, 이 프로젝트의 첫 도메인을 만들며 채워 나간다.

### 3.2 `doc/guide/*.md`

결정 5·6번을 규칙 문장으로 옮긴다. 최소한 계층별 책임·트랜잭션 경계·네이밍·식별자·soft delete·예외 처리가 들어간다.

## 4. 자가검증 체크리스트

- [ ] `domainBase`가 `out/` 에 실제로 존재하는 경로인가
- [ ] `stages`의 `outputDirs`가 실제로 만들어진 디렉토리와 일치하는가
- [ ] `referenceDomain`이 비어 있는가
- [ ] 컨벤션 문서의 모든 규칙이 결정 문서의 항목으로 추적되는가
- [ ] 결정에 없는 규칙을 넣지 않았는가
