# LangGraph 전체 실행 전환

기준 커밋은 `0024b18`, 구현·문서 정리 커밋은 `cb0c466`이다. Node 범위와 타입을 master-agent에 맞춘 뒤 전체 실행 계층을 전환했다. 현재 동작은 [LangGraph 실행 구조](../langgraph.md)와 [흐름도](../process-flow.md)를 따른다.

## 반영 범위

- `lifecycle` 그래프에 준비·문서·접수·사전 판별·분석·영향·설계·계획·구현·검증·리뷰·통합·반영의 재개 경로를 구성했다. 호스트는 `flow advance --json`의 인계를 수행한다.
- 계획은 준비·선택·개별 배정·판정·대기로, 단계 전이는 게이트·기록 직전 재검사·커서 기록으로 분리했다. 검증의 자체 노드 반복기를 실제 LangGraph 노드·간선·interrupt로 교체했다.
- 기존 단계 명령과 문서·접수·사전 판별·동의·되감기·리뷰·반영·발견 보고·경험 추가를 그래프 실행 경계에 연결했다. 설치·릴리스 교체·조회·hook 관찰은 각자의 역할을 유지했다.
- 공식 SQLite saver를 Node 내장 SQLite에 연결했다. 프로젝트 잠금, 실행 이력, DB 버전 검사, 도메인 기록에서 다시 관찰하는 재개 규칙을 구현했다. 프로젝트 상태 형식 세대를 3으로 올렸다.
- master의 기능 협상·상태·결과·순번 이벤트에 그래프 관찰을 추가하고 실행 노드 시작에서 정지·소유 세대를 다시 검사했다. 기존 명령 멱등·위임 범위·실제 응답 확인은 유지했다.
- Claude·Codex 재개 지침, 설치·설계·계획·사용 문서와 흐름도를 맞췄다. 템플릿 예산은 늘리지 않고 중복 안내를 줄였다.
- README 구조도와 사용 가이드의 수동 단계 선택 설명을 그래프 인계에 맞추고, 상세 설명은 `langgraph.md`(실행·재개)·`master-control.md`(master 통신·통제)·`install.md`(의존성 설치)로 모았다.

## 검증 중 수정

1. 계획 그래프가 여러 번 관찰하면서 자동 되감기 허용을 중복 소비했다. 준비 노드에서만 한 번 판정하도록 바꾸고 기존 되감기 회귀 시험을 통과했다.
2. SQLite의 `readOnly` 연결도 WAL 보조 파일을 만들었다. 실행 중 원자적으로 `view.json`을 발행하고 조회는 사본만 읽도록 바꿨다. 파일 목록·수정 시각 불변 시험과 단일 실행 파일 시험에서 확인했다.
3. npm 패키지 시험의 평탄한 의존성 구성이 zod만 제공했다. 실행 의존성을 실제 패키지 선언에 맞춰 연결하고 릴리스 복사본에서 그래프 명령이 실행되는지 확인했다.
4. Git에 포함 범위와 무관한 그래프 제외 경로를 넘기면 글롭 문자를 가진 작업 ID의 pathspec 판정이 달라졌다. 포함 범위와 겹치는 제외 경로만 넘겨 동일한 반영 범위를 유지했다.
5. 통합 증거 저장 뒤 커서 기록 전에 중단된 경우를 보완했다. 재개 시 통과한 통합 증거로 먼저 게이트를 지나고, 같은 통합 실행을 반복하지 않는다.
6. 승인 무효의 재계획 인계는 낡아진 첫 단계의 절차를 가리키도록 맞췄다.

계획 시험은 한 파일 실행이 약 109초여서 공통 fixture와 배정·교차 검토·복구·실제 연쇄 진행으로 나눴다. 기존 안내 문구 단위 시험(`planningChain.test.ts`)도 유지했다.

## 검증 범위와 한계

최종 `npm test`는 1,564개 중 1,560개 통과, 플랫폼 조건에 따른 4개 생략, 실패 0개로 완료했다(약 169초). SQLite 대기·재개·잠금·형식 검사, 두 호스트의 같은 그래프 인계, 수정 뒤 재검증, 통합 증거 재사용, 승인 무효 인계, master 정지·세대·관찰, hook 경량 로드, 패키지 릴리스 복사, 문서 동기화·템플릿 예산을 포함한다. 실행 환경과 실행 파일 해시는 [검증 근거](evidence/2026-10-16-langgraph.json)에 기록했다.

`npm run build:bin`으로 Windows 단일 실행 파일을 만들고 `node scripts/smoke-langgraph-bin.cjs`로 임시 Git 저장소의 양쪽 호스트 설치·SQLite 체크포인트·다른 프로세스에서 재개·읽기 전용 조회·Git 제외를 확인했다. 소스 저장소에는 `init`을 실행하지 않았다.

문서 정리 후 동기화·최종 재검증 안내·템플릿 예산·호스트 표기·계획 연쇄 안내 시험 70개를 다시 실행해 모두 통과했다. 실행 코드와 설치 템플릿은 문서 정리로 바꾸지 않았다.

실제 Claude·Codex 모델을 호출하는 유료 종단 시험은 이 변경에서 수행하지 않았다 → 실제 Claude 신규 개발 완주는 [복원·실제 모델 기록](2026-10-20-session-recovery-live.md)에서 통과를 확인했고, 실제 Codex 완주는 그 기록에서 미통과다. master의 기존 무인 호스트 지원 범위(Claude)는 유지했다. 기존 master-agent 어댑터는 상태 스키마 v1과 부가 필드를 수용하는 구조이며, 이 작업에서는 master-agent 저장소를 수정하지 않았다. 코드 에이전트의 새 `graph.changed` 이벤트를 별도로 표시하는 master UI는 이 변경의 검증 대상이 아니다.
