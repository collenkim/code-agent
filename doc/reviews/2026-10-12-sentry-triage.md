# Sentry 사전 판별과 fix 인계

사용자 요청: Sentry 오류 → 판별 → 코드 변경 필요 → Jira 생성 → 코드 수정. 자동 서비스 연결 전에 실제 작업 절차를 검증하고 기존 직접 fix·feature·refactor는 유지한다.

## 구현

- `ca-fix`의 Sentry 진입과 `triage` CLI를 추가했다. 별도 개발 스테이지·서브에이전트·동의 동작은 추가하지 않았다.
- 사전 판별 동안 현재 초안 외 파일 쓰기·일반 셸·알려진 외부 MCP 쓰기를 막는다. 로그·코드·문서 조사만 하고 원인과 코드 변경 여부를 별도로 판단한다.
- 코드 근거의 실제 경로·줄 인용·파일 해시를 대조한다. 불필요·판단 보류·중복 미조회는 Jira 준비와 인계를 막는다.
- Jira 생성·조회는 수동이다. CLI는 본문·추적 표지를 렌더하고 사람이 확인한 키·URL을 연결한다. 원격 티켓의 실재를 인증하지 않는다. 실서비스 자격 증명이나 네트워크 어댑터를 추가하지 않았다.
- 코드 변경 필요와 Jira 연결 뒤 원본 로그·조사 제안을 보존한 fix 접수만 연다. 사람의 요구·계획·반영 확인과 기존 재현·검증 게이트는 유지한다.
- 사전 판별 기록은 무시되는 log/ 안에 보관하고 인계 사본은 작업 문서에 남긴다. 같은 체크아웃에서는 출처별 인계 기록을 재사용하고 다른 체크아웃은 원격 중복 조회가 필요하다.

## 템플릿 예산

판별의 상세 절차는 필요할 때만 읽는 `ca-fix/triage.md`(3,400자 예산)에 분리했다. 기존 `ca-fix/SKILL.md`는 진입 분기와 인계 설명으로 3,400→4,000자, `ca-request/SKILL.md`는 Sentry 선행 분기로 5,200→5,500자 예산을 둔다. 공통 흐름 합계 예산은 올리지 않는다.

## 검증

- `npm.cmd run build` 통과.
- 사전 판별 테스트 12개: 로그만으로 시작, 상태 재개, 코드·상태·외부 MCP 쓰기 차단, Claude/Codex 초안 허용, 데이터·환경·외부 조치 분기, 판단 보류, 데이터 원인의 코드 보완, 근거 줄·해시 변화, 중복 미조회, Jira 키·URL 대조, 기존 작업 폴더 보존, 원문·기준 브랜치 인계, 미승인 요구 제출, 직접 fix·feature·refactor 유지, CLI 인자와 양쪽 호스트 배포를 확인했다.
- 첫 전체 실행: 1,369개 중 통과 1,358·실패 7·생략 4. 보조 문서 수 고정 기대값 4곳, 이동한 사용 가이드 줄 인용 1곳을 맞췄다. 나머지 2곳은 기존 테스트가 현재 Codex 호스트 표지를 물려받아 생긴 실패였다. 테스트의 사람 터미널 시뮬레이션을 기존 `withCaller(undefined, ...)`로 격리했다. 제품 호스트 판정은 변경하지 않았다.
- 최종 `npm.cmd test`: **1,369개 중 통과 1,365·실패 0·생략 4**, 204.259초. 임시 git 저장소에서 시험하며 실제 대상 저장소나 외부 서비스를 변경하지 않았다. 전체 테스트는 OS 사용자 정보 조회가 필요한 기존 시험 때문에 샌드박스 밖에서 실행했다.
- `git diff --check` 통과. 템플릿 예산·문장 치환·문서 동기화·hook 로드·기존 fix 재현·검증 흐름은 전체 시험에 포함된다.

## 확인하지 않은 것

실제 cloud 저장소·Sentry 이벤트·Jira 계정은 제공되지 않아 실서비스 판별 정확도와 티켓 생성은 시험하지 않았다. 자동 테스트의 원인 판단·중복 조회·Jira 연결은 합성 입력이다. 원인과 코드 변경 필요 여부는 호스트 모델이 조사해서 제안하며 CLI는 자료 형식·코드 인용·전이 조건을 검사한다. 수동 Jira 생성·조회와 키 회신은 사람이 담당한다. 배포·운영 데이터 수정·Sentry 해결 처리는 포함하지 않는다.
