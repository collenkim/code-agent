# Codex 관리 실행과 명시적 호스트 인계

## 변경 범위

code-agent만 수정했다. master-agent는 읽기와 임시 프로젝트 연결 검사 대상으로 사용하며 실제 관리 프로젝트는 변경하지 않는다. 서버 API 전환이나 자동 토큰 소진 감지는 추가하지 않았다.

- Codex 관리 실행을 JSONL로 감독하고 `thread.started`의 실제 UUID를 저장한다. 대시보드 응답과 명시적 continue는 확인된 같은 세션만 재개한다. 접수 시 반환한 별칭도 같은 thread로 해석한다. 실행별 호스트·권한 설정을 고정하고 설정이 달라지면 자동 재개를 차단한다.
- Codex는 `approval_policy=never`, 제한된 샌드박스, 샌드박스 네트워크 차단을 사용한다. 프로젝트·hook 신뢰 기록과 PreToolUse 설치를 확인한다. 질문·확인은 영속 요청으로 보내며 실제 사람 응답과 승인·검증 게이트를 유지한다.
- `execution --json`으로 작업·임대·질문·동의·차단 사유를 조회한다. 호스트 밖 TTY의 `--handoff`는 기존 실행 중지와 문맥을 재확인하고 미응답 일반 질문에 취소 이력을 남긴 뒤 임대를 해제한다. 받은 답·열린 동의·진행 중 관리 실행은 먼저 처리해야 한다.
- `both --main claude|codex`로 교차 검증을 유지하면서 관리 실행의 주 호스트를 정한다. 명시적 인계 뒤 같은 작업·연결에서 새 호스트 세션을 한 번 시작한다. 기존 작업 ID·최초 접수 종류·계획·승인 기록은 보존한다.
- 실행 기록 확장에 맞춰 상태 형식 세대를 8로 올렸다. README·설치·사용·Codex·대시보드·master 계약과 흐름도를 맞췄다.

## 검증

Windows·Node 24.19.0 환경에서 `npm.cmd ci`와 `npm.cmd run build`를 통과했다. Codex CLI의 실제 start/resume 인자 형식은 `--help`로 확인했으며 모델은 호출하지 않았다. 규격은 [공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)를 확인했다.

집중 검사 `masterCodex`·`dashboardCodexResume`·`executionHandoff`·`executionMode` 17개를 통과했다. 실제 자식 프로세스로 JSONL 시작·별칭 재개·중복 submit·thread 불일치·thread 누락·턴 실패·협력 정지·표지 확인 강제 종료·호스트 인계를 검사한다. 대시보드 실제 서명 응답의 재개 예약, 미확인 thread 거부, 작업·계획 보존, 열린 동의·미소비 답 차단, 인계 확인 중 상태 변경, 해제된 임대에 질문을 다시 묶지 않는 조건을 검사했다. 모의 호스트·합성 신뢰 기록을 쓰며 실제 모델 인증이나 운영 신뢰를 대신하지 않는다.

Windows 프로세스 조회가 제한된 샌드박스에서는 강제 종료 검사가 실패했다. 남은 모의 프로세스를 실행 표지로 확인해 정리하고 같은 집중 검사를 샌드박스 밖에서 통과했다. 일반 실행의 권한 제한을 완화한 변경은 없다.

전체 회귀 `npm.cmd test -- --test-concurrency=4`는 1,652개 중 1,648개 통과·실패 0개·플랫폼 생략 4개다. 문서·템플릿 동기화, hook 경로, 기존 Claude 감독·권한·동의·작업 ID·접수 종류·LangGraph 검사를 포함한다. 약 658초가 걸렸으며 이 환경의 전체 실행 시간은 기존 안내의 2~3분보다 길었다.

master-agent의 `scripts/smoke-interactions-live.mjs`를 임시 작업 폴더에서 이 빌드에 연결해 22개 시나리오를 통과했다. 실제 CLI·서명 응답, 모든 단계 질문, 다중 선택·직접 입력, 보류·재개, 오래된 브랜치 문맥·키 누락 거부, 별도 동의와 실제 문서 적용, 재시작 후 같은 명령 재전송을 확인했다. 자격 증명과 발행자는 합성 fixture이며 브라우저나 실제 모델을 실행하지 않았다. 수치와 범위는 [기계 판독 근거](evidence/2026-10-20-managed-hosts.json)에 기록한다.

## 인계와 남은 범위

호출 예제·연결·현재 지원 범위는 [대시보드 인계 문서](../dashboard-interactions.md), 호스트 선택·신뢰·인계 순서는 [관리 실행 계약](../master-control.md#호스트-전환-인계)을 따른다.

실제 두 모델의 프로젝트별 완주·브라우저 클릭·운영 반영은 이 모의 검사의 범위 밖이다. 종료 독립 세션 복원과 실제 모델의 후속 검증·남은 항목은 [복원·실제 모델 기록](2026-10-20-session-recovery-live.md)에 모았다. Codex 관리 실행의 통신(app-server)과 승인 정책(`on-request`)은 [Git 실행 권한](2026-10-20-codex-git-permission.md)에서, 신뢰 확인은 [실행 준비 판정](2026-10-22-codex-readiness.md)에서 바뀌었다.
