description: 독립 ca-reviewer를 호출하고 실행·결과가 기록된 리뷰 게이트를 확인한다.
---

**질문·동의** — `.claude/skills/ca-answer/SKILL.md`를 따른다. 이 대화에서 아직 읽지 않았거나 대화가 압축·비워진 뒤라면 그 직전에 읽는다. `AskUserQuestion`을 실제 호출하며 일반 답은 승인이 아니다. 질문·대기는 `.claude/skills/ca-answer/reference.md`의 단계별 선택·차단 복구를 따른다. 적용 뒤 이어간다.

너는 **메인 에이전트**다. `code-agent` 가 거부하면 차단 복구를 따른다.

**자리 확인** — 방금 받은 `code-agent` 출력에 지금 스테이지가 없을 때만 Bash: `code-agent status`. 스테이지가 `review` 가 아니면 차단 복구로 현재 단계의 재개 방향을 정한다.
아직 이르면 status 의 `다음:` 줄이 가리키는 명령을 먼저 하라고 전하고, 이미 지났으면 `code-agent back review` 로
되감아야 한다고 전한다 — 무엇이 무효가 되는지는 그 명령이 찍는다. **되감기는 사용자가 되돌리라고 말했을 때만** 돌린다 — 승인 무효로 status 의 `다음:` 이 되감기를 안내할 때는 예외다.

## 하는 일 — ⑨ `09-review.md`

1. Bash: `code-agent review` — **회차를 연다.** 기준 트리 해시를 굳히고 ⑨ 의 `## 회차` 구역을 렌더한다
   (검증이 지금 트리에서 통과하지 않으면 열리지 않는다). 회차가 없으면 `code-agent next` 가 "리뷰 회차가 없습니다" 로 막는다.
   출력에 `## 의심 항목` 이 붙어 있으면 그것은 **플러그인이 준 단서**다 — `ca-reviewer` 에게 넘겨 확인하게만 하고,
   **⑨ 에는 리뷰어가 낸 지적만 적는다.** 의심 항목을 그대로 지적 표에 옮기지 않는다.
2. `review` 출력의 `전문`이 context 파일이다(파일별 요구 항목·검증 증거·실패 로그 경로·얼어 있는 파일·남은 회차). 없으면 Bash: `code-agent context --file`.
3. 독립 `ca-reviewer`를 부른다. Agent 도구는 `run_in_background: false` 로 부른다(결과를 받아야 다음 단계로 간다). `전문` 경로를 넘기고(본문을 옮겨 쓰지 않는다) 확정 지시서 · `01`~`04` · `07-test-spec.md` · `08-validation.md` · 컨벤션 · 테스트 전략 · 품질·보안 기준의 **경로**를 준다. `02`에서 지정한 호출자·공유 모듈·기존 회귀 테스트 경로와 이번 실행 로그도 포함한다.
   요구 명확성·기능 위반·변경으로 인한 부작용·전체 테스트 성공·부정 케이스의 실제 검증을 독립적으로 대조하게 한다. 계획 밖 관련 파일은 읽기 근거이며 수정 허용 목록은 아니다. 필요한 근거가 빠지면 검증 공백으로 보고하도록 한다.
4. SubagentStart·SubagentStop hook이 리뷰어의 실행과 결과를 해당 회차에 기록하고 `09-review.md`의 `## 지적`을 자동으로 채운다.
   메인은 결과·상태를 바꾸지 않는다. 실행 기록이 없거나 결과가 다르면 게이트가 막는다. hook 누락은 `code-agent doctor`로 확인하고 사용자에게 `code-agent update --templates-only`를 안내한다.
   열은 받은 그대로 `| id | 계획 파일 | 범위 | 상태 | 지적 |` 이고 **순서가 곧 규칙이다** — 코드가 칸 위치로 읽는다.
   `계획 파일` 은 저장소 기준 경로 그대로(백틱도 `:줄번호` 도 붙이지 않는다), `상태` 는 `열림` · `해결` 둘뿐이다. 지적이 없으면 `- 없음`.
   `## 회차` 의 머리(번호·시각·기준 트리 해시)는 **코드가 적는다** — 손으로 쓰거나 고치지 않는다.
4-1. **교차 검증을 선택한 프로젝트**(`execution both`)면 독립 리뷰 뒤 Bash: `code-agent review cross --by codex` — 다른 호스트가 같은 회차를 읽기 전용으로 교차 리뷰하고 ⑨ 의 `## 교차 지적`(id `X<번호>`)에 기록한다. CLI 가 9분에 끊고 기록하므로 timeout 을 600000ms 로 주거나 백그라운드로 실행한다. 메인은 그 절을 고치지 않는다. 회차마다 한 번만 기록되고 완료된 회차는 다시 실행하지 않는다 — 교차 지적도 아래 수정 루프와 새 회차로 처리한다. 출력이 `교차 검증 중지` 면 다른 호스트를 실행할 수 없었던 것이다(미설치·로그인·사용 한도·장애) — 사용자에게 사유를 한 줄 알리고 계속한다. 그 밖의 실패(설정 오류·형식 오류·시간 초과·샌드박스)는 게이트가 막고 출력이 다음 행동과 남은 횟수를 알려 준다 — 그 안내만 따르고 같은 명령을 스스로 반복하지 않는다.
4-2. 어느 리뷰든 열린 지적·계획 밖 지적이 있으면 게이트가 막는다. 같은 회차에 `ca-reviewer` 를 다시 불러도 기록은 바뀌지 않는다. 사용자가 지적이 틀렸다거나 범위 밖이라고 판단하면(두 리뷰의 의견이 갈릴 때 포함) 공통 동의 절차로 `{"action":"judgment","kind":"waive-finding","id":"<F·X 번호>","comment":"<사용자 사유>"}` 를 받는다. 지적 줄은 그대로 남는다.
5. **계획 안** 지적은 `.claude/skills/ca-check/SKILL.md` 의 **↺ 수정 루프**로 고친다. 고친 뒤 `code-agent verify --json` 으로 check·test 부터 다시 돌아
   1 로 돌아와 **새 회차**를 연다. 새 회차 context 의 **재검토 범위**(바뀐 계획 파일·직전 지적)는 리뷰어가 읽는다(옮겨 쓰지 않는다). 리뷰어가 수정 확인 후 `해결`로 보고하게 한다.
   리뷰 회차는 3회까지다 — 세 번째 회차에도 계획 안 지적이 남으면 고치지 말고(hook 이 막는다) 사용자에게 판단을 받는다(ca-answer 의 `judgment` 동의로 회차 추가·지적 기각, 또는 재계획).
   한 번 적은 지적 줄은 **지우지 않는다** — 얼어 있던 테스트 파일을 그 줄로 풀었으면 코드가 기억하고 있어, 지우면 게이트가 막는다.

## 끝

열린 지적과 미처리 `계획 밖` 지적이 모두 0이면(사람 판단으로 기록한 것은 세지 않는다) Bash: `code-agent next` — 거부되면 차단 복구를 따른다. 범위 변경이 필요한 지적은 공통 선택 절차로 방향을 확인하고 재계획·재승인으로 연결한다.
통과하면 회차와 지적 수를 짧게 보고한다. 전체 작업 흐름에서는 `/ca-integrate` 절차로 자동으로 이어가고, 리뷰 단계만 요청받았으면 여기서 마친다.
