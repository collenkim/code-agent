# 접수 용어 구분

사용자 요청에 따라 실행 절차와 업무 식별자의 혼동을 줄였다. README·사용 가이드·CLI 도움말은 `/ca-fix` 등을 실행 명령 또는 실행 절차로 안내한다. 호스트가 요구하는 `skills/`·`SKILL.md` 경로와 내부 함수명은 유지한다.

| 용어 | 의미 |
|---|---|
| 실행 명령 | `/ca-fix`, `$ca-fix` 등 개발 절차 호출 |
| 작업 ID | code-agent의 작업 식별자. 외부 식별자를 재사용하거나 `WORK-0001`처럼 자동 발급 |
| 외부 업무 식별자 | Jira 티켓 키·Notion 페이지 ID 등 원래 업무의 식별자 |
| 조사 ID | 오류 사전 판별 기록의 내부 식별자. Jira 티켓 키와 다름 |

사전 판별의 외부 연결은 Jira 전용이며 Notion 연동을 추가한 것은 아니다. Notion의 요구사항 내용·출처는 일반 접수로 전달할 수 있다. Jira 연결 인자는 `<Jira티켓키>`, 판별 기록 조회·재판별·배포 기록 인자는 `<조사ID>`로 명시했다. 접수·중복 판별·개발 게이트의 동작은 유지한다.

`npm.cmd run build`와 관련 56개 테스트가 모두 통과했다(실패·생략 0, 26.6초). 사전 판별·CLI·양쪽 호스트 템플릿·예산·문서 동기화·흐름도 줄 인용·최종 회귀를 확인했다. 템플릿 문구는 기존 흐름 합계 예산 안으로 줄였으며 예산을 늘리지 않았다. `git diff --check`도 통과했다. 직전 기능 변경의 전체 회귀 결과(1,376개 중 1,372개 통과·생략 4)는 [로그 중복 판별 기록](2026-10-12-log-dedup.md)에 있다.
