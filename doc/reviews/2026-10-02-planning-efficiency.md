# 계획 실행 효율과 역할별 모델 설정 개선 이력

기준일: 2026-10-02. 기준 커밋: d1045d0. 현재 사용 계약은 [계획 작업](../planning.md), 호스트 차이는 [Codex 연동](../codex.md)을 따른다.

후속 우선순위 2와 Codex 재검증은 [별도 이력](2026-10-02-priority-two-native-codex.md)에 기록한다. 아래 수치와 실패 원인 해석은 당시 기록이며 후속 검사로 덮어쓰지 않는다.

## 목적과 범위

Hermes의 공개 실행 구조에서 참고한 우선순위 1 개선 세 가지를 기존 코드 에이전트에 적용했다. Claude·Codex 내부 추론을 재구현하지 않고 CLI·스킬·관찰 결과 경계를 개선한다. 단계별 승인·근거·독립 검토 계약은 유지한다.

- 선행 결과와 캐시 응답에서 문서 본문을 경로·해시·길이로 바꾼다. 판단·근거·질문·차단 지적은 보존한다. 상세 원문은 기록과 파일에 남고 `planning result <ID>`로 조회한다. status는 요약이다.
- `planning advance`가 기본 작업 준비·재사용·선행 조건·동시 한도·배정을 같은 상태 잠금에서 처리한다. 실제 에이전트 호출과 사용자 판단이 필요한 경계만 메인에 반환한다. 단계 전환·계획 제출·승인은 자동 처리하지 않는다.
- 관찰된 출력 형식 오류의 원본을 보존하고 같은 입력에서 한 번만 교정한다. 새 배정 식별자와 새 담당 관찰을 요구한다. 원본에서 유효한 필드의 내용 변경은 거부한다. 형식 교정까지 실패한 작업을 advance가 자동으로 전체 재실행하지 않는다.

명시적인 작업 등록과 배정은 기존 prepare·dispatch를 계속 사용한다. 저장 상태 버전은 1을 유지하며 교정·시작 연결 필드는 선택 사항이다. 스킬 4개를 갱신했고 Codex 자산도 공통 원본에서 같은 절차를 생성한다. 기존 설치에서는 템플릿 갱신과 호스트 재시작이 필요하다.

추가 실제 검사에서 호출 이름의 하이픈 거부를 확인하여 Codex 역할의 `name`을 밑줄 형태로 변환했다. 배정은 `hostAgents.claude`와 `hostAgents.codex`를 함께 제공하고 Codex 스킬은 후자를 선택한다. 관찰 어댑터는 Codex 역할을 공통 역할로 연결한다. 갱신·제거 시 파일 소유권을 유지하도록 기존 TOML 파일 경로는 바꾸지 않는다.

Claude는 기존 역할별 Claude 모델 설정을 사용한다. 추가 사용자 요구에 따라 Codex도 부모 설정 상속에서 제품의 역할별 기본 모델·추론 강도와 사용자 변경값으로 전환했다. 기본값은 gpt-6.1-sol이며 analyst·critic·reviewer는 high, 나머지 역할은 medium이다. 이는 시작 정책이며 최적 비용·성능 조합을 실측한 결론은 아니다. 사용량 집계는 현재 Claude만 지원한다.

`model --host` 조회·변경·기본값 복원, 기존 같은 세션 model 동의, 초기 설치·업데이트 시 변경값 보존, doctor의 유효 설정 대조, 최종 반영 경로를 함께 갱신했다. 두 호스트의 설정 파일을 분리하고 둘 다 설치한 경우 변경 호스트를 명시하게 한다. 모델 식별자·추론 값과 계정의 실제 사용 권한 검증은 구분한다. 변경 후 호스트 재시작이 필요하다. 앞선 실제 모델 검사는 이 역할별 Codex 모델 설정 추가 전의 기록이며 최종 설정으로 실연동에 성공했다는 뜻이 아니다.

## 검증 기준

자동 검사에서는 Claude·Codex 각각의 설치 파일, 동일한 분석→조사→종합→설계→계획→독립 검토 흐름, 형식 교정, 승인 전 전환 차단을 대조한다. 합성 이벤트와 실제 모델 실행은 구분한다.

회귀 범위에는 문서 원문 보존·참조 전달, 오래된 결과 표시, 반복 advance의 중복 배정 방지, 영역 분할·동시 한도·질문·충돌, 교정 1회 제한, 원본 차단 지적 보존, 입력 변경·위조 식별자·늦은 결과·미관찰 결과 거부가 포함된다. 여러 병렬 담당 중 출처를 확인할 수 없는 깨진 JSON은 자동 교정하지 않는다.

긴 문서 fixture에서는 선행 전달 JSON이 기존 원문 결과 크기의 10분의 1보다 작음을 검사한다. 이는 해당 fixture의 전달량 검사이며 실제 모델 토큰·비용·전체 작업 시간의 절감률이 아니다. 메모리 자동 학습, 모델 자동 선택, 난이도별 단계 통합은 이번 범위에 포함하지 않는다.

## 실행 근거

검사 명령·결과·시간·로그 해시는 [원자료 요약](evidence/planning-efficiency-2026-10-02.json)에 보존한다. 과거 검증 보고서의 수치와 합산하지 않는다. 실제 호스트 검사는 `scripts/evaluate-planning-hosts.cjs`로 임시 프로젝트에서 수행하며 초기 준비·요구 확정·Claude 모델 선택 동의는 합성 fixture다. 실제 사용자 승인·전체 개발 흐름의 실사용 측정으로 해석하지 않는다.

실제 호스트 검사 도구의 최초 실행은 비대화형 모델 변경 제한에 걸렸다. 제품의 제한을 유지하고 모델 선택을 명시적인 합성 동의 fixture로 변경했다. 이 최초 시도에서는 모델을 호출하지 않았다. 전역 호스트 설정이나 훅 신뢰 설정을 자동 변경하지 않는다.

| 검사 | 결과와 해석 |
|---|---|
| 전체 회귀 | 709개 중 705개 통과·실패 0·생략 4개. 역할 이름·역할별 모델 설정 보완 전후의 실행은 원자료에서 구분한다. |
| 공통 계획 기능 | 두 호스트별 설치·분석→조사→종합→설계→계획→독립 검토·교정·승인 게이트를 합성 관찰 이벤트로 검사한다. |
| 실제 Claude 2.1.287 | 명확한 함수 요구 fixture에서 실제 분석 담당·완료 훅·게이트 준비 확인. 56,808ms. |
| 실제 Codex 0.160.0 | 명령 실행은 확인했지만 설치 역할 선택 인자가 제공되지 않았고 로컬 훅도 관찰되지 않았다. 실제 연동 미완료. |

Claude 최초 모델 실행에서는 배정 밖 근거 인용을 거부했다. 범위를 명시한 후에는 모호한 요구로 미결 질문과 확정 문서를 함께 반환해 기존 계약이 거부했다. 입력·기대 동작·오류를 명시한 fixture에서 통과했다. 성공 기록으로 앞선 실패를 덮어쓰지 않는다.

Codex 최초 실행은 담당 응답이 있었지만 관찰 이벤트가 없어 완료되지 않았다. 검토한 훅의 일회성 실행 옵션을 사용한 격리 검사에서는 기존 Windows 샌드박스 설정 누락으로 명령이 거부되었다. 기존 설정을 유지하자 명령 실행은 가능했고, 하이픈 이름 문제를 발견했다. 이름 보완 후 환경이 제공한 호출 도구에는 설치된 역할 선택 인자가 없어 중단했다. 로컬 훅 기록도 생성되지 않았다. 이는 현재 환경의 실측 결과이며 모든 Codex 환경의 불가능을 뜻하지 않는다.

자동 검사 도구의 `--vetted-hooks`는 사용자·상위 훅이 없는지 확인하고 생성된 훅만 검토한 뒤 공식 일회성 옵션을 사용한다. Windows에서는 기존 샌드박스 구현을 유지하며 작업 공간 쓰기 제한을 해제하지 않는다. 일반 설치에는 이 옵션을 적용하지 않는다. [공식 훅 문서](https://learn.chatgpt.com/docs/hooks)는 로컬 훅과 클라우드 실행의 지원 범위를 구분한다. 현재 환경의 역할 선택·로컬 훅 부재와 관련될 가능성은 있지만 정확한 실행 방식은 이번 검사만으로 확정하지 않는다.
