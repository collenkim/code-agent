# 메인 컨텍스트 토큰 효율 개선 이력

기준일: 2026-10-06. 기준 커밋: 62bef62. 현재 계약은 [설계 §1 메인 컨텍스트로 들어가는 것](../design.md#메인-컨텍스트로-들어가는-것), [계획 작업](../planning.md), [Codex 연동](../codex.md)을 따른다. 원자료는 [token-efficiency-2026-10-06.json](evidence/token-efficiency-2026-10-06.json)과 `full-flow-new-2026-10-06-opus-*.json`이다.

## 목적과 범위

Hermes Agent 비교 검토에서 나온 권장안(P0 측정 → P3 지침 축소 → P2 전달 파일 → P1 staging → P4 시작 hook → P5 동의 묶기)을 적용했다. 사람 확인 지점과 역할별 opus 기본값은 바꾸지 않았다. 권장안 5(절차 교훈 학습 장치)는 이후로 남겼다.

| 항목 | 변경 |
|---|---|
| P0 측정 | `evaluate-full-flow.cjs`에 `--model`·`--label`·`--budget`·`--timeout`과 `usage` 집계를 더했다. `total_cost_usd`가 `--continue` 세션 누적값이라 턴 비용은 직전 누적값과의 차이로 센다. 업무 질문의 빈 답은 드라이버가 '평가 fixture 답'으로 채우고 기록한다 |
| P3 상시 지침 | CLAUDE 블록 4,511→1,493자. planning 스킬 4개에서 문서 기준(`criteria.md`)·이전 버전 작업 절차(`legacy.md`)·계획 작업 계약(`ca-plan/contract.md`)을, ca-answer에서 페이지 나누기·동작 JSON 표·수동 경로(`reference.md`)를 분리했다. 17개 스킬의 공통 문단(342→156자)은 ca-answer를 질문·승인 직전에만 읽게 한다. 메인이 한 흐름에서 읽는 지침 54,494→38,882자 |

## 검토에서 찾아 고친 문제

| 구분 | 내용 | 조치 |
|---|---|---|
| 이번 변경의 회귀 | 배정 파일에 넣은 영향도 기준이 "확인하지 못한 것은 `확인 필요`로 남긴다"(이전 흐름 문장)라 완료 게이트와 충돌 — 실제 실행에서 explore 2회·synthesis 4회 | 기준을 "완료 문서에 남기지 않고 질문 또는 조사 한계로"로 고쳤다 |
| 이번 변경의 결함 | `advance`가 실행 중이 아닌 staging을 지워 형식 교정 대기 원본의 본문을 잃을 수 있었다 | 정리는 완료 hook만 한다(남은 것은 `.gitignore`로 커밋 제외). 교정 담당에게 원본 staging을 옮기라고 지시. 회귀 검사 추가 |
| 이번 변경의 부작용 | 기준선에서 메인이 써 주던 안내(호출당 1.1~2.6K자)가 빠져 분석이 짧은 경로·이스케이프된 인용으로 3회 돌았다 | 단계 context(접수 요구 원문 목록·형식·후보·계획 형식)를 배정 파일에 넣고 경로·인용 규칙을 지시에 추가, 메인 메모는 하이브리드로 허용 |
| 호스트 차이 | Codex 담당 지침에 "staging에 써라"와 "쓰지 말라"가 함께 들어갔다 | Codex 변환에서 해당 문장을 `{path, content}` 문장으로 바꾼다 |
| 기존 결함 | 관찰 흐름에서 계획이 반려되면 메인에게 문서·plan.json을 직접 고치라 했지만 hook이 막는다 | 수정 피드백으로 원인 작업을 다시 배정하도록 고쳤다 |
| 기존 결함 | 재배정 담당이 자기 이전 출력을 근거로 인용해 "배정 범위 밖 근거"로 반복 거부 | 배정 지시에 금지 문장 추가 |
| 기존 결함 | critic 질문이 영어로 기록됐다 | 질문·요약·설명문을 지시서 언어로 쓰라고 배정 지시에 추가 |
| 측정 결함 | 평가 스크립트가 누적 비용을 턴마다 더했다. 2026-10-01 기록의 합계(2.65·3.76·8.83·5.53)는 실제로 마지막 누적값(1.75·2.08·2.89·1.96)이다 | 스크립트 수정, 2026-10-06 기록에 `correctedCostUSD` 추가. 과거 기록은 원본대로 두고 여기서 정정한다 |

PostToolUse의 `updatedToolOutput`으로 서브에이전트 결과를 줄이는 방법은 실험했지만 쓸 수 없었다. Agent 도구가 비동기로 시작돼 PostToolUse가 시작 응답에 붙고, 결과는 별도 알림으로 온다.
