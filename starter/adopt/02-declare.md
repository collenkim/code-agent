# [adopt 02] 선언 — code-agent.json + 컨벤션 문서

> **선행**: [01] 구조 조사 · **다음**: develop (도메인 추가)
> **산출물**: `doc/templates/code-agent.json`, 컨벤션 문서 초안

## 0. 사용법

조사 결과를 이후 실행이 읽을 파일로 옮긴다. **레거시 도입의 본체다.**

이 단계가 끝나면 그 프로젝트는 `develop` 모드를 그대로 쓸 수 있다.

## 1. 입력 게이트

- [ ] [01] 구조 조사서가 있다
- [ ] 표준으로 삼을 도메인이 정해져 있다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| 모든 값이 조사서의 항목으로 추적돼야 한다. 추측으로 채우지 않는다 | 무효 |
| `stages`는 **실제로 존재하는 계층**만. 없는 계층을 만들지 않는다 | 무효 |
| `exemplars`는 표준 도메인에 **실제로 있는 파일 경로**여야 한다 | 무효 |
| `referenceDomain`은 `--reference` 로 지정된 도메인 | 무효 |
| 조사서의 불일치 항목은 컨벤션 문서에 **경고로 남긴다** — 조용히 한쪽으로 정리하지 않는다 | 무효 |
| 기존 문서가 있으면 대체하지 말고, 어긋나는 지점만 표시한다 | 무효 |

## 3. 작업

### 3.1 `code-agent.json`

조사서의 항목이 그대로 키가 된다.

| 조사 항목 | 키 |
|---|---|
| 소스 루트·도메인 분류 | `domainBase`, `domainRoots` |
| 계층 | `stages[]` — 계층당 하나, `outputDirs`는 그 디렉토리 |
| 계층별 대표 파일 | `stages[].exemplars` — `{Ref}` 치환 형태로 |
| 테스트 위치 | 테스트 단계의 `base` |
| 빌드·테스트 명령 | `build`, `test` |
| 표준 도메인 | `referenceDomain` |

> `exemplars`가 실제 파일과 어긋나면 생성 품질이 무너진다. 조사서에서 확인된 경로만 쓴다.

### 3.2 컨벤션 문서

기존 문서가 있으면 **그것을 그대로 쓰고**, `code-agent.json`의 `conventions`가 그 경로를 가리키게 한다.
없거나 부족하면 조사서를 근거로 초안을 만든다. 불일치는 경고로 남긴다.

## 4. 자가검증 체크리스트

- [ ] `domainBase`·`outputDirs`가 실제 디렉토리와 일치하는가
- [ ] `exemplars`의 모든 경로가 표준 도메인에 실제로 존재하는가
- [ ] 조사서에 없는 계층·규칙을 넣지 않았는가
- [ ] 불일치 항목이 경고로 남았는가 (임의로 정리하지 않았는가)
- [ ] 기존 문서를 덮어쓰지 않았는가

## 5. 산출물 → 다음 단계 입력

- **산출물**: `code-agent.json`, 컨벤션 문서
- **사람이 할 일**: `exemplars` 경로가 맞는지 확인 (여기가 틀리면 이후 전부가 흔들린다)
- **다음**: `--templates doc/templates` 로 develop 모드 사용
