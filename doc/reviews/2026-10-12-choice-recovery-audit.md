# 두 호스트의 질문 도구와 차단 복구 재점검

## 확인한 문제

- 사용자가 제시한 Codex 사례는 문서 작성 방식의 선택지를 글머리표로 출력하고 질문 도구를 호출하지 않았다. 이것은 hook 차단과 구분해야 한다. Codex 전용 질문 지침은 도구 이름·현재 모드의 가용성·호출 실패 대체 경로가 불명확했고, Claude의 AskUserQuestion 치환은 업무 질문과 동의 응답 절차를 혼동하게 했다.
- `ca-adopt`에는 거부하면 사유만 전하고 멈추라는 지시가 남아 있었다. 구현·검증·단계 불일치에도 같은 지시가 있었다. 공통 복구를 안내한 앞선 수정이 모든 진입을 포괄하지 못했다.
- `ca-adopt 소스 설정 기준으로 작성`으로 방향이 정해진 뒤 `planning --help`가 거부된 사례에서, 기존 복구 지침의 무조건 응답 대기가 허용된 `code-agent help` 조회에도 추가 확인을 요구했다.

## 반영

17개 진입의 공통 질문 문단을 같은 글자로 맞추고 ca-answer의 복구 참조를 연결했다. Codex는 사용 가능한 질문 도구를 실제 호출하고 request_user_input의 현재 모드·사용 조건을 따르며, 도구가 없거나 거부되면 번호·선택지·결과를 대화로 제시한다. Claude도 AskUserQuestion을 실제 호출하고 도구를 사용할 수 없는 경우에만 대화로 답을 받는다. 두 호스트 모두 대화 답을 승인으로 바꾸지 않는다. Codex 변환은 AskUserQuestion을 업무 질문 도구로 명시한다.

차단된 동작은 중지하지만 허용된 도움말·상태 조회와 이미 선택한 방향은 재확인 없이 수행한다. 새 결정에 의존하는 동작만 응답을 기다린다. 명시적 취소·보류는 존중한다. 범위 변경·문서 확정·작업 중단 등의 기존 동의와 게이트는 유지한다. 작업 ID와 원문을 보존한다.

## 템플릿 예산

공통 복구 참조와 도구 가용성·동의 구분을 진입과 질문 시점에서 읽도록 유지한다. 필요할 때 읽는 reference 예산은 7,100→7,400자, Codex 질문 정본은 4,100→4,700자로 조정한다. 흐름 합계는 Claude 51,700→52,500자, Codex 49,500→50,500자다. 다른 파일 예산은 유지한다. 초기 검증은 이 예산 초과 2건을 발견했고 정책 문장 검증은 통과했다.

## 검증 범위

두 호스트 생성본의 17개 진입·질문 정본·복구 참조·기존 선택 존중·모드 제한·승인 분리를 회귀 시험으로 대조한다. 텍스트·설치 검증은 실제 호스트가 도구를 호출한다는 보장이 아니다. cloud 설치본 갱신과 실제 Codex·Claude 선택 UI 재현은 수행하지 않았다.

`npm.cmd test`(빌드 포함)는 1,379개 중 1,375개 통과·실패 0·플랫폼 생략 4개, 272.3초다. 이후 참조 경로 명확화와 남은 중단 문구 정리를 하고, triage·templateBudget·templateText·hookLoad·docSync·finalReverify·hostNotation 97개를 재검증하여 모두 통과했다(28.1초). 최종 문구 대조 중 ca-test 예산 4자 초과는 공통 문단을 줄여 해결했다. `git diff --check`도 통과했다.
