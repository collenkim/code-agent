# [fix 02] 수정

> **선행**: [01] 실패하는 재현 테스트 · **다음**: 없음 — 사람이 확인하고 옮긴다
> **근거**: [01] 의 실패 메시지 · 대상의 현재 코드 · 지시서의 `preserve`
> 이 단계는 `expect: pass` 다 — [01] 의 테스트가 **통과**하는 것을 확인해야 끝난다.

## 0. 사용법

[01] 이 고정한 결함을 고친다. 고치는 범위는 지시서의 `scope`, 지켜야 할 것은 `preserve` 다.
결함의 원인이 `scope` 밖에 있다면 고치지 말고 `note` 로 남긴다 — 지시서를 고치는 것은 사람의 일이다.

**do-not-touch**: 이 단계의 `outputDirs` 에 테스트 디렉토리가 없다. **테스트를 고치거나 지워 통과시키는 길은 막혀 있다.** 테스트가 잘못됐다고 판단되면 `note` 로 남기고 멈춘다.

## 1. 입력 게이트

- [ ] [01] 의 테스트가 있고, 그 실패 메시지가 「앞 턴에서 요청한 것의 결과」에 있다
- [ ] 지시서에 `scope` 와 `preserve` 가 있다 (0차 게이트가 이미 확인했다)
- [ ] 계획의 `preserve` 항목마다 "어떻게 지키는지"가 적혀 있다 (계획 저장 때 코드가 확인했다)

## 2. 규칙 게이트

| 규칙 | 근거 | 위반 시 |
|---|---|---|
| 고치는 것은 [01] 의 실패 메시지가 가리키는 원인만이다. 그 김에 정리하지 않는다 | 경계 | 무효 |
| `preserve` 에 적힌 것은 바꾸지 않는다 — 경로면 코드가 막고, 문장이면 여기서 지킨다 | 지시서 | 무효 |
| 기존 테스트가 새로 깨지면 그것은 회귀다. 통과시키기 위해 기존 동작을 바꾸지 않는다 | `preserve` | 무효 |
| 테스트를 고치지 않는다 | 경계 | 무효 |
| `### run test` 로 돌려 **통과**를 확인한다. 파일을 고쳤으면 다시 돌린다 | `expect: pass` | 끝나지 않음 |

## 3. 작업

1. [01] 의 실패 메시지에서 원인 위치를 특정한다. 추측이면 `### read` 로 그 파일을 먼저 본다
2. 원인만 `edit` 으로 고친다 — `write` 로 파일을 통째로 다시 쓰지 않는다. 나머지가 조용히 사라진다
3. `### run test` 로 돌린다. [01] 의 테스트가 통과하고 **기존 테스트가 그대로 통과**해야 한다
4. 기존 테스트가 깨졌으면 그 수정을 되돌리고 다른 원인을 찾는다. 두 번 반복되면 `note` 로 남기고 멈춘다
5. 통과하면 `### done`

## 4. 자가검증 체크리스트

- [ ] 고친 파일이 전부 계획의 목록에 있고, 전부 본문 소스인가
- [ ] 고친 줄이 전부 [01] 의 실패 메시지 하나로 되짚어지는가
- [ ] `preserve` 의 각 항목이 계획에 적힌 방식대로 지켜졌는가
- [ ] 마지막 `run` 이 마지막 `edit` 뒤이고, 결과가 **통과**인가
- [ ] 테스트 파일을 한 줄도 고치지 않았는가

## 5. 산출물 → 사람

- **산출물**: [01] 이 통과하는 상태의 `out/`
- **사람이 할 일**: 4차 확정 뒤 저장소에 옮긴다. 재현 테스트는 함께 남는다 — 그것이 이 결함이 다시 오지 않게 하는 것이다
