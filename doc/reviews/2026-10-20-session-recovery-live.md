# 종료 독립 세션 복원과 실제 모델 검증

code-agent만 수정했다. 다른 저장소와 실제 관리 프로젝트는 수정하지 않았고 push하지 않았다. 변경은 관리 기록 없는 종료 세션의 명시적 복원, 같은 세션의 응답 재개, 선택 실행 평가 도구와 문서다. HTTP API 전환이나 자동 호스트 전환은 포함하지 않는다.

## 구현 범위

- `master recover <요청ID>`로 관리 기록 없는 종료 세션의 원본 대화를 대조하고, 호스트 밖 TTY에서 사람이 모든 원래 실행의 종료를 확인하면 결과 미검증의 `blocked` 복원 실행으로 연결한다. 질문의 서명 대상·받은 답과 기존 작업 ID·feature/fix 종류를 보존하고 AI grant나 승인을 만들지 않으며, 실제 서명 답을 받은 뒤 기존 적용·재개 처리기를 쓴다. 상태 형식 세대는 9다. 원본 확인 항목·거르는 조건·중복 방지는 [대시보드 인계 문서](../dashboard-interactions.md#관리-기록-없는-종료-세션-복원)가 정본이다.
- 실제 완주 평가에서 questions.md에 답한 뒤 낡은 미응답 화면이 남는 경우를 확인했다. 같은 문맥의 원래 질문 모두에 기존 출처 검사를 통과한 답이 있고 문서 해시가 바뀌면 미수신 요청만 superseded로 닫는다. 질문 삭제·출처 미확인 답은 대기를 풀지 않는다. 이미 받은 서명 답은 보존하고 문서 적용 시 해시가 다르면 거부하며, 원래 채널의 답을 대시보드 승인으로 바꾸지 않는다.

## 검증 근거와 구분

실제 모델의 동작과 자동 평가 입력을 분리했다. 평가 드라이버의 TTY 확인·선택·사람 채널 키는 합성 fixture이며 실제 사용자 승인으로 보고하지 않는다. 제품의 승인·검증 게이트와 hook은 우회하지 않는다. Codex 완주 평가에서만 검토한 임시 프로젝트 생성 hook에 공식 일회성 신뢰 옵션을 사용하며, 제품 관리 실행에는 이 옵션을 추가하지 않는다.

| 검사 | 결과·근거 |
|---|---|
| 실제 Claude 종료 세션 복원 | 통과. 실제 hook으로 질문 발행 → 호스트 종료 → 원본 대조·복원 → 서명 답 재전송 → 동일 sessionId 한 번 재개 → consume·complete. 대화에만 있던 기억값을 재개 결과에서 확인했다. [원자료](evidence/2026-10-20-live-session-recovery.json) |
| 실제 Claude 신규 개발 완주 | 통과. 최초 계획 검토의 제한 시간 종료 후 같은 세션 ID로 재개했다. 테스트 실패에 따른 재계획·재승인 후 TC 11개와 통합 TC 11개 통과, 실제 독립 리뷰 1회 관찰, 로컬 반영 커밋 `a07af9d`와 진행 커서 종료를 확인했다. 최초 ID `WORK-0001`·종류 `feature`의 식별 기록은 하나다. [원자료](evidence/full-flow-new-2026-10-20-live-claude.json) |
| 실제 Codex 신규 개발 완주 | 미통과. 원문·sourceMap·공통 문서·요구 제출 후 `start`의 `.git/index.lock: Permission denied`로 중단됐다. Windows workspace-write·approval_policy=never 권한은 확대하지 않았다. 비용은 측정 불가이며 0으로 주장하지 않는다. [원자료](evidence/full-flow-new-2026-10-20-live-codex.json) |
| 실제 Codex 원본 대조 | 위 실제 실행의 native JSONL을 복원 파서로 읽어 thread ID·프로젝트·주 세션·대화 존재를 확인했다. 원자료의 `nativeSessionValidation`에 파일·해시·크기를 남겼다. 관리 재개 완주 검사는 아니다 |

실제 호스트 버전은 Claude Code 2.1.303, codex-cli 0.163.0이다. 실제 Claude 복원은 `dist-bin`의 같은 깊이 별도 TypeScript 산출물로 검사했다. 당시 진행 중인 완주 평가가 사용하는 `dist`와 빌드 경합을 피하기 위한 경로이며 제품 진입점은 `dist/agent/cli.js`다.

복원 회귀는 Claude·Codex 원본 대조, 실제 Ed25519 서명 fixture, 질문 전체 대기, 같은 세션 재개 예약, 재전송, 원본 변경, 소유 세대 변경, 원본 누락·다른 프로젝트·하위 담당·손상 파일·외부 파일, Codex 신뢰 조건, 최초 접수 ID·종류 보존, 실행 저장 후 원장 연결 전 장애, 미응답 만료를 검사한다. 최종 검사 수치와 빌드는 [집계 근거](evidence/2026-10-20-session-recovery-live.json)에 기록한다.

Node 24.19.0에서 `npm.cmd ci --offline --no-audit --no-fund`·`npm.cmd run build`·타입 검사·스크립트 구문 검사·`git diff --check`를 통과했다. 전체 회귀는 1,664개 중 1,660개 통과·실패 0개·플랫폼 생략 4개이며 약 722초가 걸렸다. 전체 회귀 실행 중 마지막으로 강화한 질문 삭제·출처 미확인 차단과 복원 이벤트 커서는 최종 빌드에서 관련 28개를 다시 실행해 모두 통과했다.

평가 드라이버도 보완했다. 전체 평가의 재개는 명시적 native session ID만 사용한다. Codex의 동일 Git 권한 거부를 반복하지 않고 첫 차단에서 멈춘다. 실제 복원 평가의 첫 재검증은 재전송 응답의 `at`·`replayed`까지 같아야 한다는 드라이버 단언 오류로 실패했고, 그 단언을 고쳐 저장 영수증·실행 개수·세션·기억값·적용 결과를 원래 실행 기록으로 다시 검증했다. 모델을 성공한 것처럼 대체하지 않았다.

## 인계와 남은 범위

명령·API 예제·연결 조건의 정본은 [대시보드 인계 문서](../dashboard-interactions.md)다.

- Windows Codex의 `.git` 보호에 막힌 Git 쓰기는 자동 권한 상승이나 sandbox 해제 대신 단건 권한 경로로 처리한다 → [Git 실행 권한](2026-10-20-codex-git-permission.md)·[셸 꼴 보완](2026-10-23-codex-git-wrapper.md)에서 실제 Codex 와 합성 대시보드 승인으로 `code-agent start`의 단건 승인 실행까지 확인했다. 실제 Codex 의 전체 개발 완주는 그 뒤 다시 검증하지 않았다.
- 실제 Codex 종료 세션 복원의 대시보드 연속 실행은 별도 실측 대상이다. 이번에는 Codex 원본·신뢰·서명·동일 thread 예약을 회귀 시험으로, 실제 대화 기억을 포함한 종료·재개는 Claude로 확인했다.
- 실제 브라우저 클릭·운영 환경 반영·업데이트·플러그인 실행은 이번 검증 범위가 아니다.
