# 대시보드 사람 응답과 실행 호스트 선택 검증

변경 커밋: 이 기록과 같은 커밋. 인계 계약은 [대시보드 상호작용](../dashboard-interactions.md), 실행 정책은 [Codex 연동](../codex.md)을 따른다.

## 변경 범위

- 10개 단계의 질문·선택·복구 판단과 14개 동의를 프로젝트 원장에 저장한다. 추천·이유·근거·직접 입력 조건과 수신·소비·적용·재개 결과를 분리한다.
- 대시보드 조회·서명 응답 API를 기존 로컬 CLI 제어 계약에 추가한다. 별도 HTTP 서버를 만들지 않는다. 기존 LangGraph의 사람 대기·소비 인계에 연결한다.
- 실제 사람 채널은 일반 제어 토큰·AI 위임과 분리한다. 기존 동의 스냅샷·권한·승인·검증 게이트를 재사용한다. 같은 commandId 재전송과 동시 응답은 원자적 원장 잠금으로 중복 처리하지 않는다.
- init은 두 호스트를 준비한다. 단독 Claude·단독 Codex·교차 검증을 설치와 별도로 선택한다. 기존 both 설치의 교차 의무는 보존한다. 자동 호스트 전환이나 Codex 비대화형 감독은 추가하지 않는다.
- 상태 세대를 7로 올린다. 보조 지침 dashboard.md는 필요할 때 읽고, 기존 주 지침 예산은 늘리지 않는다.

## 검증 범위

임시 Git 저장소에서만 실행했다. 실제 관리 프로젝트·master-agent 저장소는 수정하지 않았고 push하지 않는다.

자동 시험은 단계별 발행·기본값 비응답, 단일·다중·직접 입력, 누락·위조·재전송·동시 응답, 보류·취소·만료·인계·권한 회수, 브랜치·HEAD·원문 변경을 검사한다. setup·request·plan·docs 동의는 실제 도메인 처리기를 호출해 승인 원장·최초 feature 접수·구현 진입을 확인한다. 다른 동의는 기존 전체 회귀의 도메인 게이트와 공통 적용 경로를 함께 검사한다.

실제 CLI 프로세스 두 개의 경쟁 제출과 재시작 조회를 검증했다. 실제 감독이 시험용 호스트 프로세스를 시작하고 같은 세션에서 답 소비 → 처리 결과 → 다음 질문으로 이어지는 경로를 확인한다. 다른 임시 프로젝트의 원장은 그대로다. 시험용 호스트는 LLM을 호출하지 않는다.

새 공개 init·호환 인자·두 호스트 파일·MCP 설정, 단독/교차 정책, 재설치 보존, 잘못된 정책의 차단, 다른 호스트의 쓰기 거부도 검증한다. `npm ci`·빌드를 통과했고 전체 회귀 1639개 중 1635개 통과·실패 0·생략 4다. 이후 후속 답 출처 호환 보완과 시험 파일 분리를 포함한 최종 빌드의 집중 검사 54개도 통과했다. 수치는 [기계 판독 근거](evidence/2026-10-19-dashboard-interactions.json)에 기록한다.

전체 병렬 실행에서 새 상호작용 시험 파일의 검사 합계가 약 175초여서 접수·계획 승인(`dashboardApproval`), 동의(`dashboardConsent`), 질문·재개(`dashboardInteractions`)로 나누고 준비 코드는 `dashboardFixture`로 공유했다. 대시보드 답의 Source만 바꿔 출처 검사를 피할 수 없으며, 이후 실제로 기록된 다른 채널의 답은 기존 observed/delegated/relayed/contract 분류를 유지한다.

## 남은 검증과 인계

master-agent의 브라우저 UI·서명 키 보관·명시적 제출 처리와 실제 두 모델의 완주 시험은 별도다. 종료된 독립 세션·Codex 비대화형 세션 자동 재개, 실행 도중 자동 호스트 전환은 지원하지 않는다. 승인이나 반영 단계의 실제 운영 실행을 모의 호스트 시험으로 검증했다고 주장하지 않는다. Claude 열린 질문창의 외부 강제 닫기는 지원하지 않으며 저장된 답을 원래 세션에서 소비한다.
