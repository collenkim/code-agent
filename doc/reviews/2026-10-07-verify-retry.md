# 검증 재시도 — 원인별 카운터·환경 분류·동결·worktree 표지

기준일: 2026-10-07. 기준 커밋: `3b5e867`(재시도 규약 공통 모듈). 감사 [2026-10-07 이중 호스트 프로세스 감사](2026-10-07-dual-host-process-audit.md)의 검증 영역 지적을 실패 원인별 재시도 규약([프로세스 흐름도](../process-flow.md) §6.4)에 연결했다. 현재 동작은 흐름도 §6.2·§6.3이 정본이다.

## 결정

| ID | 판정 | 바꾼 것 |
|---|---|---|
| PVR-3 | 수정 | 검증 회차를 원인별 카운터(고쳐 쓰기·수집 수정·같은 코드 재실행·통합 검증 재실행·리뷰 회차·총 회차)로 나눴다. `check()`·`verify`·hook·`status`가 `retryPolicy.ts`의 같은 판정(`nextRoundDecision`·`verifyNode`·`writeBlockReason`)을 쓴다. 통과한 회차 뒤의 변경은 고쳐 쓰기를 쓰지 않는다 |
| FLOW-06 | 수정 | 리뷰 회차 3회(`review.json` `limit`, 사람 허용 +1)와 총 회차(1+고쳐 쓰기+리뷰+수집)를 뒀다. 판정은 `reviewRoundUsageOf` 하나이고 `openRound`는 같은 트리 거부 뒤에 한도를 본다 |
| PVR-4 | 수정 | 선언된 환경 문구는 같은 실행의 결과(콘솔 결과 줄·새 보고서의 모든 testcase)에 실패가 없을 때만 환경이다. 같은 코드 재실행은 회차당 2회다 |
| PVR-17(검증) | 수정 | 시간 초과를 `CommandResult.timedOut`·`VerifyRun.cause`로 남기고 같은 코드의 `--retry`는 같은 회차를 쓴다 |
| FLOW-05·PVR-9 | 수정 | 동결은 결과가 인식된(또는 코드 결함으로 실패한) test 실행부터다. 결과 미확인 회차는 수집 수정 1회 동안 열리고 그 회차는 고쳐 쓰기를 쓰지 않는다(fix 작업은 없다). `check`가 ⑦ TC id 사전 점검 줄을 낸다 |
| PVR-8 | 수정 | 통합 검증·격리 재현은 체크아웃마다 하나인 `.code-agent/log/worktree.lock`을 카운터 기록 전에 쥔다. 임시 worktree 이름에 체크아웃 키를 넣고 자기 키의 것만 정리한다. test·통합 검증 시작 표지(`retry.started`)로 끊긴 실행을 센다 |
| PVR-14 | 일부 | 콘솔 JUnit 은 `<?xml` 선언이 있을 때만 읽고, 보고서 탐색 중단을 기록·안내한다. TAP 헤더 요구·보고서 경로 선언은 미뤘다(픽스처·러너 호환, 매니페스트 스키마 범위) |
| PVR-15 | 수정 | 동결 때 kind:test 파일 해시를 `testFreeze`에 남기고 test·integrate 게이트가 대조한다. ⑨ 지적으로 연 파일과 수집 수정 회차의 파일은 다음 `check`가 기준을 갱신한다 |
| PVR-13 | 수정 | 부분 트리 해시를 파일 바이트로 계산한다. 유효한 UTF-8 파일은 값이 같다(골든 테스트) |
| C3-X1 | 수정 | 격리 재현 갱신이 실패해도 증거의 `treeHash`를 바꾸지 않는다(`carryForRepro`) |

옛 증거(`retry` 없음)는 읽을 때 추정하고 다음 저장 때 기록한다. 엄격해지는 판정은 하나다 — 마지막 회차가 실행 기록 없이 끊긴 뒤 코드를 고치면 고쳐 쓰기를 쓴다(옛 규칙은 마지막으로 기록된 실행을 봤다). 새 필드가 없는 증거의 ⑧ 은 바이트가 그대로다(골든 테스트).

## 설계 명세와 다르게 한 것

- **재현의 환경 분류** — PVR-4 규칙(실패 결과가 있으면 환경이 아니다)을 재현에는 적용하지 않는다. 재현에서 환경으로 보는 것은 재현을 인정하지 않는 엄격한 쪽이라, 컨텍스트 로드 실패로 빨개진 재현 TC 를 결함 재현으로 받으면 게이트가 약해진다(기존 회귀 `p6` 10e).
- **리뷰 뒤 테스트 보완 회귀(`p6` 17b)** — 테스트 파일을 hook 을 거치지 않고 바꾸던 픽스처를 ⑨ 지적으로 연 뒤 바꾸도록 고쳤다. 동결 뒤 지적 없이 바뀐 테스트 파일은 이제 게이트가 막는다(PVR-15). 단언은 그대로다.
- **임시 worktree 이름** — 이름에 체크아웃 키가 들어가 `p5` 의 정리 실패 경고 경로 정규식을 `[\w-]+` 로 넓혔다.
- **안내 문구의 호스트 표기** — CLI 출력은 호스트 중립 문구(공통 모듈 `GUIDE_VARIANTS` 와 같은 `셸 명령의 제한 시간을 가장 길게`)를 쓴다. 장시간 실행 정본 문장(`Bash 도구의 timeout …`)은 Claude 템플릿 네 곳에만 둔다.
- **명세의 T-P1~T-P10** — 공통 모듈 단계의 `retryPolicy.test.ts`가 이미 다룬다. `verifyRetry.test.ts`는 증거 쪽 함수(리뷰 회차 사용량·동결·수집 창·옛 재현 원인 추정)와 ⑧ 골든(T-L3)만 본다.
- **사람 판단 동의(`judgment`)** — 안내·템플릿은 규약대로 그 동의를 가리키지만 동의 동작은 아직 없다. 지금 사람이 고를 수 있는 것은 재계획·재승인·abort 다.

## 근거

- 설계 sandbox(`sandbox-design-C3`): C3-X1 재현(`p6` 17d 뒤 check 게이트가 문제를 내지 않음), `git worktree list` 가 형제 체크아웃의 임시 worktree 를 보여 주고 체크아웃 키 접두어로 갈림, 보고서 파일로만 결과를 내는 러너의 TC 아닌 실패가 로그에 없음, 깊이 14 아래 보고서 누락, UTF-8·바이너리 해시 비교.
- 구현 확인: 바이트 해시로 바꾸기 전 dist 로 옛 증거 ⑧ 과 BOM·한글·CRLF 파일 해시를 골든으로 떠 두고 바꾼 뒤 같은지 대조했다. 임시 저장소에 `init --host both` 를 하고 Codex 사본(`.agents/skills/ca-check`·`ca-test`·`ca-integrate`·`ca-implement`, `.codex/agents/ca-tester.toml`)에 바뀐 문장과 `셸:` 변환이 들어간 것을 확인했다.
- C3-X1 재현 절차: fix 작업에서 재현 → 고침 → `check` 뒤 재현 테스트의 단언을 지우고 `check` 를 부른다. 격리 재현 갱신이 `재현하지 못했습니다` 로 멈춘 뒤 `stageProblems(check)` 에 `계획 파일이 바뀌었습니다` 가 있어야 한다(`p6` 17d).
- `npm test`: 913개 중 909개 통과·실패 0·생략 4(Windows, 약 165초). 새 시나리오는 `p5`(리뷰 회차·통과 뒤 변경·환경 분류·시간 초과 mock·이행·포맷터·계획 밖·수집 수정·동결 대조·worktree 표지 넷·끊긴 test·선반영 회차), `p6`(재현 시도·같은 트리·fix 수집 창·prepare 재실행), `verifyRetry.test.ts`, `build`·`testResults`·`remaining` 에 있다.

## 남은 위험

- 리뷰 회차 판정은 `review.json` 을 잠금 없이 저장한다. 동시 `openRound` 경합은 교차·리뷰 묶음이 잠금 저장(`mutateReview`)을 넣을 때 같은 판정을 잠금 안에서 다시 한다.
- `worktree.lock`·`retry.started` 의 pid 가 다른 살아 있는 프로세스로 재사용되면 표지 나이 한도(명령 한도×3+10분)까지 실행 중으로 본다.
- 보고만 하는 이전 버전 이름의 임시 worktree 는 사람이 지울 때까지 매번 보고된다.
- 수집 수정 창에서 hook 은 쓰기 내용을 보지 않는다. 창은 실패가 없는 회차에만 한 번 열리고, 바뀐 파일은 ⑧ 수정 루프 줄과 독립 리뷰에 남는다.
