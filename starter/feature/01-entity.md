# [feature 01] Entity + 코드 enum

> **산출물**: 이 도메인의 엔티티와 상태·코드 enum · **다음**: [02] Repository
> **근거**: 참조 표준 도메인의 같은 계층 파일. 컨벤션 문서는 근거를 되짚을 때 본다.

## 0. 사용법

참조 표준 도메인의 엔티티가 **어떻게 생겼는지**를 이 도메인의 데이터 정의에 옮긴다. 발명하지 않는다 —
참조 표준에 없는 어노테이션·기반 타입·필드 규약을 새로 들이지 않는다.

**do-not-touch**: 이 단계의 `outputDirs` 밖에는 파일을 만들지 않는다. 다른 계층이 필요해 보이면 `note` 에만 적는다.

## 1. 입력 게이트

- [ ] 계획(`.plan.json`)에 이 단계의 파일이 적혀 있다 — 그 목록만 만든다
- [ ] 스펙에 데이터 정의(필드·타입·필수·길이)가 있다. 없으면 만들지 말고 `ask`
- [ ] 상태값이 있으면 허용 전이가 스펙에 있다. 없으면 `ask` — 전이 없는 상태 enum 은 반쪽이다
- [ ] 참조 표준 코드가 프롬프트에 실려 있다. 실려 있지 않으면 코드가 이미 멈췄어야 한다

## 2. 규칙 게이트

| 규칙 | 근거 | 위반 시 |
|---|---|---|
| 참조 표준과 같은 기반 타입·어노테이션·필드 순서를 쓴다 | 참조 표준 엔티티 | 무효 |
| PK·테넌트·삭제 표시·감사 필드는 **스펙에 없어도** 참조 표준대로 둔다 | 참조 표준 엔티티 | 무효 |
| 상태·코드 값은 참조 표준의 enum 위치·명명·저장 방식을 따른다 | 참조 표준 `cd/` | 무효 |
| 스펙에 없는 필드를 추가하지 않는다 | 스펙 | 무효 |
| 다른 도메인의 엔티티를 직접 참조하지 않는다 — 참조 표준이 하는 방식(식별자 보유 등)을 따른다 | 참조 표준 | 무효 |
| 판단이 필요했던 지점은 `note` 로 남긴다 | — | 무효 |

## 3. 작업 — 스켈레톤

1. 참조 표준 엔티티를 열어 **골격**(클래스 선언·기반 타입·어노테이션·필드 블록 순서)을 그대로 가져온다
2. 필드 블록만 스펙의 데이터 정의로 바꾼다. 타입 매핑은 참조 표준에 같은 타입이 있으면 그것을 따른다
3. 상태·코드 값이 있으면 참조 표준 `cd/` 의 enum 하나를 골라 같은 모양으로 만든다
4. 참조 표준에 있는데 스펙이 말하지 않는 것(감사 필드 등)은 **그대로 둔다** — 그것이 컨벤션이다
5. 스펙에 있는데 참조 표준에 대응이 없는 것은 만들지 말고 `ask`

## 4. 자가검증 체크리스트

- [ ] 만든 파일이 계획의 목록과 정확히 같은가 (더도 덜도 아닌가)
- [ ] 참조 표준 엔티티와 나란히 놓았을 때 **필드 블록 말고 다른 곳**이 다른가 — 다르면 이유가 `note` 에 있는가
- [ ] 스펙의 모든 필드가 들어갔고, 스펙에 없는 필드는 없는가
- [ ] 상태 enum 의 값이 스펙의 상태 목록과 같은가
- [ ] 다른 계층 디렉토리에 파일을 만들지 않았는가

## 5. 산출물 → 다음 단계 입력

- **산출물**: 엔티티 · enum
- **[02] 입력**: 엔티티의 식별자 타입과 필드 이름 — Repository 의 조회 메서드 이름이 여기서 나온다
