# 보존한 호스트 측정

이 문서는 새 코드로 재실행하지 않은 실제 호스트·프로젝트 사본 측정의 유효 범위다. 최신 자동 시험과 현재 수정의 한계는 [호스트 흐름 검증](2026-11-03-host-flow-validation.md)을 따른다. 원본 [집계 자료](evidence/2026-11-01-validation.json)와 [재현 기준선](evidence/2026-10-29-repro-baseline.json)은 보존한다.

## 실제로 확인한 범위

측정 환경은 Windows 11, Node 24.19.0, PowerShell 5.1.26100이다. 버전이 다른 호스트나 현재 코드로 결과를 확대하지 않는다. 승인 응답은 평가 fixture 또는 master 위임 판단이며 사람의 승인 검증이 아니다.

| 측정 조건 | 확인한 동작 | 미확인·제한 |
|---|---|---|
| Claude Code 2.1.312, sonnet, print(`-p`) 전체 흐름·대화형 CLI·관리 실행 | 담당 완료 알림이 메인의 새 턴을 열어 다음 명령으로 이어졌다. 중복 완료 알림은 다음 행동을 반복하지 않았다. | 실행마다 도달 단계가 다르다. 관리 실행에는 fixture 원장 오류·test 실패 중단도 포함돼 모두 전체 성공으로 합치지 않는다. 현재의 전문 표시 검사·권한 안내는 이 측정에 없다. |
| codex-cli 0.166.0 exec, 분석~영향도 | 메인이 담당을 기다려 다음 명령을 실행했다. | 전체 흐름·대화형 UI·최종 반영 권한 검증이 아니다. |
| Claude Code 2.1.314, sonnet, 완료 hook 되돌림 | 다른 배정의 결과 포인터가 exit 2로 같은 담당에게 전달돼 바른 포인터로 완료됐다. 전달하지 않은 모의 실행에서는 메인이 같은 담당을 재개했다. | 취소 후 재배정하는 회수는 실제 모델이 선택하지 않아 미확인이다. |
| Claude Code 2.1.316, 적용 릴리스의 임시 프로젝트 사본 | 적용 릴리스로 상태를 읽었고 분석 담당 완료 뒤 다음 명령을 실행했다. | 실제 사용자 프로젝트는 읽기만 했다. 현재 상태 형식의 적용을 확인한 측정이 아니다. |
| 스트리밍 입력·SubagentStop asyncRewake | hook exit 2 뒤 쉬던 메인의 새 턴이 열리는 호스트 기능을 확인했다. | 제품 Stop 차단·wake-event가 실제 턴을 잇는 장면은 관찰하지 않았다. 완료 알림이 먼저 턴을 열었다. |

프로젝트 4개 사본의 적용 검사는 진행 중·접수 중이면 예약하고 준비된 프로젝트면 적용하며 사용자 파일·HEAD·브랜치를 보존하는 범위를 다뤘다. 사용량 구간·같은 ID 후속·답 이어받기는 모의 반영/확정을 포함한다. 현재 상태 형식·읽기 계약은 코드와 흐름도를 따른다.

## 재현 기준선

원본 기준선은 `scripts/repro-baseline.cjs --repeat 3`의 결정적 fixture 결과다. 지금 코드는 같은 명령 뒤 `--compare doc/reviews/evidence/2026-10-29-repro-baseline.json <결과.json>`으로 비교한다. fixture 해시가 다르면 스크립트가 알린다. 가짜 호스트의 시간은 실제 호스트 지연으로 해석하지 않는다. 비교 대상은 Stop 차단·사람 입력 필요 여부·구간 분류이며 현재 동작은 `reproScenarios.test.ts`가 고정한다.

## 계속 남는 한계

- 테스트 수정 창을 실제 호스트에서 여는지, 담당이 단언을 약화하지 않는지 확인하지 않았다. 기계 검사는 TC 인식·건너뛰기 표지·파일 존재 등이고 단언의 충분성은 리뷰 판단이다.
- critic의 지적 수준·재검토 안내가 실제 재작성 수를 줄이는지는 미측정이다.
- 외부 계약 재생은 기준 커밋 원문과 결정적 판정이다. 사용자에게 채택 알림을 전하고 pending 의존 대기를 지키는 모델 동작은 미확인이다. 요구 연결의 의미 정확성은 기계 검사만으로 보장하지 않는다.
- macOS·Linux와 위 버전 밖 호스트 동작은 이 측정으로 입증하지 않는다.
