# 호스트 흐름 검증

Windows, Node 24.19.0, PowerShell에서 현재 구현의 자동 회귀와 제공된 호스트 증거를 대조했다. 실제 모델을 새로 실행하거나 master-agent 저장소와 전체 통합을 검증한 결과는 아니다. 최신 전체 시험 결과·실행 조건은 [회차 커밋 합치기 검증](2026-11-03-cycle-squash-validation.md)에 있다.

## 동의·호스트 흐름

| 항목 | 현재 동작 | 검증·남은 한계 |
|---|---|---|
| 동의 전문과 Claude 기록 시점 | CLI가 `summary`에 파일 링크를 넣고, Pre는 원래 `toolInput` 결속을 검사하며 Post는 질문 이전 전문을 확인한 뒤 승인 응답을 기록한다. 전문·질문 경계가 없으면 적용하지 않고 새 질문으로 확인한다. 보류·수정 요청·빈 응답은 재질문으로 바꾸지 않는다. | `consentPresentation`은 Pre 때 빈 기록→같은 메시지의 전문·호출 기록→Post 승인과 누락·질문 뒤 출력·다른 세션·도구 결과·thinking 거부를 검사한다. 제공된 Claude 기록에서 같은 메시지의 글이 Pre 뒤에 기록되는 조건을 확인했다. 현재 Post hook의 실제 UI·기록 반영 순서는 새 호스트에서 재검증하지 않았다. |
| Codex 전체 흐름 평가 | `pendingBaselineFiles`로 준비 파일을 수집하고 두 턴 연속 진척이 없으면 중단한다. workspace-write/never에는 작업 시작·통합 Git의 권한 응답 경로가 없어 호스트 호출 전에 지원 불가로 종료한다. | `evaluationDriver`는 준비 파일·진척·조기 종료를 확인한다. fixture의 준비 커밋·반영은 사람 승인이 아니다. 실제 호스트의 Git은 호스트 권한 경로가 맡는다. 모델의 한국어 응답 준수는 이 시험으로 검증하지 않는다. |
| Claude 명령 실행 권한 | 설치 결과·설치 문서·doctor에 project/local 규칙과 실효 권한 확인을 안내한다. 기존 설정을 보존하고 허용 규칙을 자동 추가하지 않는다. | `claudePermissions`·평가 설정 검사가 보존·setting-sources·allowedTools를 확인한다. 관찰된 17회·9종은 project만 읽은 조건의 결과다. 모든 신규 사용자에게 일반화하거나 권한 질문이 줄었다고 주장하지 않는다. |
| 계획 TC | AC·TC·배정 점검은 구체적 입력·호출·기대값·오류를 검증하며, 전체 실행은 절차·preserve로 둔다. | `resultContracts`는 구체적 TC·다중 AC·실행기 종료 코드 검증을 통과시키고 전체 테스트 통과 자체의 TC는 반려한다. 계획 반박 검토(critic)는 별도로 수행한다. 제공된 단일 Claude 실행의 재작성 감소는 일반적 모델 준수 증명이 아니다. |
| Codex 동의 후속 처리 | `pending`은 `confirm`으로 남은 질문을 표시하고 `approved`에서만 `finish`로 적용한다. | `choiceServer`·`templateText`와 제공된 Codex 화면에서 승인 전 `finish` 생략을 확인했다. 최종 Git 권한 요청은 유지한다. 통합 검증 권한 문제와 구분한다. |
| 호출 표식·원문 | 독립 첫 줄 호출 표식은 요구 추적에서 제외하고, 한 줄 요청의 실제 선두 토큰은 INVOCATION으로 명시한다. 원문과 뒤의 업무 문자열은 그대로 둔다. | `intakeInvocation`·`request`는 두 호스트 표식·인용·반복 문자열·실제 제출/확정 보존을 검사한다. sourceMap이 정확히 하나 줄어든다고 주장하지 않는다. |
| Codex 관리 실행의 통합 권한 | 추가 인자 없는 `code-agent integrate`와 지원하는 단순 셸 래퍼를 단건 권한 경로로 처리한다. | `codexPermissions`는 미응답·업무 승인으로 실행되지 않음, 서명된 단건 응답, 중복 전달 거부, 실제 로컬 RPC 뒤 fixture Git 쓰기를 확인한다. 가짜 app-server 검사이며 실제 Codex·master-agent 전체 통합 성공 증거가 아니다. |

`Invalid tool parameters`는 제공된 화면에서 거부 뒤 원래 toolInput 재호출로 회복했다. 거부된 원시 인자는 없어 필드별 원인은 확정하지 않는다. 질문을 재작성한 입력을 거부하는 회귀 시험은 유지한다. 호스트 스키마에서 거절된 호출은 hook에 도달하지 않을 수 있으므로 모든 도구 입력 오류가 해결됐다는 뜻은 아니다.

## 실행 상태·검증 근거

| 항목 | 현재 동작 | 검증·남은 한계 |
|---|---|---|
| Stop 이어가기의 세션 | 완료 `session`과 현재 `session_id`가 일치할 때만 Stop·깨우기로 잇는다. | `agentContinuation`·`wakeHook`에서 원래 세션은 한 번 이어가고 다른 세션·세션 없는 완료는 통과한다. 실제 asyncRewake 개입은 미확인이다. |
| `master call` 타임라인 | 외부 제어 조회는 CLI 사건 기록에서 제외하며, 저장된 조회 사건도 집계에서 제외한다. | `timeline`은 실제 CLI 반복 호출 후 원본 로그 불변과 조회 사건이 있는 대기 구간을 확인한다. 다른 명령·도구 호출의 측정은 유지한다. |
| 테스트 수정 검사·반영 요약 | 조건부 비활성화 표지를 검사하고 흔한 주석·문자열을 단언 수에서 제외한다. 원인·근거·TC·파일·단언 수를 리뷰·반영 보고서와 동의 전문에 싣는다. | `testRepair`가 조건부 비활성화 증가 거부·주석 제외·정상 수정·리뷰와 반영 렌더를 확인한다. 어휘 검사는 모든 언어 문법·동적 skip·단언 의미를 판정하지 못하므로 실제 실행과 독립 검토를 유지한다. |
| 검증 중 판정 기록 보호 | 리뷰·계획·승인 원장, 현재·보관 커서, 요구 개정, 실행 회차, 답 원장을 보호한다. 바뀐 기록은 실행 전 바이트로 복구하고 새 기록은 지운 뒤 실행을 증거로 받지 않는다. | `validationStateGuard`는 실제 검증 자식이 기록을 변조·생성하는 사례를 확인한다. 보호 목록 밖 동의·티켓·임대 등 전체 파일 시스템을 격리하는 기능은 아니다. |
| 계약 문맥 | `section`을 생략한 자동 범위는 가장 가까운 제목의 직접 본문과 상위 제목이며 제목 앞은 문단이다. 중복 줄은 고유한 `section`을 요구한다. 사본 버전 3·상태 형식 세대 24를 사용한다. | `dependencyContracts`·`contractAdoption`은 같은 보안 문장 이동, 범위 밖 변경, 중복 문장 거부, 버전 2 사본의 원래 무결성 확인과 문맥 복구를 검사한다. 의미 추론 대신 문서 구조에 묶으며, 변경된 범위에 의존한 기존 승인은 다시 확인할 수 있다. |
| 해결된 동의의 대기 시간 | 같은 작업·동작의 준비 완료·요구·계획 결정과 동의 폐기·취소에서 해당 대기를 닫는다. | `timeline`에서 9초에 해결한 대기가 463초까지 늘지 않는 사례와 다른 동의 구간 분리를 확인한다. 측정 종료는 승인 생성이 아니다. |
| 종료·재시작의 완료 장부 | `abort`와 새 `start`에서 해당 작업의 실행·완료를 비운다. | `agentContinuation`은 abort·같은 ID 재시작·이전 장부 유입을 확인한다. 작업 문서·승인 이력은 보존한다. |
| Windows 잠금 조회 | 한 번 확인한 같은 주인의 OS 시작 식별을 한 대기 안에서 재사용하고 회수 직전에 새로 대조한다. | `lock`은 조회 호출 수·PID 재사용 회수의 재확인을 검사한다. 새 CLI 프로세스의 최초 OS 조회와 새 주인 확인은 유지한다. 실제 전체 흐름의 속도 개선을 측정하지 않았다. |
| 평가 보고서 경로 | 실행·재개·재검사·집계가 [공통 보고서 경로](README.md)를 사용한다. | `evaluationDriver`는 Git 무시 여부·재개 경로·파일명 경계를 확인한다. 기존 공개 증거와 원본 임시 증거는 수정하지 않는다. |

## 증거와 미확인 범위

제공된 비공개 Claude·Codex 화면, 입력·대화 기록, 평가 결과, master 보고서를 읽기만 했다. 원본 증거와 실행 저장소는 보존했고 자동 회귀는 별도 임시 저장소를 사용했다. 비공개 증거는 저장소에 포함되지 않아 공개 문서만으로 원본 대조를 재현할 수 없다. 원본 대화형 선택도 평가자의 선택이며 실제 업무 승인과 구분한다.

현재 코드의 실제 UI 전문·링크 렌더링, Post hook 기록 시점, 모델의 지침 준수·언어·권한 질문 횟수, Codex 전체 흐름과 최종 권한 요청 수, Claude 깨우기 hook의 실제 개입, Codex TUI 경고 내용, macOS·Linux는 재검증하지 않았다. 합성 대화·MCP·RPC fixture는 사람 승인이나 실제 UI 증거가 아니다. [버전별 호스트 실측](2026-11-01-validation.md)의 버전·조건과 현재 코드를 구분한다.
