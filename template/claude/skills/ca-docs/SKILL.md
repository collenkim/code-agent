너는 **메인 에이전트**다. 문서만 쓴다 — 문서 작성 세션 동안 hook 이 코드 쓰기를 막는다.
`code-agent` 명령이 거부하면 사유를 그대로 전하고 멈춘다. 인자가 있으면 그 문서만 다룬다.

## 0. 점검

Bash: `code-agent docs`
- 모두 확정됐으면 그렇게 알리고 끝낸다.
- 섹션은 다 찼고 확정만 남았으면(`사람의 확정이 없습니다` · `확정 뒤 내용이 바뀌었습니다`) 확정 안내(7번)만 하고 끝낸다.

Bash: `code-agent docs begin`

## 1. 경로 고르기 — 문서마다

- **파일이 없으면** 사용자에게 묻는다: 역공학(코드가 있으면 권장) / 사용자 입력 / 기존 문서 연결.
- **파일은 있는데 섹션이 비었으면** 빠진 섹션만 채운다 — 코드가 있으면 역공학으로 먼저, 남은 것은 사용자 입력.
- 사용자가 요청에 이미 답이나 경로를 적었으면 다시 묻지 않고 그것을 쓴다.

## 2. 역공학

1. Bash: `code-agent survey` — 빌드 파일·언어·구조·계층 후보·표본 경로. 저장소를 직접 훑지 말고 이것에서 출발한다.
2. 파일이 없으면 Bash: `code-agent docs skeleton <종류>` — 써야 할 섹션과 안내.
3. `ca-surveyor` 를 **한 메시지에서 병렬로** 부른다. 각자에게 survey 출력, 맡은 섹션의 안내, 읽을 표본을 넘긴다.
   - 아키텍처: ① 기술 스택(빌드 파일) ② 모듈/패키지 구조 · 계층과 책임 · 의존 방향 ③ 공통 모듈 · 주요 결정
   - 컨벤션: ④ 명명 · 계층별 규칙 ⑤ 예외 처리 · 테스트 규칙
4. `ca-writer` 에게 뼈대(또는 지금 문서)와 surveyor 결과를 넘겨 문서 경로에 쓰게 한다.
   코드로 알 수 없는 것(이유·방향·정책)은 `확인 필요` 로 남긴다. 내용이 하나도 없는 필수 섹션은 통과하지 못하고, 내용 옆의 `확인 필요` 는 미결로 세어 확정하는 사람에게 보인다.

## 3. 사용자 입력

1. Bash: `code-agent docs interview <종류>` (일부 섹션만이면 `--sections stack,decisions`) — 섹션별로 물을 것.
2. 섹션별로 사용자에게 묻는다. 선택지가 있으면 선택지로, 결정이 필요한 곳은 각 선택지의 트레이드오프를 한 줄씩 붙인다.
   한 번에 최대 4개. 역공학으로 이미 채운 것은 묻지 않는다.
3. 고르는 것은 사용자다. 모른다고 하면 `확인 필요` 로 남긴다 — 대신 정하지 않는다.
4. 답을 해당 섹션에 쓴다. 출처는 `(사용자 답)` 으로 단다.

## 4. 기존 문서 연결

경로를 받아 Bash: `code-agent docs link <종류> <경로...>` — 빠진 섹션이 나오면 2·3 으로 채운다.

## 5. 마무리

1. Bash: `code-agent docs` — 필수 섹션이 전부 ✓ 인지 본다. ✗ 가 남으면 3 으로.
2. Bash: `code-agent docs end`
3. 사용자에게 알린다: **문서를 직접 읽고 확인한 뒤, 별도 터미널에서**
   `code-agent confirm doc architecture` · `code-agent confirm doc conventions` —
   확정해야 작업(`/ca-feature` 등)이 시작된다. 확정한 문서는 커밋해 팀과 공유한다.
