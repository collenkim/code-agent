# 현재 검증 상태

검증 환경은 Windows 11, Node 24.19.0, PowerShell 5.1.26100이다. 실제 호스트는 Claude Code 2.1.312, codex-cli 0.166.0이다. [집계 자료](evidence/2026-10-30-validation.json)는 실행별 결과이며 서로 다른 시험 수를 합산하지 않는다. 재현 기준선은 [재현 기준선 자료](evidence/2026-10-29-repro-baseline.json)에 있다.

## 자동 시험

`npm test`(`tsc` → 옛 `dist/test` 산출물 정리 → `node --test --test-concurrency=4`)로 전체 시험을 한 번 실행했다. 1871건 중 1867 통과·4 생략(플랫폼 조건)·0 실패이고 벽시계는 531초(시험 실행 530.1초)다. 가장 긴 묶음은 `검증 workflow 노드` 73.8초다.

- `planningBudgetEpoch`는 계획 배정 예산 구간을 고정한다. 같은 구간에서는 정상 완료까지 세어 6회에서 막는다. 확정한 요구 항목이 바뀌거나 새 실행 회차를 열면 새 구간이라 과거 성공 때문에 허용을 묻지 않는다 — 같은 ID 에서 구간마다 6회를 다 쓰는 정상 개정을 세 번 거듭해도 사람 허용 없이 진행하고, 지난 구간의 배정은 `earlier`(6·13·20)로만 보인다. 준비 반복·작업 정의·입력 변경·확정하지 않은 지시서 변경은 구간을 바꾸지 않는다(확정하지 않은 변경은 준비·배정도 멈춘다). 막힌 조사 작업을 새 ID 로 다시 준비하면 새 작업은 배정되지만 종합은 막힌 작업의 완료를 기다리고, 선행에서 막힌 작업을 뺄 수 없다. 같은 입력의 실패는 구간과 무관하게 3회에서 막는다. 구간 기록이 없는 기록은 이행 시각부터 지금 구간으로 이어받아 같은 사용량을 보인다.
- `wakeHook`·`agentContinuation`은 담당 완료 뒤 끝나는 턴의 1회 이어가기와 처리하지 않은 완료가 남은 채 쉬는 메인의 1회 깨우기를 본다. 같은 완료의 재알림·동시 hook·재시작·이전 개정의 늦은 완료에서도 효과는 한 번이고, 사람 판단 자리에서는 멈춘다.
- `reproScenarios`의 `completionStall`은 격리 가짜 호스트에서 완료 뒤 사람 입력 없이 다음 행동까지 20초(`CONTINUATION_BOUND_MS`) 안에 이어지는 것을 고정한다. 이 상한은 자식 프로세스 기동을 포함한 시험 환경의 값이며 실제 호스트 지연의 기준이 아니다.

- 다섯 실행 모두 Stop 의 이어가기 차단과 깨우기는 필요하지 않았다(차단 0·깨움 0). 이 두 경로는 완료 알림이 새 턴을 열지 않는 자리 — 2.1.306 세션 기록에서 인계 메시지를 받은 메인이 턴을 끝낸 뒤 온 완료 알림이 새 턴을 열지 않았다 — 를 위한 것이다. 근거는 격리 시험과 아래 깨우기 기반 실측이다.
- 관리 실행에서 같은 담당의 완료 알림이 다시 온 경우(A 8건, B 6건)는 이미 처리한 완료로 기록됐고 다음 행동을 다시 실행하지 않았다.

### 쉬는 메인 깨우기의 기반

Claude Code 2.1.312 바이너리에서 hook 옵션 `asyncRewake`는 "백그라운드로 돌다가 exit 2 면 모델을 깨운다"이다. asyncRewake hook 은 대화형이거나 스트리밍 입력일 때만 백그라운드로 돌고, 그 밖의 `-p`에서는 동기로 돈다. exit 2 의 stderr 는 다음 메시지로 큐에 들어간다.

임시 폴더의 프로젝트 hook 으로 스트리밍 입력 모드(`-p --input-format stream-json`, haiku, 비용 약 $0.013)를 실행했다. SubagentStop 에 15초 뒤 exit 2 로 끝나는 asyncRewake hook 을 달았다. hook 은 담당 종료를 막지 않았고, 메인이 쉬는 동안 exit 2 로 끝난 뒤 26ms 만에 메인의 새 턴이 열렸다. 첫 메시지 뒤 사용자 메시지는 없다.

- SubagentStop 입력에는 `transcript_path`·`agent_id`·`agent_type`·`agent_transcript_path`·`last_assistant_message`가 있고, 메인 대화 기록에는 `"version":"2.1.312"`가 있다. hook 환경은 `-p`·스트리밍 입력에서 `CLAUDE_CODE_ENTRYPOINT=sdk-cli`, 대화형 세션에서 `cli`다.
- `-p`와 스트리밍 입력을 hook 환경으로 가를 표지가 없다. 그래서 `wake-event`는 대화형 CLI(`cli`)에서만 기다리고 그 밖에서는 바로 0 으로 끝낸다.
- `wake-event`가 대화형 CLI 에서 실제로 메인을 깨우는 모습은 관찰하지 않았다 — 위 대화형 실행에서는 완료 알림이 새 턴을 열어 깨울 자리가 생기지 않았다.

## 상태 형식 세대

상태 형식 세대는 20이다. 계획 사람 허용의 범위는 예산 구간을 담고(`planning:<작업>@<구간>`·`planning:<작업>:<입력 해시>@<구간>`), 계획 기록의 `retry`는 지금 구간 `epoch`와 지난 구간 `epochs`를 가진다. 구간을 모르는 릴리스(세대 19 이하)는 이 프로젝트에 적용되지 않는다 — 구간 표기가 붙은 허용을 읽지 못하고 구간 밖 배정까지 세기 때문이다. 세대 19 의 기록은 첫 기록 때 지금 구간을 이행 시각(`retry.since`)부터 이어받아(`migrated`) 이행 전과 같은 사용량을 보이고, 구간 표기 없는 이전 허용은 그 이행 구간에서만 쓰인다. 담당 실행 장부(`agent-runs.json`)는 게이트·배정·승인 판정에 쓰지 않는 이어가기 안내용이라 세대에 넣지 않는다.

## 배포와 검증 한계

- 패키지 dry-run은 223개 파일이다. `dist/agent/agentHook.js`·`dist/agent/agentRuns.js`·`dist/agent/wakeHook.js`를 포함하고 `dist/test`는 포함하지 않는다. 재현 시나리오와 기준선 스크립트는 이 소스 저장소에서만 실행된다.
- 예산 구간은 계획 배정(작업 총 배정)에만 있다. 검증·리뷰 회차 한도와 교차 지점 한도는 그 회차·지점에서 센다. 비용·시간 안전장치는 따로 두지 않았다 — 작업 총 배정·같은 입력 실패·동시 실행 한도, 시작·실행 기한(고아), 반복 전달 실패 차단이 그 몫이다. 예산 구간은 결정적 판정이라 실제 호스트로 따로 실행하지 않았다.
- 새 ID 로 준비한 계획 작업은 제 예산을 받는다(계획 작업 수 상한 100개). 막힌 작업은 지워지지 않고 뒤 역할의 선행으로 남아 새 ID 로 우회하지 못한다.
- master 위임 판단으로 요구를 확정하면 구간 전환 수는 사람이 준 권한의 사용 한도·만료가 묶는다. 위임 확정이 여는 구간 전환은 따로 시험하지 않았다 — 위임 범위·사용 한도와 예산 구간은 각자의 시험이 본다.
- 진행 중 대상(`target`) 변경은 요구 변경으로 받지 않는다. 다른 대상이면 사람이 그 대상의 ID 로 접수한다.
- 분석으로 되감은 뒤 같은 회차의 구현 Task 통과 판정은 기준 커밋과 다른 파일로 본다. 같은 회차에서 이미 고친 Task 파일은 다시 고치지 않아도 그 판정을 지난다 — 새 개정의 반영은 계획 재승인과 검증·리뷰 재실행이 확인한다.
- 이전 회차는 작업 브랜치(없으면 기준 브랜치)의 이력에서 찾는다. 반영 커밋을 기준 브랜치에 넣지 않은 채 작업 브랜치를 지웠으면 첫 회차로 시작한다.
- 쉬는 메인 깨우기는 Claude 대화형 CLI 에서 확인한 호스트 버전(2.1.312 이상)과 asyncRewake 설치가 있을 때만 동작한다. 그 밖에서 완료 알림이 새 턴을 열지 않으면 다음 세션 시작 요약이 처리하지 않은 완료를 알린다. Codex 에는 깨우기 hook 이 없다.
- Stop 의 이어가기 차단과 깨우기가 실제 호스트의 턴을 잇는 모습은 관찰하지 않았다 — 위 실행들에서는 그 자리가 생기지 않았다. Codex 의 완료 알림은 관측하지 않는다.
- 테스트 담당이 쓴 테스트가 동결 뒤 테스트 자체의 결함으로 실패하면 세션은 테스트를 고치지 않고 사람 판단에서 멈춘다(관리 실행 B).
- 백그라운드로 돌린 긴 검증 명령(Bash `run_in_background`)의 완료는 담당 실행 장부에 남지 않는다. 그래서 이어가기 대상이 아니다.
- 자동 회귀를 실제 사람 승인·사용자 사용성의 증거로 해석하지 않는다. 실제 호스트 동작 설명에 붙은 버전은 관찰 조건이며 지원 최소 버전을 뜻하지 않는다.
