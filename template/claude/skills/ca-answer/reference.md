# ca-answer 참고 — 질문·대기 전과 CLI·hook 차단 때 읽는다

## 단계별 선택

모든 단계에서 **새 사용자 결정이 있을 때만** 질문한다. 이미 준 지시·답·설정으로 정해진 일과 허용된 조회·정상 진행은 계속한다. 아래의 후보를 기계적으로 전부 묻지 않는다. 작업 중 원인 조사·기술 판단은 에이전트가 수행하며 사용자에게 원인을 맞히게 하지 않는다.

대기 전에 다음을 확인한다: 결정할 내용과 현재 제안·근거를 제시했는가 → 가능한 선택지와 결과를 붙였는가 → 현재 호스트의 질문 도구를 실제 호출했는가. 도구가 없거나 표시가 실패하면 설치·hook·호스트 지원을 확인하고 복구 후 같은 질문을 UI로 표시한다. `둘 다 기본안 적용` 같은 문구를 그대로 입력하라고 요구하지 않는다. 한 질문에는 한 결정만 넣고 독립 질문은 한 호출에 묶는다. 추천을 응답으로 취급하지 않는다. 사용자 취소·보류·정상 표시 후 대기 중인 같은 질문은 반복하지 않는다.

**업무 질문**은 방향·기준·정보를 받는다. **동의**는 확정·승인·중단·반영이며 기존 consent 질문·응답 형식을 그대로 쓴다. Codex 동의는 `code_agent.confirm` 폼을 쓰며, `consent respond`는 사용자가 요청한 호환 경로로만 쓴다. 업무 질문에 이 형식을 요구하거나 업무 답으로 동의를 대체하지 않는다.

선택지 없이 특정 문구 입력만 요청한 안내는 질문 제시 완료로 보지 않는다. 재개 시 그 미응답을 실제 선택지로 한 번 제시하며, 이후에는 같은 질문을 반복하지 않는다.

| 단계·진입 | 새 결정이 필요한 조건 | 선택 후보·응답 후 연결 |
|---|---|---|
| 준비: ca-adopt·ca-docs | 작성 방식·정책 기준이 미정 | 코드 기준 / 사용자 기준 / 기존 문서. 기존 방식을 받았으면 생략. 테스트·품질 기준은 제안과 근거를 보여 준 뒤 각각 제안 기준 사용 / 항목 수정 / 보류로 묻고 초안 반영 후 setup·docs 동의 |
| 접수: ca-request·ca-feature·ca-fix·ca-refactor | 대상·수정 범위·보존 조건·준비 질문이 미정 | 근거 있는 대상·범위 후보 / 직접 입력 / 보류. 같은 ID의 새 로그는 원문 보존 후 미응답 준비 질문부터 도구로 재개. 초안 확정은 request 동의 |
| 사전 판별: ca-fix triage | 로그·버전 근거 부족, Jira 연결 정보 필요 | 추가 근거 제공 / 현재 조사 보류. 코드 필요 여부는 에이전트가 근거로 판별. Jira는 기존 티켓 정보 / 사용자 생성 후 연결 / 보류. 중복이면 새 작업 선택을 묻지 않음 |
| analysis | 요구·AC·업무 규칙 충돌 또는 필수 답 부족 | 근거 있는 동작 후보 / 직접 입력 / 보류. 답을 해당 Q에 기록하고 담당에 전달 |
| impact | 영향 범위·호환성·외부 연동 선택이 미정 | 기존 호환 유지 / 변경 범위 제안 / 보류 중 실제 가능한 것. 범위 변경은 재확정·재계획 |
| design | 사용자가 정해야 하는 권한·데이터·비용 선택 | 차이와 영향을 설명한 설계 후보 / 보류. 일반 기술 세부는 에이전트 판단, 답은 설계 담당에 전달 |
| plan | 계획 검토 지적 중 사용자 결정, 승인 필요 | 범위 유지 수정 / 범위 재조정 / 보류. 승인 준비가 되면 plan 동의를 바로 제시하며 승인할지 묻는 예비 질문을 추가하지 않음 |
| implement | 담당 질문·계획 밖 변경·재현 한도 | 범위 내 해결 / 재계획 / 보류. 실제 안내가 허용할 때만 repro-log·judgment 동의. 답 후 같은 Task 재개 |
| check | 수정·진단으로 해결할 수 없는 범위·환경·한도 | 허용된 환경 조치 / 재계획 / 보류. 추가 허용은 CLI가 허용한 judgment 동의만, 한도 재시도 자동 실행 금지 |
| test | 테스트 전제 정보·결과 판정에 필요한 외부 사실 부족 | 필요한 정보 제공 / 환경 조치 / 보류. 러너·어댑터는 기존 설정 사용. 검증 생략·미실행 통과 선택 없음 |
| review | 계획 밖 지적·의견 충돌·교차 실행 복구 결정 | 수정 / 재계획 / 보류. 기각·교차 중지는 실제 허용 조건에서만 judgment 동의 |
| integrate | 통합 환경 조치·범위 변경 필요 | 환경 조치 후 허용된 재실행 / 재계획 / 보류. 코드 결함은 수정 루프, 정상 완료 시 반영으로 진행 |
| deliver | 지식 반영 항목·최종 반영 승인 | deliver 동의가 반환한 항목 선택과 최종 승인·보류를 그대로 제시. 임의 승인 문구로 대체하지 않음 |
| 재개·조회: ca-next·ca-status·ca-answer | 미응답·다른 작업·다른 세션 충돌 | 미응답 Q의 선택지를 재개하거나 기존 작업 계속 / 정식 인계 / 보류. 단순 조회 요청이면 현황만 보고하고 개발을 시작하지 않음 |

## 차단 복구

CLI·hook 거부는 그 동작을 중지한다는 뜻이며, 항상 사용자 선택이 필요하다는 뜻은 아니다. 메인은 아래 기준으로 계속할 일과 물을 일을 구분한다. 담당 에이전트는 거부를 메인에 보고하며 직접 동의를 받거나 우회하지 않는다.

1. 거부 원문·직전 상태·이미 받은 사용자 지시부터 확인한다. 허용된 `code-agent help`·`status`·`doctor`·`read`로 필요한 사용법·상태를 확인하는 일은 별도 동의 없이 수행한다. 예: `planning --help`가 거부되면 `code-agent help planning`(전체는 `code-agent help`)으로 사용법을 확인한다. 같은 실패 명령 반복·셸 래퍼·다른 도구로 금지된 동작을 실행하는 것은 우회이므로 하지 않는다. 허용된 조회도 거부되면 반복하지 않는다.
2. 이미 선택한 방향과 승인 범위 안에서 허용된 다음 행동이 명확하면 짧게 알리고 계속한다. `ca-adopt 소스·설정 기준으로 작성`처럼 받은 방식은 다시 묻지 않는다. 권한·범위·정책 변경, 필수 정보 부족, 여러 복구 방향 중 미정인 결정이 있을 때만 현재 가능한 행동 2~3개를 공통 질문 도구로 실제 제시한다. 사유·영향과 보류를 포함하며 **새 결정에 의존하는 동작만** 응답 전 실행하지 않는다. 다음 표는 자동 질문 목록이 아닌 후보이며, 불가능한 행동은 넣지 않는다. 사용자 취소·보류·승인 거절은 되묻지 않는다.

| 원인 | 선택 후보·연결 |
|---|---|
| 공통 문서·설정 누락 | 코드·기존 자료로 준비 / 기존 문서 경로를 받아 연결 / 보류. 설정은 ca-adopt, 문서는 ca-docs. 내용이 있으나 미확정이면 작성 대신 문서 확정 절차로 연결 |
| 작업 중 공통 문서 보완 필요 | 작업 보존 후 문서 보완 / 보류. 아래 작업 중 보완 순서를 설명하고 확인 |
| 현재 단계와 다른 명령·진행 중인 다른 작업 | 현재 작업·단계 재개 / 보류. 새 작업이 필요하면 기존 작업 처리 방향을 확인하고 필요한 종료 동의를 따로 받음 |
| 요구·계획 미확정 또는 승인 무효 | 현재 안 확인·승인 절차 / 내용 수정·재계획 / 보류. 확정되지 않은 상태로 실행하는 선택지는 없음 |
| 계획 범위 밖·다른 단계의 쓰기 | 현재 범위 내 해결(가능할 때만) / 범위 변경·재계획 / 보류. 단계 이동·재계획에 필요한 사용자 지시와 재승인을 따로 받음 |
| 테스트 실패·재시도 한도 | 출력이 허용하는 수정·진단 / 출력에 실제 있는 사람 판단·추가 허용 / 보류. 허용 횟수·테스트 동결·검증 생략 규칙은 바꾸지 않음 |
| 다른 세션·외부 절차와 충돌 | 기존 세션에서 계속 / 종료 확인 후 정식 인계 / 보류. 실행 중인 다른 작업을 임의 종료하지 않음 |
| 호스트 권한·설치·외부 hook 또는 원인 불명 | 읽기 전용 원인 점검 / 사용자가 권한·설정을 확인한 뒤 재개 / 보류. 외부 거부를 code-agent 승인으로 해제할 수 있다고 안내하지 않음 |

3. 선택은 복구 방향에 대한 답이다. abort·docs·setup·plan 등의 동의가 필요한 실행은 각각의 기존 동의 절차를 거친다. 권한 변경·문서 확정·승인을 일반 답변으로 대체하지 않는다. 질문 기록이 허용되지 않으면 파일을 만들지 않고 현재 대화에서 질문한다.
4. 작업 ID·종류·원문·현재 단계를 유지한다. 접수 중 문서 준비는 같은 접수로 돌아온다. **이미 시작한 작업**은 docs begin이 거부되므로 허용된 작업 폴더에 작업 ID·지시서 경로·대상·기준 브랜치·멈춘 단계를 보존하고, abort 동의를 받아 커서만 닫은 후 문서를 보완·확정한다. 기존 지시서로 start하여 분석부터 필요한 근거·계획·승인을 다시 검증한다. 원래 단계로 무조건 건너뛰거나 새 작업 ID·원문 재입력을 요구하지 않는다.
5. 선택한 복구가 끝나면 상태를 다시 확인하고 기존 작업을 자동으로 이어간다. 사용자가 ca-request·ca-fix·ca-next를 다시 입력하게 하지 않는다. 새로운 차단은 달라진 원인을 설명하고 다시 선택받는다. 같은 원인·같은 미응답에는 반복 질문하지 않는다.
