# [bootstrap 03] 공통 모듈·설정

> **선행**: [02] 스캐폴딩 실행 완료 · **다음**: [04] 선언
> **산출물**: 결정 5·6번을 코드로 옮긴 공통 모듈과 설정

## 0. 사용법

스캐폴더가 만들어 주지 않는 것만 만든다 — 아키텍처 계층의 기반이 되는 공통 타입과 설정.

**do-not-touch**: 스캐폴더가 만든 빌드 파일·엔트리포인트를 고치지 않는다. 의존성 추가가 필요하면 만들지 말고 note에 적는다.

> **참조는 `out/` 에 이미 있다.** 스캐폴더가 만든 파일들의 패키지 선언·디렉토리 규칙·코드 스타일을 그대로 따른다.

## 1. 입력 게이트

- [ ] `out/` 에 스캐폴딩 결과가 있다
- [ ] 결정 5(계층)·6(공통 규약)이 확정돼 있다
- [ ] 도메인 하나도 아직 만들지 않는다는 것을 이해했다 — 그건 seed 단계다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| 결정 6번에 적힌 것만 만든다. 없는 규약(캐시·이벤트·감사로그 등)을 추가하지 않는다 | 무효 |
| 스캐폴더가 만든 파일의 패키지·스타일을 그대로 따른다 | 무효 |
| **도메인 코드를 만들지 않는다** — Entity·Repository·Controller 등은 전부 seed 단계 | 무효 |
| 계층 이름은 결정 5번의 것을 쓴다. 다른 이름으로 바꾸지 않는다 | 무효 |
| 결정에 없어 판단이 필요했던 지점은 note에 남긴다 | 무효 |

## 3. 작업 — 결정 6번이 요구하는 것만

전형적으로 아래가 나오지만, **결정 문서에 있는 것만** 만든다.

| 결정 항목 | 나오는 것 |
|---|---|
| 감사 필드 | 공통 base 타입 (생성/수정 일시·주체) |
| soft delete | 삭제 표시 필드와 활성 조건 규약 |
| 멀티테넌시 | 테넌트 식별 필드와 주입 방식 |
| 예외 체계 | 공통 예외 타입 + 에러 코드 + 응답 변환 |
| 식별자 전략 | PK 생성 방식 |
| 인증·세션 | 보안 설정 |

## 4. 자가검증 체크리스트

- [ ] 만든 것이 전부 결정 6번의 항목으로 추적되는가
- [ ] 도메인 코드를 하나도 만들지 않았는가
- [ ] 스캐폴더가 만든 파일을 고치지 않았는가
- [ ] 패키지 선언이 결정 4번의 루트와 맞는가
- [ ] 계층 이름이 결정 5번과 같은가

## 5. 산출물 → 다음 단계 입력

- **산출물**: 공통 모듈·설정
- **[04] 입력**: 실제로 만들어진 계층 디렉토리 구조 — 매니페스트의 `stages`·`outputDirs`가 여기서 나온다
