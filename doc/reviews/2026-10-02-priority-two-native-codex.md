# 우선순위 2와 Codex 실제 연동 검증

후속 검증에서 Windows 프로젝트 신뢰 키·부모 실행 기록 문제와 파일 읽기·문서 지침 충돌을 해결했다. 수정 후 두 호스트의 실제 분석·영향도 내용 게이트 결과는 [훅 복구 이력](2026-10-02-codex-hook-recovery.md)을 따른다. 아래 기록은 당시 실패와 한계를 그대로 보존한다.

기준일: 2026-10-02. 기준 커밋: 13e5a14. 앞선 [우선순위 1 이력](2026-10-02-planning-efficiency.md)을 이어가며, 사용자가 제시한 다음 두 개선을 범위로 확정했다.

| 개선 | 적용 | 유지한 조건 |
|---|---|---|
| 독립적이고 추론 가치가 있는 작업만 위임 | 작은 기본 조사는 impact 한 담당이 조사와 02 정리를 함께 수행 | 원문 분석·설계·계획·독립 critic·사용자 승인 |
| 작업별 필요한 컨텍스트만 전달 | 직접 선행 출력·역할별 필수 문서·관련 정책을 연결하고 실행 ID만 바뀐 동일 결과를 재사용 | 선행 작업의 현재 입력·완료·근거·질문·지적·문서 변경 검사 |

## 구현과 범위

처음 자동 배정하는 영향도 단계에서 R 1~3개, 조사 대상 12파일 이하·96,000바이트 이하이면 explore와 synthesis 두 호출을 impact 한 호출로 합친다. 새 범위 입력과 크기 판정은 설치된 CLAUDE.md·AGENTS.md·doc/code-agent 단계 템플릿을 제외한다. 필요한 파일은 inputs로 직접 지정할 수 있고 호스트 자체의 지침 적용은 유지한다. 선택 기준은 구현상 시작값이며 난이도 판단이나 최적 비용 측정 결과가 아니다. 빈 저장소도 실제 조사 기록을 요구한다. 모든 R의 영향·호출자·위험은 02에 담으며 질문·차단 지적·같은 키의 사실 충돌은 그대로 막는다.

기존 작업과 명시적 분할은 유지한다. 자동 배정 전에 인자 없는 prepare를 사용하면 기존 explore → synthesis를 선택할 수 있다. 준비한 방식은 유지하며 통합 역할과 분할 역할의 중복 소유는 거부한다. 작은 기본 흐름의 역할 수는 6개에서 5개가 된다. 자동으로 단계를 건너뛰거나 메인의 자기 보고를 관찰 결과로 받지 않는다.

새 기본 작업의 contextVersion은 2다. explore·synthesis에는 아키텍처·컨벤션을 기본 제공하며 추가 정책은 명시 입력으로 연결할 수 있다. 계획에는 회귀 위험 확인용 02를 유지하고 critic은 전체 판단 문서를 받는다. 참조 문서 본문은 앞선 우선순위 1과 같이 경로·해시로 전달한다. 선행 결과 내용 해시에서 taskId·dispatchId·inputHash를 제외해 동일 내용의 재실행이 후속 재실행을 강제하지 않게 했다. 현재 배정의 식별자와 실제 시작·완료 검증은 계속 수행한다.

contextVersion 없는 기존 작업의 입력·결과 해시 계약은 유지한다. 새 작업은 호스트가 주입하는 CLAUDE.md·AGENTS.md 본문을 중복 전달하지 않아도 파일 해시로 추가·수정·삭제를 감지한다. 지침이 달라지면 이전 판단을 재사용하지 않는다. 저장 상태 버전은 1이며 새 impact 역할이 생성된 작업을 구버전으로 재개하는 것은 지원하지 않는다. Claude 템플릿에서 Codex 역할·스킬을 생성하므로 같은 통합 지침을 제공한다. 제품별 역할 모델 설정은 바꾸지 않았다.

## 실제 Codex 검사

Codex 0.160.0을 사용해 별도 임시 프로젝트에서 모델 호출·배정·훅 관찰을 검사했다. 초기 준비·요구 확정은 합성 fixture이고 실제 사람의 승인 검사가 아니다. 메인 모델 비교 옵션은 검사 전용이며 역할별 제품 기본 모델은 유지했다. 결과 원문·오류·소요 시간·로그 해시는 [검증 원자료](evidence/priority-two-native-codex-2026-10-02.json)에 보존한다.

- GPT-5.6-Luna 메인 실행에서는 하위 호출과 완료 응답이 JSON 실행 기록에 있었지만, 계획 관찰 에이전트와 훅 캡처는 0건이었다. 결과는 running에 머물렀다.
- GPT-5.5 비교도 완료 응답 이후 관찰이 없어 대기했고 180초 제한에 도달했다.
- 검사 도구의 `-c projects.<따옴표 경로>` 전달이 경로 키에 따옴표를 포함하는 문제를 발견했다. TOML 인라인 테이블로 고쳤으며 공식 설정 조회에서 경로가 제대로 전달됨을 확인했다. 수정한 기본 모델 검사도 완료 훅은 0건이었다. 따라서 이 수정만으로 훅 누락 원인을 해결했다고 판단하지 않는다.
- 최종 코드에서 메인을 GPT-6.1-Sol로 명시한 검사도 180초 제한에 도달했다. 훅 0건·관찰 에이전트 0건·계획 running이며, 해당 JSON 실행 기록만으로 역할별 모델의 실제 적용을 증명할 수 없다.
- App Server의 읽기 전용 hooks/list 조회는 프로젝트 훅 5개와 오류·경고 0건을 반환했다. 해당 조회는 사용자 설정을 포함하며 영구 신뢰하지 않은 훅은 untrusted로 보였다. 일회성 검사 플래그를 사용하는 exec와 동일한 실행 검증으로 간주하지 않는다.

검사 도구는 같은 결과 이름을 덮어쓰지 않고 새 이름을 요구한다. 훅 래퍼는 호스트가 보낸 이벤트와 어댑터 응답을 그대로 기록하며 이벤트를 합성하지 않는다. 실제 하위 도구 응답과 코드 에이전트의 수락 결과를 분리해 기록한다. 제한 시간 종료 뒤 해당 임시 프로젝트의 Codex 프로세스가 남지 않았음을 확인했다.

현재 환경의 Codex 실제 연동은 **미완료**다. 설정 파일과 합성 이벤트 검사가 통과하더라도 실계정 실행 성공을 의미하지 않는다. [공식 훅 문서](https://learn.chatgpt.com/docs/hooks)는 로컬 실행과 클라우드 조정의 지원 범위를 구분하지만, 이번 기록만으로 해당 제한이 직접 원인이라고 확정하지 않는다. 모델 목록의 v1·v2 메타데이터만으로도 원인을 단정하지 않는다. 후속 확인에는 실제 실행 환경이 전달하는 시작·완료 훅 또는 공식적으로 지원하는 관찰 경로가 필요하다. 미관찰 결과를 메인이 대신 기록해 통과시키지 않는다.

## 자동 검사와 Claude 실계정 검사

자동 검사는 양쪽 호스트에서 통합 5역할 흐름, critic 이전 제출 차단, 사용자 승인 전 전환 차단, 큰 범위의 기존 흐름, 명시 분할, 역할별 입력, 기존 해시 계약, 동일 내용 재사용과 변경 시 무효화를 포함한다.

Claude의 분석·영향도 확장 검사는 네 차례 실행했다. 첫 검사는 문서 본문의 `requirement.md` 축약 경로, 두 번째는 원문 인용의 따옴표 중복 이스케이프가 다음 단계 게이트에서 거부됐다. 세 번째는 설치 파일까지 포함해 13파일로 분류되어 기존 explore 경로를 탔고, 담당이 출력 없는 계약에 문서를 반환해 거부됐다. 이 관찰에 따라 설치 생성 파일을 새 조사 범위·크기 판정에서 제외했다. 최종 검사는 분석 완료를 관찰했지만 R 블록의 범위 제한 원문 누락을 게이트가 거부해 영향도 단계로 진입하지 못했다.

따라서 실제 Claude의 분석 훅은 확인했으나 새 통합 영향도의 실계정 완료는 확인하지 못했다. 이 검사들은 Sonnet을 명시한 비용 제한 fixture이며 제품 기본 Opus 모델의 성능 측정이 아니다. 원문 경로·인용·R 연결의 문서 오류는 JSON 형식 교정 대상과 구분한다. 기존 제품 절차에서는 피드백을 별도 입력으로 추가해 원인 작업을 재배정한다. 이번 엄격한 호스트 검사에서는 그 내용 보완을 수행하지 않았다. 실제 입력·표현·검사 지시를 보완한 각 실행을 별도 기록하며 성공 결과로 합치지 않는다.

| 검사 | 결과 | 범위 |
|---|---|---|
| 초기 계획 집중 검사 | 37개 통과·실패 0 | 최초 구현; 후속 보완 전 |
| 전체 회귀 | 716개 중 712개 통과·실패 0·생략 4 | 674,912.4891ms. 실행 말미의 설치 생성 파일 제외 보완은 아래 집중 검사로 검증 |
| 최종 계획·Codex 집중 검사 | 56개 통과·실패 0 | 106,522.865ms. 최종 범위 제외와 설치된 양쪽 템플릿 포함 |
| 호스트 지침 변경 감지 보완 | 39개 통과·실패 0 | 80,487.1042ms. 입력에서 제외한 지침도 변경 시 재사용을 막는 최종 계획 검사 |

수치는 중복 합산하지 않는다. 실제 모델 실행 실패는 자동 검사 통과와 별도로 남긴다. 최종 소스·검사 로그 해시는 원자료에 기록했으며 모든 실제 모델 실행이 같은 검사 스크립트 버전이나 같은 입력 문장으로 수행됐다는 의미는 아니다.

## 문서·정리

README·사용 가이드·설치·설계·요구사항·계획 작업·Codex 안내·이력 색인을 갱신했다. 이전 기록을 합산하거나 성공 결과로 덮어쓰지 않는다. 원문 실행 로그와 격리 프로젝트는 무시된 dist 아래 감사 자료로 유지하고, 일회성 분석 스크립트와 조회용 생성 스키마는 정리한다. 실제 비용·토큰·품질 개선 비율은 별도 반복 측정이 필요하다.
