# Windows 실행 명령의 hook 판정

UZRF-392 접수 중 `code-agent.cmd status`가 셸 허용 목록에서 거부된 사례를 확인했다. `isModelCommand`가 `code-agent ` 접두어만 인정해 npm의 Windows 실행 파일 표기를 거부했다.

`decide` 진입에서 명령 맨 앞의 `code-agent.cmd`만 기존 이름으로 정규화한다. 상태 조회뿐 아니라 교차 자식·읽기 전용 담당·작업 임대·동의 세션 결속·티켓 발급 전에 처리한다. 인자와 셸 연결 문자는 보존하며 경로나 래퍼를 새로 허용하지 않는다. 대상 프로젝트의 hook 설정을 완화할 필요는 없다.

회귀 시험은 두 셸의 조회, 직접 승인·종료 거부, 셸 연결·리다이렉트·줄바꿈 거부, PowerShell 평가식 거부, 읽기 전용 역할, 다른 세션의 임대, 교차 자식, 손상된 상태의 조회, 동의 티켓과 다른 세션 적용 거부를 확인한다. 실제 cloud 프로젝트의 설치본과 UZRF-392 재개는 이 저장소의 검증 범위 밖이다.

검증: `npm.cmd run build` 통과. `hookPaths`·`consentBinding`·`hookLoad`·`docSync`·`finalReverify` 106개 통과, 실패·생략 0개(69.2초). 첫 샌드박스 실행은 Windows 사용자 정보 조회(`uv_os_get_passwd`)의 ENOMEM으로 실패해 권한 승인 후 제한 밖에서 검증했다. 전체 테스트는 이번 변경에서 다시 실행하지 않았다. [검증 기록](evidence/2026-10-12-cmd-hook.json).
