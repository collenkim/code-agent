# [spec 01] 스펙 문서 — 사람이 답한 것을 문서로 만든다

> **산출물**: `doc/spec.md` 한 장
> **다음**: 이 문서를 `bootstrap` 실행의 `--spec` 으로 넘긴다

## 0. 사용법

이 단계는 **코드도 결정도 만들지 않는다.** 사람이 답한 것을 문서 한 장으로 옮겨 적는 것이 전부다.

> **네가 아는 것으로 빈칸을 메우지 않는다.** 이 문서는 이후 모든 실행의 근거가 된다 —
> 여기에 지어낸 문장이 한 줄 들어가면, 아무도 정한 적 없는 것이 프로젝트 전체의 전제가 된다.

앞선 1차 게이트가 필수 항목의 빈칸을 이미 질문으로 냈고, 그 답이 「사람이 답한 것」에 실려 있다.
그것과 씨앗 문서에 적힌 것, 둘 말고는 쓸 것이 없다.

## 1. 입력 게이트

- [ ] 씨앗 문서(작업 지시서 머리말이 있는 문서)가 주어졌다
- [ ] 「사람이 답한 것」에 목적·사용자·도메인·이번 범위가 있다
- [ ] 없는 항목이 있으면 — 쓰지 말고 `ask` 로 묻는다. 물을 것은 **한 번에 모아** 묻는다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| 사람의 답과 씨앗 문서에 없는 내용을 쓰지 않는다 | 무효 |
| **언어·프레임워크·계층·DB·식별자 전략을 적지 않는다** — 요구사항이 아니라 결정이다 | 무효 |
| 「이미 정해진 것」에는 사람이 확정했다고 말한 것만 적는다. 관행·업계 표준을 채우지 않는다 | 무효 |
| 답이 모호하면 그 자리를 채우지 말고 `ask` 로 되묻는다 | 무효 |
| 파일은 `doc/spec.md` 하나만 만든다 | 무효 |

> 언어·프레임워크를 여기 적으면 그건 *이미 내린 결정*이 되어 `bootstrap` 이 다시 묻지 않는다.
> **아키텍처 결정서는 이 문서의 입력이 아니라 다음 실행의 산출물이다.**

## 3. 작업 — `doc/spec.md`

맨 위 네 줄은 다음 실행의 작업 지시서다. 이 네 줄이 없으면 그 실행의 0차 게이트가 막는다.

````
---
kind: bootstrap
id: <씨앗 문서의 id 를 그대로>
title: <한 줄 요약>
target: <프로젝트 이름 — 씨앗 문서의 target 을 그대로>
---

# 프로젝트 개요
무엇을 만드는지 · 왜 만드는지 · 누가 쓰는지 (사람의 답 그대로)

# 주요 도메인
이름 나열

# 이번 범위에서 되어야 하는 것
- 동사로 한 줄씩
- 하지 않기로 한 것이 있으면 「이번에 하지 않는 것」으로 따로 적는다

# 이미 정해진 것
사람이 확정했다고 답한 제약만. 없으면 이 절을 통째로 뺀다
````

## 4. 자가검증 체크리스트

- [ ] 문서의 모든 문장이 사람의 답 또는 씨앗 문서로 되짚어지는가
- [ ] 언어·프레임워크·계층·DB 이야기가 한 줄도 없는가
- [ ] 머리말 네 줄이 있고 `kind: bootstrap` 인가
- [ ] 「이미 정해진 것」에 사람이 말한 적 없는 항목이 섞이지 않았는가
- [ ] 만든 파일이 `doc/spec.md` 하나뿐인가

## 5. 산출물 → 다음 단계 입력

- **산출물**: `doc/spec.md`
- **사람이 할 일**: 읽어 보고, 스펙 폴더로 옮긴다
- **다음 실행**: 그 경로를 `bootstrap` 작업의 스펙 문서로 넘긴다
