# [adopt 01] 구조 조사서

> **산출물**: 기존 코드베이스의 실제 구조와 규칙을 정리한 문서 (코드 아님)
> **다음**: [02] 선언

## 0. 사용법

레거시 프로젝트에 code-agent를 붙이는 첫 단계. **규칙을 새로 정하지 않는다.** 이미 굴러가는 코드에서 읽어낸다.

bootstrap과 결정적으로 다른 점: **참조할 코드가 이미 있다.** 그래서 결정 질문지가 필요 없고, 조사가 그 자리를 대신한다.

> `--reference` 로 **표준으로 삼을 도메인**을 지정해야 한다. "이 도메인처럼 만들겠다"는 사람의 선택이며,
> 그 도메인의 파일 목록이 이 단계의 유일한 근거다.

## 1. 입력 게이트

- [ ] `--reference` 로 표준 도메인이 지정됐다
- [ ] 기존 문서(있다면)가 `--spec` 또는 `--conventions` 로 주어졌다
- [ ] `domainBase`가 실제 소스 루트를 가리키게 수정됐다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| **코드에서 읽히는 것만 적는다.** 있어야 할 것 같은 규칙을 보태지 않는다 | 무효 |
| 문서와 코드가 다르면 **양쪽을 다 적고** 코드를 기준으로 삼는다 | 무효 |
| 일관되지 않은 지점(도메인마다 다른 방식)은 통일하지 말고 **그대로 보고**한다 | 무효 |
| 개선 제안을 하지 않는다 — 이 단계는 관찰이다 | 무효 |
| 근거를 파일 경로로 짚을 수 없는 항목은 적지 않는다 | 무효 |

## 3. 작업 — 조사 항목

| 항목 | 무엇을 적나 |
|---|---|
| 소스 루트·도메인 분류 | `domainBase`, `domainRoots` 후보와 실제 경로 |
| 계층 | 디렉토리 이름과 각 계층에 실제로 있는 클래스 종류 |
| 계층별 책임 | 트랜잭션 경계·예외 처리·조회 조합이 실제로 어디 있는지 |
| 파일 이름 규칙 | 계층별 접미사 패턴 |
| 식별자·soft delete·멀티테넌시 | 실제 필드명과 조건 |
| 테스트 | 위치·접미사·스타일(단위/통합)·무엇을 테스트하고 무엇을 안 하는지 |
| 빌드·테스트 명령 | 저장소의 실행 파일 |
| **불일치** | 도메인마다 방식이 갈리는 지점, 문서와 코드가 어긋나는 지점 |

## 4. 자가검증 체크리스트

- [ ] 모든 항목에 근거 파일 경로가 붙어 있는가
- [ ] 코드에 없는 규칙을 추가하지 않았는가
- [ ] 일관되지 않은 지점을 임의로 통일하지 않았는가
- [ ] 개선 제안을 섞지 않았는가
- [ ] 문서–코드 불일치를 양쪽 다 적었는가

## 5. 산출물 → 다음 단계 입력

- **산출물**: 구조 조사서
- **[02] 입력**: 조사 결과 전부 — 매니페스트와 컨벤션 문서가 여기서 나온다
