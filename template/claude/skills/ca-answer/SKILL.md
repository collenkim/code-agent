너는 **메인 에이전트**다. 모든 `/ca-*` 명령에서 사용자에게 물을 때 아래 절차를 사용한다. 서브에이전트는 질문 후보만 반환하고, 메인이 `AskUserQuestion`을 호출한다.
질문 목록을 마지막 메시지에 출력하고 답을 기다리는 방식으로 대신하지 않는다. 사용자에게 `/ca-answer`를 다시 입력하게 하지 않는다.

## 1. 질문 생성

1. 현재 명령의 자료·기존 답·프로젝트 문서부터 확인한다. 이미 답한 것은 다시 묻지 않는다. 기존 설정으로 정할 수 있는 기술 세부는 근거를 가정에 기록한다.
2. 사람이 정해야 하는 동작·권한·데이터·비용·호환성·범위와 아직 선택하지 않은 초기 구성을 질문으로 만든다. **질문 하나에 결정 하나**, 쉬운 말로 쓴다. 내부 JSON 키나 러너 판정 방법을 선택하게 하지 않는다.
3. 선택지마다 짧은 이름과 결과·차이를 설명하는 한 문장을 붙인다. 추천할 근거가 있으면 하나를 첫 번째에 놓고 이름에 `(추천)`을 붙이며 설명에 이유를 쓴다. 사용자 요청·기존 설정·회사 규칙이 우선이다. 폴더 이름(예: IdeaProjects)만으로 언어·업무 의도를 추측하지 않는다. 업무 결정은 추천을 보여 주더라도 실제 선택 전에는 확정하지 않는다.
4. 언어·프레임워크·아키텍처처럼 대안이 많은 질문에는 **서로 다른 실제 후보를 최소 5개** 준비한다. 기타·직접 입력·페이지 이동은 그 수에 넣지 않는다. 이진 범위 결정처럼 대안이 적은 질문에는 허구의 대안을 만들지 않는다. 질문 수를 5개로 늘리라는 뜻도 아니다.
5. 질문과 전체 후보·추천 이유를 **도구 호출 전에** 기록한다. 기존 Q 번호를 재사용하지 않고 이어 붙인다. `[Answer]:`는 빈칸으로 둔다.
   - 접수 중 또는 작업 중: `doc/work/<ID>/questions.md`. 접수 답은 `request.json`의 `clarifications`와 해당 요구·완료 조건·제약에도 반영한다.
   - 작업 ID 없는 문서 준비: `docs begin` 뒤 `doc/code-agent/setup-questions.md`. 답은 관련 POLICY 문서·설정에 반영하고 `(사용자 답)`을 표시한다.
   - 읽기 전용 명령 등 기록할 쓰기 권한이 없으면 파일을 임의로 만들지 않고 현재 대화의 도구 질문·응답을 사용한다. 이후 쓰기가 허용된 단계에서 필요한 결정을 옮긴다.

## 2. 선택 도구 호출

- `AskUserQuestion`을 **실제로 호출**한다. 보통 한 번에 1~3개, 최대 4개의 독립적인 질문만 넣는다. 앞선 선택에 따라 달라지는 질문은 답을 받은 다음 생성한다.
- 각 질문은 `question`, 12자 이하 `header`, `options`의 `label`·`description`, `multiSelect`로 구성한다. `multiSelect`는 기본 `false`, 서로 함께 선택할 수 있는 항목만 `true`다.
- 한 화면의 `options`는 **2~4개**다. 내장 Other/직접 입력으로 다른 답이나 경로·버전을 입력할 수 있다고 처음 한 번만 안내한다. 내장 입력과 중복되는 `X. 기타` 옵션을 넣지 않는다. 추천 표시나 기본 강조는 사용자 응답이 아니다.
- 경로·버전·회사 규칙처럼 자유 입력이 필요한 질문도 도구를 사용한다. 관측한 후보가 없으면 `직접 입력으로 지정` / `아직 정하지 않음`을 제시하고 내장 입력을 안내한다. `직접 입력으로 지정`만 선택하고 실제 값이 없으면 미응답이며 필요한 값을 같은 도구로 받는다. 경로를 지어내지 않는다.
- 선택지가 5개 이상이면 아래 절차를 사용한다. `options`에 5개 이상 넣지 않는다.

### 5개 이상 선택지

전체 후보의 이름과 한 줄 설명을 먼저 짧은 표로 보여 주고, 선택은 도구로 받는다. 추천을 첫 번째로 정렬하고 고유한 후보 이름은 페이지 사이에 바꾸지 않는다.

- 첫 화면: 후보 3개 + `다른 선택지`(설명에 남은 후보 이름).
- 중간 화면: `앞 선택지` + 다음 후보 2개 + `다른 선택지`.
- 마지막 화면: `앞 선택지` + 남은 후보 최대 3개. 따라서 모든 화면은 2~4개 옵션이고 어떤 후보든 선택할 수 있다.
- 5개 후보 예: 첫 화면 A·B·C·다른 선택지 → 마지막 화면 앞 선택지·D·E. 7개 후보 예: A·B·C·다른 선택지 → 앞 선택지·D·E·다른 선택지 → 앞 선택지·F·G.
- 페이지 이동은 답으로 저장하지 않는다. 후보를 고르면 그 결정은 끝내고 다른 페이지를 강제로 질문하지 않는다. 내장 직접 입력으로 다른 페이지의 후보를 명시해도 그 선택을 기록한다.
- 5개 이상을 복수 선택해야 하면 먼저 3개 이하의 의미 있는 그룹을 도구로 선택하게 하고, 선택한 각 그룹의 후보를 최대 4개씩 복수 선택으로 받는다. 이동·그룹 이름을 최종 선택으로 간주하지 않고, 실제 선택한 후보들을 합쳐 기록한다.

## 3. 답 기록과 진행

1. 도구 응답을 받은 즉시 해당 Q의 `[Answer]:` 뒤에 **선택한 label 또는 직접 입력 원문 그대로** 기록한다. 뜻을 풀어 쓸 때는 별도 `(해석: …)` 줄을 둔다. 선택지의 설명은 선택 당시 기록을 유지한다.
2. 빈 응답·취소·건너뛰기·보류·‘모르겠다’·페이지 이동은 답이 아니다. `[Answer]:`를 비워 두고, 상태 설명은 **표시자 앞**에 적는다. 업무 결정을 추천으로 자동 채우거나 같은 질문을 무한 반복하지 않는다. 필요한 답이 없으면 의존 작업을 멈추고 이유만 알린다.
3. 일반 답변을 문서 확정·요구사항 확정·계획 승인·반영 승인으로 취급하지 않는다. `confirm doc`·`confirm request`·`setup baseline`·`approve`·`deliver`의 사람 터미널 절차는 그대로 따른다. CLI의 TTY 입력이나 Claude 자체 권한 창을 에이전트가 대신 실행하지 않는다.
4. 다른 스킬에서 이 절차를 읽었다면 답을 호출한 스킬에 돌려주고 **그 자리에서 이어간다**. 여기서 `/ca-next`를 재귀 호출하지 않는다. 답으로 요구·범위·계획이 바뀌면 그 스킬의 재제출·재승인 절차를 따른다.
5. 사용자가 `/ca-answer`를 직접 호출했다면 `code-agent status`로 접수·작업 폴더 또는 문서 세션을 찾고 미응답 질문만 처리한다. 전부 답했으면 `/ca-next` 절차로 현재 상태부터 이어간다. 준비 질문은 `/ca-docs` 또는 `/ca-adopt`로 복귀한다.

## 도구를 쓸 수 없는 경우

`AskUserQuestion`이 없거나 실행이 거부되면 그 사실을 알리고 미응답을 유지한다. 대화형 Claude Code에서 이어가도록 안내한다. 텍스트 질문으로 조용히 대체하거나 응답을 만들어 진행하지 않는다. 사용자가 이미 직접 적어 준 명확한 답은 재질문 없이 기록한다.
