# authorization-api 보고의 계획·질문 대기 복구

보고된 네 결함과 상태 안내를 소스에서 보완한다. 대상 프로젝트의 실행·작업 원장은 이 변경으로 직접 수정하지 않는다.

질문 UI 관련 선행 변경(`8ab6cba`)의 중복 보고는 이 기록으로 통합한다. 당시 service-api의 YSIJ-255에서 독립 Claude 세션의 실제 답과 질문 원장이 어긋난 8건을 확인했다. Pre의 사전 입력 거부와 Post의 실제 응답 관찰을 분리하고, 작업 답 원장 대조·질문 묶음 보존·Codex 폼 오류 표시·선택 UI 없는 영속 발행 거부를 반영했다. 증거가 있는 대기는 폐기 상태로 닫혔고 새 요청은 실제 호스트 응답으로 적용됐다. 당시 집중 회귀는 42개 통과했으나 전체 회귀는 중단됐으며, 실제 UI 클릭은 시험하지 않았다. 선행 검증 근거는 아래 실행 근거의 `priorQuestionUi`에 보존한다. 개별 질문 번호와 재시작 경위의 반복 기록은 Git 이력에서 확인한다.

- 파일 작업: 계획의 생성·수정·삭제·이동과 이동 원본을 보존하고, 분석 후보 사전 검사·승인 화면·쓰기 경계·Task 완료·검증·반영 대상에서 같은 경로 집합을 사용한다. 승인된 구현의 삭제·이동 명령은 파일 덮어쓰기·디렉터리 삭제·링크 경유를 거부한다.
- 담당 되돌림: 완료 hook 요청에 지적·초안을 보존하고 재개 미관찰 상태를 CLI·master 상태에 노출한다. 종료를 확인한 메인이 회수한 배정은 전달 실패로 구분한다. 입력별 첫 복구만 총 배정에서 분리하고 반복 전달 실패는 막는다. 종료된 호스트 담당에게 후속 메시지가 도착한다고 가정하지 않는다.
- 지식 키: 백틱 안의 공백을 키의 일부로 보존해 정의·참조·문서 영향 표가 일치하게 한다.
- 질문 대기: 작업 ID가 있는 답 원장 대조와 ID가 없는 호스트 주 세션 원본 대조를 공통 판정으로 사용한다. 읽기 전용 조회는 실제 미응답과 정리 가능한 낡은 기록을 구분한다. 동기화는 증거가 있는 대기만 닫고 답·승인을 합성하지 않는다.
- 상태·버전: 문서 질문과 선택창 질문 수를 따로 보이며, 설치 완료와 프로젝트 적용 완료를 구분한다. 예약 당시 사유와 현재 차단 사유를 구분하고 구체적인 정리·적용 명령을 안내한다.
- 질문 표시 안내: 완료 hook과 README·사용 안내·흐름도에 남은 번호 입력 대체 문장을 선택 UI 연결 복구로 통일한다. 표시 실패만 복구 후 재표시하며 사용자 취소·보류와 이미 받은 답은 반복하지 않는다.

계획 파일 작업과 되돌림 상태가 영속 기록에 추가돼 상태 형식 세대를 13으로 올린다. 낮은 세대 릴리스로의 적용은 거부된다.

전달 실패 표지가 없는 과거 취소를 전달 실패로 추정하거나 기존 한도를 초기화하지 않는다. `next`는 답변 증거가 있는 낡은 기록이 있을 때만 동기화해 기존 문서 질문 게이트를 유지한다. 파일 실행은 현재 호스트·세션으로 쓰기 경계를 검사하며 Claude 단독과 Codex 단독 모드를 각각 시험한다.

템플릿 예산은 필요한 계약과 재개 분기만큼 늘린다. `ca-next`는 실제 미응답과 낡은 기록, 되돌림 전달 확인의 재개 분기를 위해 6700→7000자, `ca-plan/criteria`는 파일 작업 계약·사전 검사·실행 명령을 위해 3100→3400자, `ca-status`는 질문·버전 상태 구분을 위해 1900→2000자로 조정한다. 분석 기준은 상세 형식을 계획 기준으로 연결해 기존 예산을 유지한다.

검증 결과는 [실행 근거](evidence/2026-10-21-workflow-recovery.json)에 기록한다. 임시 Git 저장소의 승인·실제 삭제/이동·검증, 구조화된 호스트 원본의 일치·불일치, hook 되돌림과 초안 재사용을 재현한다. 실제 Claude/Codex UI의 클릭과 종료된 실제 담당에 대한 재전달은 이번 시험 범위가 아니며, 대상 프로젝트에 새 릴리스를 적용해야 변경이 사용된다.

최종 빌드를 통과했다. 전체 회귀 1,708개는 1,701개 통과·3개 실패·환경 조건에 따른 4개 생략으로 끝났다. 실패는 템플릿 줄 이동에 따른 인용 1건과 파일 작업 오류 문구의 옛 기대값 2건이었다. 인용과 기대값을 맞춘 뒤 재빌드하고 해당 3개와 질문 표시 안내 3개를 재검증해 6개 모두 통과했다. 미해결 실패는 없으며 서로 다른 실행의 시험 수는 합산하지 않는다. 전체 실행은 약 54분 걸렸다. 시험 중 실제 Git 호출에 콘솔 생성 억제 옵션만 더한 임시 preload를 사용했으며 실행 인자·출력·종료 코드·저장소 작업은 그대로다. 실행 로그와 preload는 재생성 가능한 `dist/` 산출물로 커밋하지 않는다.
