입력: 쓸 문서 종류와 경로, 문서 뼈대(`code-agent docs skeleton <종류>` 출력), 재료(분석 결과·explorer 결과·사용자 답), 범위(요구 항목).

- 뼈대의 제목을 그대로 쓴다 — 코드가 제목으로 필수 섹션을 찾는다. 안내 주석은 지워도 된다.
- 설명문은 사용자의 언어로 작성하고 제출 전에 문장 연결·언어 혼입·깨진 문자를 확인한다. 기술 식별자·경로·도구명과 보존할 인용 원문은 바꾸지 않는다. 다른 언어로 받은 분석 결과를 그대로 설명문에 붙이지 않는다.
- 받은 재료에 있는 것만 옮긴다. 빈칸은 `확인 필요` 로 남기고, 메인 에이전트가 질문으로 돌릴 수 있게 목록으로 돌려준다.
- 모든 서술에 출처(근거 `path:line` 또는 `사용자 답 Qn`)를 단다.
- **범위만** 쓴다. 이번 요구 항목이 닿는 것만 — 전체를 서술하지 않는다.
- 작업 폴더(또는 지정된 문서 경로) 밖에는 쓰지 않는다.

## 작업 문서

| 문서 | 필수 섹션 | 코드가 보는 것 |
|---|---|---|
| `02-analysis.md` ② | 기존 시스템 분석 · 영향 범위 · Risk | 세 섹션이 비지 않았고, **`영향 범위` 표 첫 열에 01 의 모든 R** 이 한 줄 이상 |
| `03-design.md` ③ | 구성 요소 · 처리 흐름 · API · 데이터 · 설계 결정 | 다섯 섹션이 채워졌거나 `해당 없음 — <근거>` |
| `04-functional.md` ④ | 기능 정의 · 업무 규칙 · 예외 · 수락 기준 | 네 섹션이 비지 않았고, AC id 중복 없음, **R 마다 AC 1개 이상** |

- `영향 범위` 는 표다: `R 번호 | 닿는 파일/모듈 | 부르는 곳 | 파급`. 영향이 없는 R 도 근거와 함께 `없음` 으로 **한 줄 넣는다** — 빠지면 전환이 막힌다.
- `03` 의 `API`·`데이터` 는 조건부다. 이번에 접점·데이터를 안 건드리면 `해당 없음 — <근거>` 라고 쓴다. **근거 없는 `해당 없음` 은 미충족이다.**
- `04` 의 수락 기준은 `AC-R<n>-<m>` 한 줄씩, "~하면 ~이다" 또는 Given/When/Then. **R 마다 최소 하나.** 오류 코드는 `03` 의 `API` 와 글자까지 같게.
  **지시서의 `## 완료 조건`(또는 수락 기준 절)에 문장이 있으면 그것을 그대로 옮기고 AC 번호만 붙인다** — 사람이 확정한 기준을 두고 새로 짓지 않는다. 그 절이 `원문에 없음` 이면 그때 짓는다.
- `04` 의 업무 규칙은 작업 안에서만 `BR-<n>` 이고, 근거(사용자 답 Qn · `path:line` · business-rules.md 의 키)가 없는 규칙은 지어낸 것이다.

## 공통 KNOWLEDGE — 인용하고, 쓰지 않는다

`doc/knowledge/` 의 데이터 사전 · API 목록 · 업무 규칙·용어집은 **읽기만 한다.**
작업 중에는 hook 이 작업 폴더 밖 쓰기를 막고, 갱신은 반영(deliver)에서 사람이 항목을 고른 뒤 코드가 한다.

인용 규칙 — `03`·`04` 는 그 항목의 **키와 그것에 기대는 사실 한 줄**을 옮겨 적고 **그 뒤에 이번 작업이 만드는 차이만** 쓴다.
옮겨 적은 한 줄이 승인의 근거가 된다. 전량을 베껴 오지 않는다.

```
- `ORDER_ITEM` — 주문 1건에 품목 N행, `order_id` 는 필수 (doc/knowledge/data-dictionary.md)
  차이: `cancel_reason` 컬럼을 더한다 (R2)
```

## 공통 POLICY 문서 (`/ca-docs`)

아키텍처·컨벤션·테스트 전략·품질·보안 기준을 쓸 때는 코드로 알 수 없는 것(이유·방향·정책·임계)을 `확인 필요` 로 남긴다.
**KNOWLEDGE 문서(데이터 사전·API 목록·업무 규칙·용어집)에는 `확인 필요` 를 쓰지 않는다** — 모르는 칸은 빈칸으로 둔다.
막지 않는 문서에 미결 표시를 남기면 영원히 지워지지 않는다.
