# 선택형 질의응답·문서 작성 방식·리뷰 기준 보완

> 이 문서는 해당 시점의 기록이다. 현재 변경과 검증 결과는 [문서·검증 이력](README.md)을 따른다.

2026-10-01. 질문을 채팅에 나열하던 절차를 모든 명령에서 선택 도구로 통일하고, 레거시 문서 작성 방식과 독립 리뷰 기준을 보완했다. 편집 중 영향도 스킬에 들어간 잘못된 외국어 문장은 한국어로 수정하고 문서 전체의 언어 혼입을 검사했다.

## 요청별 반영

| 요청 | 확인한 문제 | 반영한 동작 |
|---|---|---|
| 모든 명령에서 선택형 질문 | 공통 블록·개별 스킬·CLI 안내·Stop hook에 질문을 마지막 메시지에 나열하거나 `/ca-answer`를 다시 입력하라는 지시가 남아 있었음 | 18개 스킬이 `ca-answer` 공통 절차를 사용. 메인이 `AskUserQuestion`으로 답을 받고 호출한 명령으로 복귀 |
| 추천과 최소 5개 후보 | 초기 구성 안내가 Node·Python·직접 선택에 한정됨 | 실제 구성 후보 7개와 목적별 추천 근거. 대안이 많은 질문은 최소 5개, 이진 업무 결정은 불필요하게 늘리지 않음 |
| 도구 표시 제한 | Claude 도구는 질문당 2~4개 옵션, 호출당 최대 4개 질문 | 전체 후보를 먼저 보여 주고 앞·다른 선택지로 이동. 이동·취소·보류를 답으로 기록하지 않음 |
| 레거시 문서 작성 방식 | 세 작성 경로는 있었지만 처음에는 추천대로·직접 선택으로만 안내 | 소스·설정 기준 작성 / 사용자 선택·입력 / 기존 문서 연결을 한 번에 선택. 현행과 변경할 방향을 구분 |

| 전체 테스트·실패 케이스 | 기존 게이트는 명령 실패와 필수 TC의 실패·생략·미실행을 이미 차단. 부정 케이스의 의미와 회귀 확인 지시 보강 필요 | 전체 명령을 변경 테스트만으로 좁히지 않음. 예상 오류·거부·보존 조건을 단언하는 테스트 자체는 passed여야 함. 검증 공백은 열린 리뷰 지적으로 보고 |
| 문서 언어 | 편집 과정에서 영향도 스킬에 잘못된 외국어 문장이 한 차례 입력됨 | 해당 문장 수정. 전체 문서·템플릿·소스 안내 검사. 공통 블록과 writer에 설명문 언어·깨진 문자 확인 지시 추가 |

Node·Python은 기존 `docs setup` 자동 설정을 사용한다. TypeScript/Node, FastAPI, Java/Spring Boot, Kotlin/Spring Boot, Go는 `/ca-adopt`의 문서·설정 작성 경로로 연결한다. 7개 모두를 `docs setup`이 직접 생성한다고 설명하지 않는다.

## 승인과 범위

질문 선택은 요구·정책을 정하는 답변이다. 문서·요구사항 확정, 기준 커밋 준비, 계획 승인, 최종 반영의 TTY 절차를 대체하지 않는다. 빈 저장소는 요구 원문을 먼저 보관하고 문서·설정을 준비하며, 필수 문서와 요구사항 확정 전에는 분석을 시작하지 않는다.

기존 요구에 위배되거나 주변 기능을 깨뜨리는 변경, 필요한 검증 근거가 없는 변경은 리뷰 지적으로 남긴다. 수정 뒤에는 check·test·독립 리뷰를 다시 거친다. '부작용이 절대 없다'는 선언 대신 실제 영향 경로와 회귀 테스트를 근거로 판단한다.

생략 4개는 Windows 파일시스템에서 대소문자로만 구별되는 파일 두 개를 만들 수 없는 검사 2개, Unix `chmod` 권한 검사 2개다. 통과 수에 포함하지 않았다. 위 추가 검사 3개도 전체 548개 통과에 포함되므로 합산하지 않는다. 문서 언어 검사와 스킬 적용 범위는 [검사 자료](evidence/selection-language-audit-2026-10-01.json)에 남긴다.

검사 범위에는 README, 문서, 18개 스킬, 8개 에이전트, 공통 블록과 CLI 설명문을 포함한다. 별도로 기존 Downloads의 작업 흐름 HTML도 언어 혼입만 읽기 검사했다. HTML의 화면·내용을 이번 변경에 맞춰 다시 생성한 것은 아니다.

질문 화면 호출과 리뷰의 의미 판정은 Claude가 따르는 스킬 지시다. 자동 테스트는 설치·갱신된 지시, CLI 안내, 질문 기록과 승인 분리, 기존 실행·검증 게이트를 확인한다. 이번 회차에서 실제 Claude 화면의 선택 조작, 각 기술 구성의 신규 프로젝트 실행, 모델의 리뷰 탐지율을 실측한 것은 아니다.

## 적용 방법

소스 설치를 사용하는 경우 이 저장소에서 `npm run build` 후, 실제 개발 대상 프로젝트에서 `code-agent update`와 `code-agent doctor`를 실행한다. Claude Code를 다시 열어 새 스킬을 읽고 `/ca-next` 또는 필요한 명령으로 이어간다. 다른 프로젝트의 설치 사본은 이번에 임의로 덮어쓰지 않았다.

도구 제한은 [Claude 공식 문서](https://code.claude.com/docs/en/agent-sdk/user-input#question-format), AI-DLC의 선택 도구 사용과 5개 이상 후보 분할 방식은 [AWS 공식 절차](https://github.com/awslabs/aidlc-workflows/blob/main/docs/reference/04-stage-protocol.md)를 확인했다. code-agent는 별도 서버나 SDK UI를 추가하지 않고 Claude Code의 도구를 사용한다.
