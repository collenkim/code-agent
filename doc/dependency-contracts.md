# 외부 의존 계약 인계와 재인용

선행 프로젝트의 확인된 계약을 계획 담당에게 전달할 때 사용한다. 계약은 근거 자료이며 사람 답·요구 확정·계획 승인·master 위임 권한을 대신하지 않는다. 등록된 자료가 없으면 기존 입력 범위와 질문 절차를 따른다.

## 등록

진행 중인 작업의 계획 단계에서 실행 중 배정이 없을 때 `code-agent planning contracts <계약.json>`을 실행한다. 입력 JSON은 다음 형태다. 경로는 정확한 파일 하나이며 디렉터리·와일드카드·저장소 전체 탐색을 받지 않는다.

```json
{
  "version": 1,
  "contracts": [{
    "id": "discount",
    "repository": "C:/projects/price-core",
    "path": "docs/discount-contract.md",
    "commit": "40자리 소문자 Git 커밋 SHA",
    "sha256": "파일 바이트의 64자리 소문자 SHA256",
    "claims": [{
      "key": "discount.range",
      "text": "amount는 0 이상이고 percent는 0부터 100까지이며 범위 밖이면 RangeError"
    }]
  }]
}
```

- `repository`는 로컬 Git 저장소 루트의 절대 경로다. `path`는 그 안의 일반 파일이다. 경로 탈출·저장소 밖 심볼릭 링크·커밋의 심볼릭 링크를 거부한다.
- 지정 커밋의 blob, 현재 파일, `sha256`이 모두 같아야 한다. 네트워크 조회·checkout·원본 파일 변경은 하지 않는다. 줄바꿈도 해시에 포함되므로 인계 파일의 Git blob과 작업 트리 바이트를 맞춘다.
- `claims.text`는 원문의 한 줄과 앞뒤 공백을 제외하고 정확히 같아야 한다. 새 요약·추론을 인증하지 않는다. `key`는 저장소들을 통틀어 같은 사실을 가리키는 이름이다. 같은 키의 서로 다른 값과 중복 계약 ID를 거부한다.
- 계약은 최대 20개, 계약별 항목은 최대 40개다. 입력·원본 파일·저장된 묶음은 각각 131072바이트 이하 UTF8 텍스트다. 큰 소스 대신 작고 명확한 커밋된 계약 문서를 인계한다.

검증 후 `.code-agent/work/<ID>/dependency-contracts.json`에 원문 사본·출처를 원자 기록한다. 이 파일은 반영 대상이며 동의 스냅샷에도 포함된다. 모든 계획 담당의 `inputs`와 `externalContracts`에 연결한다. 담당은 이 사본만 읽으며 원본 저장소를 추가 탐색하지 않는다. 등록 명령은 기존 묶음을 전체 교체하고 실행 중 배정에서는 거부한다.

계획 입력 판정과 답 출처 판정은 원본·사본·커밋·해시를 다시 확인한다. 원본 변경·삭제·접근 실패·사본 변조는 미확인으로 처리하고 담당 결과와 계획 승인을 낡게 한다. 계약이 없는 기존 작업의 해시·답 출처는 그대로다.

## 질문에 기존 계약 재인용

`code-agent planning reuse-answer Q1 discount discount.range`는 답이 없는 단일 질문에 확인된 항목 원문을 기록한다. 이미 답했거나 보류한 질문은 덮어쓰지 않는다. 질문 본문·답·계약 묶음 해시를 `answers.jsonl`의 `contract` 행에 결속하고 `[Source]: 기존 계약 discount discount.range`로 표시한다.

출처 `contract`는 `conversation`·`observed`·`intake`·`delegated`·`relayed`와 별개다. 확인 화면에 **기존 계약 재인용 — 사람 응답 아님**으로 나타난다. Source 문자열만 적으면 미확인이다. 질문·답·근거·기록이 다르면 열린 질문으로 취급한다. Source를 대화로 바꾸어 검증 실패를 숨길 수 없다. 이후 실제로 관찰한 사람 답이나 권한 있는 master 답은 기존 경로로 처리한다.

코드는 같은 키의 값 충돌과 원문 동일성을 확인한다. 서로 다른 키나 자연어 요구 사이의 의미상 모순, 해당 계약이 질문에 충분한지는 담당·독립 검토가 확인한다. 자료가 없거나 모순이 있으면 재인용하지 않고 질문한다. 임의 답을 원문과 연결한 추론으로 인증하는 기능은 없다.

## master 연동 계약

master는 확인된 선행 산출물에서 모듈 경로·export·입력 범위·오류 조건을 담은 커밋된 계약 문서를 선정하고 위 JSON을 개발 호스트에게 전달한다. `claims.key`는 같은 의미에 같은 키를 사용한다. 개발 호스트는 작업을 시작한 뒤 첫 세부 배정 전에 등록한다. 원래 배정의 criteria를 대화 문자열로만 보내는 것은 계약 등록이 아니다.

`code-agent.master` v1의 submit·위임·사람 전달 형식은 그대로다. 상위 러너가 위 계약 JSON을 생성·전달하고 등록 명령을 연결하는 것은 master 쪽 구현 범위다. code-agent는 상위 저장소를 수정하거나 이전 실행의 증거를 재작성하지 않는다.
