# [bootstrap 01] 아키텍처 결정 — 묻고, 답을 받아, 결정서로 남긴다

> **산출물**: `doc/architecture-decisions.md` (코드 아님)
> **다음**: [02] 스캐폴딩 — 결정 3번(스캐폴딩 명령)이 그 입력이다

## 0. 사용법

이 단계는 **한 턴에 끝나지 않는다.** 두 국면으로 돈다.

```
① 묻는다   정해야 할 것을 ask 로 낸다 — 선택지와 트레이드오프를 질문 안에 담아서
      ↓     (사람이 답할 때까지 진행되지 않는다)
② 적는다   사람의 답을 doc/architecture-decisions.md 로 옮긴다
```

> **선택지를 제시하되 고르지 않는다.** 언어·프레임워크·계층 구조는 요구사항이 아니라 **결정**이다.
> 에이전트가 고르면 프로젝트 전체가 근거 없는 구조 위에 올라간다.

「사람이 답한 것」에 이미 답이 있는 항목은 **다시 묻지 않는다.** 아직 답이 없는 항목만 묻는다.
물을 것은 **한 번에 모아** 묻는다 — 한 항목씩 물으면 사람이 그만큼 여러 번 멈춘다.

## 1. 입력 게이트

- [ ] 프로젝트 개요(무엇을 만드는지, 누가 쓰는지, 주요 도메인)가 있다
- [ ] 이미 정해진 것이 있으면 스펙 문서로 주어졌다 — 그건 다시 묻지 않는다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| 정해지지 않은 항목을 임의로 채우지 않는다 | 무효 |
| 아직 답이 없는 항목은 `ask` 로 묻는다. **질문에 선택지와 트레이드오프를 함께 담는다** | 무효 |
| 결정서에 적는 값은 전부 「사람이 답한 것」이나 스펙 문서로 되짚어져야 한다 | 무효 |
| 스펙에서 이미 답이 읽히는 항목은 "이미 정해짐"으로 표시하고 근거 문장을 인용한다 | 무효 |
| 이 프로젝트에 해당 없는 항목은 목록에서 뺀다 (일반론 나열 금지) | 무효 |
| 답이 다 차기 전에는 결정서를 쓰지 않는다 — 절반짜리 결정서가 [02] 의 입력이 된다 | 무효 |

## 3. 다루는 항목 — 최소 아래 6가지

| # | 항목 | 예 |
|---|---|---|
| 1 | 언어 · 런타임 버전 | Java 17 / Node 22 / Python 3.12 |
| 2 | 프레임워크 · 주요 라이브러리 | Spring Boot 3.x + JPA + Thymeleaf |
| 3 | 빌드 도구와 **스캐폴딩 명령** | gradle · `spring init --dependencies=web,data-jpa` |
| 4 | 패키지/모듈 루트와 도메인 분류 | `com.acme.newsales` · `application` / `admin` |
| 5 | **아키텍처 계층** — 이름, 책임, 의존 방향, 트랜잭션 경계 | Controller → Facade → Handler(트랜잭션) → Service → Repository |
| 6 | **공통 규약** — 식별자 전략, soft delete, 멀티테넌시, 감사 필드, 예외 체계 | id 단일키 · `deletedDt` · `workspaceId` · `BaseEntity` · `AppException`+`ErrorCode` |

프로젝트 성격상 더 필요한 것(인증 방식, 배포 형태, DB 종류 등)이 있으면 추가한다.

### ① 묻는 국면 — 질문 하나의 모양

```
### ask
[2] 프레임워크를 무엇으로 합니까?
  A) Spring Boot 3.x + JPA — 사내 사례가 많아 참고할 코드가 있다. 초기 기동이 무겁다
  B) Spring Boot 3.x + MyBatis — SQL 을 직접 쥔다. 매핑 코드가 늘어난다
  트레이드오프: A 는 스키마 변경이 코드에 먼저 드러나고, B 는 쿼리 튜닝이 쉽다
```

### ② 적는 국면 — `doc/architecture-decisions.md`

항목마다 **결정 · 근거 · 대안** 세 줄을 남긴다. 근거는 사람의 답이나 스펙 문장을 가리켜야 한다.

```
## 2. 프레임워크
- 결정: Spring Boot 3.x + JPA
- 근거: 사람이 답함 — "사내 표준이 Spring 이라 A 로 간다"
- 대안: MyBatis (SQL 을 직접 쥐지만 매핑 코드가 늘어남)
```

## 4. 자가검증 체크리스트

- [ ] 6개 항목이 모두 다뤄졌는가 (해당 없으면 그 이유가 적혔는가)
- [ ] 묻는 국면에서, 각 질문에 선택지가 2개 이상 있고 트레이드오프가 적혔는가
- [ ] **어느 것도 대신 고르지 않았는가**
- [ ] 결정서의 모든 값이 사람의 답 또는 스펙 문장으로 되짚어지는가
- [ ] 이미 정해진 항목은 스펙 문서의 근거 문장을 인용했는가
- [ ] 코드나 설정 파일을 만들지 않았는가 — 이 단계의 산출물은 문서 한 장뿐이다

## 5. 산출물 → 다음 단계 입력

- **산출물**: `doc/architecture-decisions.md`
- **[02] 입력**: 결정 3번(스캐폴딩 명령). 앞 단계 산출물로 자동으로 실린다 — 사람이 옮겨 적지 않는다
