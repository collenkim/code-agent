# [bootstrap 02] 스캐폴딩 명령

> **선행**: [01] 결정 확정 · **다음**: [03] 공통 모듈
> **산출물**: 실행할 스캐폴딩 명령 (코드 아님)

## 0. 사용법

빌드 파일·엔트리포인트·디렉토리 레이아웃은 **생성하지 않는다.** 생태계의 공식 스캐폴더가 만들게 한다.

> **왜 직접 쓰지 않는가.** 빌드 파일을 기억으로 쓰면 플러그인 버전과 의존성 좌표를 환각한다.
> 참조할 코드가 없는 이 시점에 가장 먼저 터지는 곳이 여기다.
> 스캐폴더 출력이 **이후 단계의 참조 표준**이 된다 — 빈 상태에서 시작하지 않기 위한 장치다.

## 1. 입력 게이트

- [ ] 결정 1·2·3(언어·프레임워크·빌드 도구와 스캐폴딩 명령)이 확정돼 있다
- [ ] 결정 4(패키지 루트)가 확정돼 있다

## 2. 규칙 게이트

| 규칙 | 위반 시 |
|---|---|
| 결정 문서에 적힌 명령을 그대로 쓴다. **인자를 지어내지 않는다** | 무효 |
| 결정에 없는 의존성을 추가하지 않는다 | 무효 |
| 명령은 `out/` 에서 실행한다 (대상 저장소를 건드리지 않는다) | 무효 |
| 해당 스택에 공식 스캐폴더가 없으면 **그 사실을 명시**한다 — 골격을 모델이 쓰게 되고 빌드 통과가 유일한 신호가 된다 | 무효 |

## 3. 작업 — 산출 형식

실행할 명령과 그 근거, 그리고 명령이 만들어 낼 것으로 예상되는 파일 목록을 적는다.

```
실행 명령: <결정 3번 그대로>
작업 디렉토리: out/
근거: architecture-decisions.md 의 어느 항목인지

생성 예상: build 파일 · 엔트리포인트 · 디렉토리 레이아웃 · 의존성 좌표
```

**사람이 이 명령을 실행한 뒤** [03]으로 넘어간다. 실행 결과가 [03]의 참조 표준이 된다.

## 4. 자가검증 체크리스트

- [ ] 명령이 결정 문서의 것과 **한 글자도 다르지 않은가**
- [ ] 결정에 없는 의존성·플래그를 넣지 않았는가
- [ ] 스캐폴더가 없는 경우 그 사실과 영향을 적었는가
- [ ] 빌드 파일 내용을 직접 쓰지 않았는가

## 5. 산출물 → 다음 단계 입력

- **산출물**: 스캐폴딩 명령
- **사람이 할 일**: `out/` 에서 명령 실행
- **[03] 입력**: 스캐폴더가 만든 실제 파일들 — 이제부터 이것이 참조 표준이다
