**질문·동의** — 사람에게 묻거나 승인·확정·반영을 받기 직전에 `.claude/skills/ca-answer/SKILL.md`를 읽고 그 절차(`AskUserQuestion`·같은 세션 동의)를 따른다. 일반 답변은 승인이 아니며, 적용 뒤에는 이 흐름을 자동으로 이어간다.

`.claude/skills/ca-feature/SKILL.md` 의 절차를 그대로 따른다 — 접수는 **종류 `refactor`** 로 하고, 같은 단계 스킬을 같은 순서로 돈다.
접수에서 `target` 은 바꿀 코드가 있는 **저장소 경로**, `scope` 와 `preserve` 는 필수다 — 원문으로 정할 수 없으면 묻는다.
다른 점은 아래 셋이고, **전부 코드가 막는다** (지시가 아니다).

- **영향도 (`/ca-impact`)**: `02-analysis.md` 의 `기존 시스템 분석` 에 **지금 동작**을, `영향 범위` 에 바꿀 코드와 그것을 부르는 곳을 빠짐없이 적는다.
  `기존 시스템 분석` 은 `해당 없음` 으로 비울 수 없고 근거 `path:line` 이 최소 하나 있어야 `code-agent next` 가 넘어간다.
- **계획 (`/ca-plan`)**: 지시서의 preserve 문장을 **하나도 빠짐없이 그대로** 옮기고, 각각 어떻게 지켜지는지 적는다 (빠지면 제출이 거부된다).
  새 파일을 발명하지 않는다. 동작이 바뀌는 변경은 리팩토링이 아니다 — 필요해 보이면 질문으로.
- **기존 테스트는 손대지 않는다**: 기준 커밋에 이미 있던 `kind: "test"` 단계의 파일은 고치지도 지우지도 못한다 —
  계획에 넣으면 `plan submit` 이, 쓰려 하면 hook 이, 바뀐 채로 검증하면 `code-agent check` 가 거부한다.
  **동작이 보존되는지 보는 것이 그 테스트**라서다. 고쳐야 할 이유가 보이면 고치지 말고 `questions.md` 로 묻는다.
  어디까지가 "기존 테스트" 인지는 매니페스트의 `kind: "test"` 단계가 밝힌 자리(`scope: "project"` 의 `outputDirs` 또는 `base`)로 정해지고,
  계획 스테이지의 `code-agent context` 가 그 자리를 찍어 준다. 자리를 밝히지 않은 단계가 있으면 거기는 **지켜지지 않는다** —
  `code-agent manifest check` 의 경고를 사람에게 그대로 전한다.

`test` · `integrate` 에서 **기존 테스트 스위트 전체가 그대로 통과**해야 한다.
`code-agent.json` 에 `test` 명령이 없으면 `not-run` 으로 막힌다 — 아무것도 돌리지 않은 결과는 보존의 증거가 아니다.
