# 문서·hook 차단 후 선택과 재개

사용자가 공통 문서 누락이나 다른 hook 차단에서도 다음 행동을 선택해 계속할 수 있도록 요청했다.

메인 단계 템플릿의 일괄 중지 지침을 차단 복구 선택으로 연결했다. Claude·Codex 설치 블록 모두 공통 참조 문서의 복구 절차를 가리킨다. 담당 에이전트의 중지·보고, 기존 거부 판정과 검증·승인 게이트는 유지한다. 사람이 취소·보류한 경우에는 복구 질문으로 재촉하지 않는다.

문서 준비·필수 문서 거부 출력에도 실제 가능한 선택을 표시한다. 공통 문서 누락은 작성·기존 문서 연결·보류, 미확정은 확정 동의·보류로 나눈다. 작업 중 문서 보완은 작업 정보를 보존하고 기존 abort 동의 후 준비하는 절차이며, 같은 지시서로 시작해 필요한 계획·승인을 다시 검증한다. 중단 없이 문서 쓰기를 허용하거나 기존 단계로 강제 복귀하는 기능은 추가하지 않았다.

외부 권한·hook은 읽기 전용 진단이나 사용자 설정 확인으로 연결한다. 모델이 기존 권한 경계를 해제할 수 있다고 안내하지 않는다. 선택 도구를 실제 사용하는 것은 호스트의 메인 에이전트이며 CLI는 선택 안내를 출력한다.

복구 표는 차단 시에만 읽는 ca-answer/reference.md에 두었다. 파일 예산 5,300→7,100자, Codex 설치 블록은 참조 안내를 위해 1,500→1,600자로 조정했다. 공통 흐름 합계 예산은 유지한다.

검증 결과:

- 전체 `npm.cmd test`: 1,376개 중 1,371개 통과, 생략 4, 실패 1(231.5초). 유일한 실패는 Claude 공통 흐름의 템플릿 길이 한도 초과였다. 빌드·문서 차단 안내·기존 개발 게이트를 포함한 나머지는 통과했다.
- 실패한 합계 예산은 늘리지 않고 반복 지침과 강조 표기를 줄였다. 이후 템플릿 예산·양쪽 호스트 변환·문서 동기화·최종 회귀 37개를 실행해 모두 통과했다(25.9초).
- README·사용 가이드·설계·Codex 안내·흐름도를 최종 상태로 정리한 뒤 전체 `npm.cmd test`를 다시 실행했다. **1,376개 중 1,372개 통과, 실패 0, 플랫폼 조건 생략 4, 251.4초**. 빌드와 템플릿 예산을 포함해 통과했으며 최종 증거 요약은 [evidence](evidence/2026-10-12-blocked-recovery.json)에 있다.
- 두 호스트의 설치 자산에서 ca-answer/reference.md의 복구 절차가 제공되는 것을 확인했다. `git diff --check` 통과.
- 실제 Claude·Codex 대화에서 선택 도구 표시와 사용자 응답 후 복귀까지의 실행은 미검증이다. CLI 출력과 설치 템플릿·기존 게이트의 로컬 검증이며 외부 hook의 권한 해제를 보장하지 않는다.

정리 범위는 이 소스 저장소의 코드·설치 템플릿·현행 문서·검증 이력이다. 대상 cloud 프로젝트에 템플릿을 설치하거나 외부 Sentry·Jira·Notion을 변경하지 않았다. 앞선 오류 사전 판별·중복 처리·용어 정리 커밋은 `a4b6df8`이며, 이번 변경은 그 위의 공통 준비·차단 복구 안내다.
