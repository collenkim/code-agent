# 선택 화면에 다 들어가는 질문

동의 질문에 요약 전문을 그대로 실어 확인할 내용과 질문 줄을 한 화면에서 볼 수 없었다. Codex만의 문제가 아니라 두 호스트에서 모두 재현됐다. 질문에는 화면에 들어가는 앞부분과 전문 파일 경로만 싣고, 전문은 CLI가 파일로 남긴다.

## 원인

- 동의 질문(`consent.ts` `questions`)이 요약 전문에 "이 내용으로 진행할까요?"를 붙인 문자열이었다. 시험 저장소에서도 setup 62줄, request 56줄, plan 47줄, deliver 107줄이었다. 실제 프로젝트의 계획·커밋 목록은 더 길다.
- Codex 폼은 `message`(요약)와 필드 제목(같은 요약 + 질문)을 이어 붙여 같은 요약을 두 번 그렸다. codex-cli 0.162.1 소스(`codex-rs/tui/src/bottom_pane/mcp_server_elicitation.rs`)에서는 `current_prompt_text`가 둘을 합치고, `render`가 `prompt_height = min(줄 수, 남은 높이)`로 스크롤 없이 자른다. 선택지 `description`은 표시하지 않는다.
- Claude Code 2.1.296의 질문 창도 화면 높이를 넘는 질문을 자른다. 108줄 질문은 49~76번째 줄만 보였고, 마지막 줄은 `…`로 끝났다.
- 모델이 쓰는 업무 질문은 길이 제한이 없었다. Codex `ask`의 `title`도 8000자까지 받았다.

## 변경

- `screenText.ts`: 화면 폭(76칸, 한글·전각 두 칸)으로 줄 수를 센다. 질문 본문 상한 `QUESTION_ROWS`는 10줄이며, 80×24 터미널에서 선택지 3개와 함께 들어가는 크기다. 앞부분 발췌(빈 줄·표 구분선 제외, 넘치는 줄은 `…`)와 질문 크기 검사를 함께 둔다.
- 동의 준비가 요약과 문서 변경 후보 전부를 `.code-agent/consents/confirm-<내용 해시 12자>.md`에 쓰고 기록에 `fullText`를 남긴다. 질문은 다음으로 구성한다.
  - 앞부분: 최종 확인은 제목 포함 6줄. 문서 변경 선택이 붙으면 앞부분 3줄과 선택 2개·`… 외 N개`. 후보 질문은 4줄.
  - `… 이하 N줄 생략`, `전문: <경로>`, 질문 줄.

  `fullText`가 없는 이전 기록은 전문을 그대로 싣는다. 이미 낸 Claude `toolInput`과 deep-equal이 유지된다.
- Codex `confirm` 폼의 `message`는 조작 안내 한 줄이다. 업무 질문은 본문 10줄 또는 선택지 3줄(Claude는 이름+설명)을 넘으면 표시 전에 돌려보낸다. Claude는 PreToolUse `consent-event`가 exit 2로, Codex는 `ask`가 폼을 열지 않고 오류로 돌려보낸다. 응답 관찰(PostToolUse)은 크기로 막지 않는다.
- 템플릿: Claude `ca-answer` 2절에 질문 10줄 이내 규칙을, 동의 2항에 선택 화면 표시 범위를 추가했다. Codex `ca-answer` 2항은 폼 표시 내용을 실제에 맞게 고쳤다. Codex 업무 질문의 줄 수 규칙은 `ask` 도구 설명과 거절 문구에 있다. 이렇게 해서 템플릿 예산을 넘지 않았다(Claude `ca-answer` 8,699/8,700, Codex 흐름 합계 53,396/53,400).

## 실제 호스트 검증

`@lydell/node-pty` 1.1.0(ConPTY)으로 실제 대화형 호스트를 띄우고 `@xterm/headless` 5.5.0으로 화면 버퍼를 캡처했다. 신뢰 창·MCP 실행 허용·Esc 키 입력은 하네스가 보냈으며 사람의 동의 응답이 아니다. Codex 동의는 임시 저장소의 setup 동의이고 모두 Esc(보류)로 끝냈다. 화면 원문은 [증거](evidence/2026-10-13-choice-screen-size.json)에 있다.

| 호스트·크기 | 수정 전 | 수정 후 |
|---|---|---|
| Claude 2.1.296 · 120×40 | 108줄 질문의 49~76번째 줄만 표시. 제목·커밋 대상·질문 줄 없음 | 질문 9줄과 선택지 3개 모두 표시 |
| Claude 2.1.296 · 80×24 | — | 질문 9줄과 선택지 3개가 24줄 안에 모두 표시 |
| Codex 0.162.1 · 80×24 | 요약 앞 18줄만 표시. 질문 줄 없음. 선택지 1줄(`option 1/3`) | 안내 2줄·질문 9줄·선택지 3개 모두 표시. Esc → `deferred`(`response-defer`) |

Claude 80×24의 첫 시도는 이미 신뢰한 폴더에서 실행돼, 신뢰 창 대신 동의가 아닌 합성 질문에 하네스가 "수정 요청"을 입력했다. 새 폴더로 다시 캡처했다. Codex의 프로젝트 hook 신뢰는 각 임시 저장소 경로에 대해 기록됐다.

## 자동 검증

- 새 `screenText.test.ts`에서 다음을 검사한다.
  - 폭·줄 수·발췌·크기 검사.
  - setup·deliver 동의 질문이 10줄 안에 들고, 전문 파일이 요약을 그대로 싣고, 이름이 내용 해시인지.
  - 합성 문서 변경 후보 5개의 후보 질문·최종 선택 목록.
  - 이전 기록의 전문 질문.
  - Claude hook의 업무 질문 거절과 응답 관찰 통과.
- `choiceServer.test.ts`에서 다음을 검사한다.
  - 폼 `message`에 요약이 없고, 필드 제목이 전문 경로·질문 줄로 끝나는지.
  - 넘치는 `ask` 질문·선택지가 폼을 열지 않는지.
- 기존 시험 4개가 확인 화면 내용을 질문 문자열에서 찾던 것을 전문 파일에서 찾도록 옮겼다. 동의 결속·관찰 규칙은 바꾸지 않았다.
- 관련 시험 8개 파일: 138개 통과, 실패 0.
- 최종 `npm test`: 1,410개 중 1,406개 통과, 플랫폼 조건으로 4개 생략, 실패 없음(205.3초). 템플릿 예산·문서 대조·hook 로드 그래프 검사를 포함한다.
