# 브랜치별 작업 복귀와 설정 준비

기준 커밋은 `8085647`, 구현 커밋은 `99da682`다. `simmons`의 현재 브랜치는 `feature/UZRF-394`이고 `code-agent.json`은 없었지만, 로컬 `active.json`은 `fix/UZRF-392`의 implement·test·T2를 가리켰다. 저장소 단위로 커서를 읽는 경로가 다른 브랜치의 설정을 요구해 Codex 도구 호출을 차단했다.

## 최종 동작

- CLI·hook은 현재 브랜치와 일치하는 작업만 읽는다. 다른 브랜치의 커서는 유지하며 해당 브랜치의 도입·접수는 허용한다. `init`은 설치만 하고 설정 파일을 만들거나 작업을 종료하지 않는다.
- 다른 브랜치에서 새 커서를 저장할 때 기존 커서·임대를 `branches/`에 보관한다. 원래 브랜치로 복귀하면 Task·단계·임대를 다시 읽는다. 조회 자체는 상태를 바꾸지 않는다. 종료는 현재 브랜치의 커서만 삭제한다.
- 보관 커서도 동의 스냅샷과 버전·모델 변경 제한에 포함한다. 임대 갱신·잠금만 스냅샷에서 제외한다. 기존 승인·검증 게이트는 유지하고, `start`가 보관한 작업을 처음 단계로 덮어쓰지 못하게 한다.
- 같은 브랜치의 설정 누락·손상과 판별할 수 없는 커서는 계속 차단한다. 브랜치 없는 기존 기록은 저장소 단위로 유지한다. 상태 형식 세대는 5다.

## 검증

`branchCursor.test.ts`와 `branchResume.test.ts`의 추가 사례 14개에서 실제 임시 Git 저장소·worktree로 브랜치 전환, 설정 준비, 접수, 복귀, 종료, 임대 보존, 승인 유지, 검증 없는 전이 거부, 동의 대상 변경, 손상 거부와 Git 제외를 확인했다. 기존 테스트를 삭제하거나 게이트를 완화하지 않았다. 문서 줄 인용 검사의 위치만 실제 줄에 맞췄다.

Node 24.19.0·Windows에서 최종 `npm.cmd test`(빌드 포함)는 1609개 중 1605개 통과, 실패 0개, 플랫폼 조건 생략 4개다. 프로세스 종료·생존 검사를 위해 샌드박스 밖에서 실행했다. [최종 검증 자료](evidence/2026-10-19-branch-resume.json)에 결과를 남기고 중간 실행 로그는 제거했다.

실제 `simmons`는 읽기 전용으로 확인했다. 현재 작업은 없음, 보관 작업은 `UZRF-392`, `git status --short`의 hook 판정은 허용이며 원래 `active.json`의 내용은 바뀌지 않았다. `code-agent.cmd`의 npm junction은 이 저장소를 가리킨다. 대상의 브랜치·설정·작업 기록은 수정하지 않았고 실제 Codex 대화형 재실행은 수행하지 않았다.

## 범위

접수·문서 준비 세션은 checkout 단위다. 그 세션을 끝낸 뒤 브랜치를 바꾸며, 실행 중인 에이전트·검증과 동시에 브랜치를 전환하지 않는다. 병렬 개발은 별도 worktree에서 수행한다. 브랜치 이름 변경은 자동 추적하지 않는다. 브랜치별 선택은 작업 설정·승인·검증을 복제하거나 새 승인을 만드는 동작이 아니다.
