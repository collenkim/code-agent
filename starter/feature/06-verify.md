# [feature 06] 빌드·테스트 통과시키기

> **선행**: [01]~[05] 전부 · **다음**: 없음 — 사람이 `out/` 을 확인하고 저장소에 옮긴다
> **근거**: 실행 결과. 이 단계는 `kind: verify` · `expect: pass` 다

## 0. 사용법

`### run build` 와 `### run test` 를 돌려 결과를 본다. 실패하면 **본문 소스만** 고쳐 다시 돌린다.
`expect: pass` 이므로 통과를 확인하지 않고는 이 단계가 끝나지 않는다 — `### done` 만으로는 안 된다.

**do-not-touch**: 테스트 디렉토리는 이 단계의 `outputDirs` 에 없다. **실패한 테스트를 고치거나 지우는 길은 구조적으로 막혀 있다.**
테스트가 잘못됐다고 판단되면 고치지 말고 `note` 로 남기고 멈춘다 — 그 판단은 사람의 것이다.

## 1. 입력 게이트

- [ ] [01]~[05] 산출물이 전부 `out/` 에 있다
- [ ] `code-agent.json` 에 `build`·`test` 명령이 선언돼 있다 — 없으면 이 단계는 돌 수 없다

## 2. 규칙 게이트

| 규칙 | 근거 | 위반 시 |
|---|---|---|
| 먼저 돌린다. 결과를 보기 전에는 아무것도 고치지 않는다 | — | 무효 |
| 고치는 것은 **컴파일·실행 오류의 원인**만이다. 그 김에 구조를 바꾸지 않는다 | 경계 | 무효 |
| 테스트 파일을 고치지 않는다 (경계가 막지만, 시도 자체가 위반이다) | 경계 | 무효 |
| 파일을 고쳤으면 **다시 돌린다**. 앞서 본 결과는 바뀌기 전 파일들에 대한 것이다 | — | 무효 |
| 같은 실패가 두 번 반복되면 더 고치지 말고 `note` 로 남기고 멈춘다 | — | 무효 |

## 3. 작업

1. `### run build` — 컴파일 오류가 있으면 원인 파일만 `edit` 으로 고치고 다시 돌린다
2. `### run test` — 실패한 테스트의 **본문 쪽 원인**을 찾아 `edit` 으로 고치고 다시 돌린다
3. 통과하면 `### done`. 통과를 확인한 뒤 파일을 또 바꿨다면 다시 돌려야 한다
4. 통과시킬 수 없다고 판단되면 원인을 `note` 에 적고 `### done` 없이 멈춘다 — 사람에게 넘기는 것이 맞다

## 4. 자가검증 체크리스트

- [ ] 마지막 `run` 이 마지막 `edit` **뒤**인가
- [ ] 고친 파일이 전부 본문 소스인가
- [ ] 고친 것이 전부 오류 메시지 하나로 되짚어지는가 — 되짚어지지 않는 변경은 없는가
- [ ] 통과했다면 `expect: pass` 가 실제 결과로 확인됐는가

## 5. 산출물 → 사람

- **산출물**: 통과한 상태의 `out/`
- **사람이 할 일**: 4차 확정 뒤 `out/` 을 저장소에 복사한다. 브랜치·커밋·PR 은 사람의 일이다
