# YSIJ-255 질문 UI와 응답 대기 결함

## 확인된 결함

service-api의 YSIJ-255에서 `blocker-interactions.md`·`questions.md`·`restart-notes.md`, 질문·업무 답 원장과 Claude 질문 호출·결과를 대조했다. 독립 Claude 세션의 Q14~Q17은 실제 응답이 있었으나 질문 원장에는 대기로 남았다. 재시작으로 HEAD가 바뀌면서 기존 요청의 소비도 차단됐다. 접수 질문을 포함한 같은 유형의 낡은 대기는 8건이었다.

## 원인과 반영

1. `observeNativeQuestion`이 Pre/Post를 구분하지 않고 `tool_input.answers`가 있으면 반환했다. Post 입력에 호스트가 채운 답이 들어오는 형태를 회귀에 더했고, 사전 입력 거부는 Pre에만 적용한다. 실제 응답은 기존 Pre와 세션·호출·질문을 대조한 tool_response에서만 읽는다.
2. native 원장 누락이 생겨도 업무 답 원장은 따로 정상 기록됐지만 대기 정리는 문서 연결 요청만 다뤘다. 동일 프로젝트·작업·세션·도구 호출·질문 해시·선택지의 사전 입력 없는 ask/answer 근거가 있는 native 대기만 superseded로 닫는다. HEAD가 바뀐 과거 질문에도 적용하지만 새 답·승인·문서 반영은 만들지 않는다. 이미 받은 대시보드 답은 보존한다.
3. 대시보드가 없는 구조화된 질문도 저장하고 UI를 생략했다. 영속 발행은 유효한 사람 채널을 확인하며, 연결이 없으면 대기를 만들기 전에 호스트 UI·연결 복구를 안내한다. 비대화형이라는 이유만으로 대시보드가 있다고 가정하지 않는다.
4. Codex 폼 오류가 미응답과 구분되지 않았다. 표시·응답 실패를 presentation에 남기고 같은 질문을 재표시하면 지운다. 질문 필요성은 유지하며 취소·보류를 자동 재시도하지 않는다. 상태 형식 세대는 12다.
5. 문서 질문을 최대 16개씩 같은 키로 발행해 17개 이상이면 반복 조회가 앞 묶음을 폐기했다. 모든 묶음을 서로 다른 안정된 키로 발행한다. 일부 답이 채워져 묶음이 바뀌어도 남은 질문을 최신 요청으로 이어 주고, 답이나 대체 요청이 없는 질문은 폐기하지 않는다.
6. Claude·Codex 진입과 단계별 선택 지침에서 번호 입력 대체 문장을 제거했다. 새로운 결정은 호스트 선택 UI 또는 연결된 대시보드 UI로 받으며 질문 저장·도구 접수만으로 표시 완료를 보고하지 않는다. 사용자가 이미 명확하게 준 답을 다시 묻지는 않는다.

설치·단독 실행은 [설치 안내](../install.md), master의 질문 표시·응답 경로는 [대시보드 계약](../dashboard-interactions.md)을 따른다. 채널 등록만으로 브라우저의 실제 표시 완료를 확인할 수는 없다.

## 검증

최종 집중 회귀 42개가 모두 통과했다. 호스트 응답 결속·낡은 대기 정리·단독 Codex 폼 복구·대시보드 응답 보존·질문 묶음·문서와 템플릿 동기화를 검사했다. 명령과 결과는 [검증 근거](evidence/2026-10-21-question-ui.json)에 기록한다. 사전 답 입력 거부와 Windows 프로세스 종료 검사의 실패는 수정·환경 재검증 후 통과했다. 전체 회귀는 장시간 실행으로 중단했으며 통과로 간주하지 않는다. UI 콜백·hook·임시 Git 저장소를 사용했고, 직접 사용자 선택창을 클릭하는 시험은 수행하지 않았다.

## 프로젝트 복구와 적용 범위

`code-agent interaction list`의 동기화와 원래 세션의 재발행으로 낡은 8건이 superseded로 정리됐다. 새 Q14~Q17은 실제 `claude-question` 응답으로 applied가 됐으며, 복구 확인 시점의 pending·responded·deferred는 0건이다. 응답·승인을 합성하지 않았다.

소스에 연결된 전역 진입점의 새 hook 호출에는 빌드가 적용됐다. 기존 프로젝트 스킬 사본은 진행 중 작업의 갱신 제한을 따랐으며 작업 종료 후 공식 템플릿 갱신이 필요하다.
